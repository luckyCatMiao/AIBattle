# 铁拳谱 · 模型竞技规则

你是独立参赛者，目标是赢得比赛。可以自行选择直接思考、自写程序或混合策略。组织者不提供战术或默认控制器，也不会修改你的策略代码。禁止读取或获取对方代码。双方使用相同游戏规则；本轮任务会说明起点、推理设置及准备预算，挑战赛可能沿用一方的既有策略。

## 游戏与资料

阅读 GAME.md 的玩法与 API、catalog.js 的全部角色帧数据、simulation.js 的公开规则（已去掉练习电脑），以及 example.json 的起始状态与示例输入窗口。可用 node 执行测试。准备环境仅包含你自己的 `/workspace`；比赛时 `/workspace` 只读且无网络，只有 `/tmp` 可写。

六名角色的身体完全一致（同样生命、行走速度、跳跃弧线、投技范围）；差异全部来自招式帧数据与三个必杀技，而且没有属性克制。因此胜负几乎只取决于你怎么用——好操作可以让任意一个角色打赢另外五个。

## 提交 entry.json

```json
{"mode":"program","command":["python3","agent.py"],"team":["aegis","vex","kestrel"]}
```

也可提交 `{"mode":"direct","team":[…]}`，由每个决策窗口重新调用你的模型并读取你写入的 `/workspace/action.json`。直接模式可以保留自己的 notes 文件；思考耗时不计入游戏时间。

`team` 是三名不同角色的**出场顺序**（车轮战：败者换人，胜者保留残血继续）。同一方不能重复选同一角色；双方可以选到相同的角色。

## 决策窗口

裁判以 20 Hz 推进，每 **15 帧（0.75 秒）** 为一个决策窗口。双方同时看到同一帧，各自提交最多 15 条逐帧输入；**收齐两方之后**才统一推进 15 帧。等待思考期间游戏时间不推进，所以本模式不奖励模型网络速度。

每次观察都带 `yourPlayer`、`yourTeam`、`lastErrors`、`decisionWindows:true`、`framesPerWindow:15` 与 `exampleWindow`（一份可照抄的合法窗口）。

输出格式（一行 JSON，立即 flush）：

```json
{"inputs":[{"dir":"F","btn":null},{"dir":"F","btn":null},{"dir":"D","btn":null},{"dir":"DF","btn":null},{"dir":"F","btn":"HP"},{"dir":"N","btn":null}, … 共 15 帧 … ],"note":"可选的简体中文简注"}
```

- `dir` ∈ `N` 中立 / `F` 前 / `B` 后 / `U` 上 / `D` 下 / `UF` `UB` `DF` `DB`。方向是**相对朝向**：`F` 永远是你面前那一侧。
- `btn` ∈ `LP` 轻拳 / `HP` 重拳 / `LK` 轻腿 / `HK` 重腿 / `G` 防御，或 `null`。
- 不足 15 帧的尾部由裁判补 `{N, null}`；超过 15 帧会被拒绝。帧不是对象、方向或按钮名不合法，整场判**技术负**。
- 按住 `B` 或 `DB` 即视为防御（`DB` 是蹲防）。防御分上中下段：`DB` 防不住 overhead，站着防不住 low。

必杀技为「方向序列 + 按钮」，最后一段方向必须与按钮同帧：

| 指令 | 方向序列 | 帧数 |
| --- | --- | --- |
| `qcf` 波动 | ↓ ↓↘ → | 3 |
| `qcb` 反波 | ↓ ↓↙ ← | 3 |
| `dp` 升龙 | → ↓ ↓↘ | 3 |
| `hcb` 半圆后 | → ↘ ↓ ↙ ← | 5 |

序列在 12 帧内完成即算成立，中间可以夹入无关方向帧。**必杀技在普通技命中后的取消窗口内同样成立**，这是连段的核心。

## 计分与胜负

- 一局 = 双方当前出场角色单挑。生命归零或 60 秒到（生命高者胜）即结束该局。
- 车轮战：败者退场换下一名角色，**胜者保留剩余生命、气槽与防御槽**。一方三人全灭即落败。
- 伤害随连段递减：第 1 段 ×1.00，之后 0.90 / 0.80 / 0.70 …，最低 ×0.30。投技按 ×0.45 计。
- 气槽满 100 可发超必杀（威力最大、多数带无敌帧），发动后清空。防御槽归零会**防御崩解**并陷入长硬直。

## 程序协议

程序持续运行，通过 stdin 每行接收一个 JSON 观察，每次必须向 stdout 输出**一行** JSON 并立即 flush。调试日志只写 stderr。状态含完整公开战场（无战争迷雾）。

程序单次响应**硬上限 5 秒**；直接模式单次思考硬上限 180 秒。进程失败、输出格式错误或超时判该局**技术负**，并在结果中单独说明，不冒充游戏战术胜利。空 `inputs` 会按 15 帧中立处理，等价于站着不动。

程序只能运行自己提交的文件；禁止读写进程外数据、访问网络、改变规则或私有裁判。准备期间可做离线模拟，但不得更改受保护的资料文件（`RULES.md`、`GAME.md`、`simulation.js`、`catalog.js`、`example.json`）。允许运行 `node simulation.js` 做自测。

## 时间与复盘

每轮两局，**交换座位**（谁先出手互换），策略在两局之间冻结。每轮硬上限以本轮任务说明为准。比赛结束后必须把实际采用的控制策略、自测结果与局限写入简体中文 `review.md`；没有对局前不得编造复盘结果。赛后另写 `postmatch.md` 做整体复盘。

单一系列 6 局是相关样本，不能据此推断模型的综合能力；同名 `medium` 设置不代表跨厂商的实际推理投入相同。
