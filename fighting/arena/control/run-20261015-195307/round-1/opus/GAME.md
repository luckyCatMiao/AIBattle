# 铁拳谱 / IRON CODEX

一个无需安装依赖的网页 1v1 格斗游戏。双击项目根目录 `StartFighting.bat`，或者运行 `npm run fight` 后打开 <http://127.0.0.1:8795/>。

游戏形态是 **2D 横版单挑**：左右对峙、有朝向、攻击有起手帧/判定帧/收招帧、命中产生硬直、距离与时机决定一切。

## 玩一局

默认「真人练习」模式：你先选三名角色与出场顺序，然后对战内置规则电脑。

| 操作 | 按键 |
| --- | --- |
| 前后 / 上 / 下 | `D` / `A` / `W` / `S` |
| 轻拳 / 重拳 | `J` / `K` |
| 轻腿 / 重腿 | `U` / `I` |
| 防御 | 按住后方向（`A`），蹲防按住 `A`+`S` |
| 显示判定框 | 按住 `H` |

必杀技是「方向序列 + 按钮」，最后一段方向与按钮同帧按下：

| 指令 | 方向序列 | 例子 |
| --- | --- | --- |
| 波动 `qcf` | ↓ ↓↘ → | `S`, `S`+`D`, `D`+轻拳 |
| 反波 `qcb` | ↓ ↓↙ ← | `S`, `S`+`A`, `A`+轻拳 |
| 升龙 `dp` | → ↓ ↓↘ | `D`, `S`, `S`+`D`+重拳 |
| 半圆后 `hcb` | → ↘ ↓ ↙ ← | `D`, `D`+`S`, `S`, `S`+`A`, `A`+重拳 |

序列在 12 帧内完成即算成立，中间可以夹入无关方向帧。**普通技命中后可以在取消窗口内接必杀技**，这是连段的核心。

## 规则

一局的流程：

- 双方各带 3 名角色，**车轮战**：双方当前出场角色单挑，败者换下一名角色，**胜者保留剩余生命、气槽与防御槽继续**。一方三人全灭即落败。
- 每局 60 秒。时间到时生命高者胜；完全相同则判平局。
- 生命 1000，气槽上限 100，防御槽上限 120。

战斗细节：

- **防御分上下段**：`mid` 两种防御都挡得住；`low` 必须蹲防；`overhead` 必须站防。只有必杀技与超必杀带削防伤害，普通技被防御时不掉血。
- **防御槽**在防御时下降、不防御时缓慢回复。归零会**防御崩解**，陷入 30 帧硬直。
- **连段伤害递减**：第 1 段 ×1.00，之后 0.90 / 0.80 / 0.70 …，最低 ×0.30。投技按 ×0.45 计。所以无限连不存在。
- **气槽**满 100 可发超必杀，发动后清空。超必杀威力最大，多数带无敌帧。
- **命中停顿**让攻防双方都短暂冻结，读得出谁先动。
- **倒地起身**有短暂无敌帧，防止无限压起身。
- 命中的普通技可以接下一个普通技（最多三个，同一按钮不能连续重复），或者取消成必杀技。

## 六名角色

**六人的身体完全相同**：同样 1000 生命、同样的行走速度、同样的跳跃弧线、同样的投技范围、同样的倒地与受身规则。角色个性全部来自招式帧数据与三个必杀技。**没有属性克制、没有体型优势、没有对特定角色的额外伤害。**

| 角色 | 类型 | 特点 |
| --- | --- | --- |
| 铁律 · Aegis | 均衡 | 波动拳 + 升龙 + 突进，三件套齐全，无短板也无尖刺 |
| 疾影 · Vex | 突进 | 最快压制：冲刺、空踏、贴脸轻拳连段；手短、凹招靠无敌帧 |
| 长弓 · Kestrel | 远距离 | 手长箭多，把你钉在屏幕另一头；近身只有 3 帧轻拳 |
| 磐岩 · Torv | 重装 | 一格霸体 + 一次抓投 + 一记震地；走位慢、起手久 |
| 幻缚 · Nyx | 奇诡 | 瞬移 + 延迟爆破 + 空投，让对手打空气；判定区间偏窄 |
| 静水 · Sable | 架式 | 格挡架式吃下一次攻击并自动反击；上限最高下限最低 |

目录启动时会做一次**火力预算自检**（`auditBalance()`）：六人的理论输出按可达距离加权后必须在 25% 以内。`GET /api/catalog` 会返回 `balance` 字段，网页也在页脚显示。这是「没有角色天生更强」这句话的可验证依据。

## 外部程序 API

服务端以固定 20 Hz 推进物理帧。网页与外部选手共用同一套规则。

创建对局：

```http
POST /api/matches
Content-Type: application/json

{"players":[{"name":"Agent A","kind":"api"},{"name":"Agent B","kind":"api"}],"seed":1,"mode":"lockstep"}
```

响应为 `{match, seats:[{player,token}], state}`。`player` 从 0 开始；每方必须恰好 2 名选手，房主不能是电脑。把各自的 token 单独交给对应选手，不要交叉传递。

```http
GET /api/catalog            # 六名角色的完整帧数据 + 平衡自检
GET /api/health
GET /api/matches/MATCH_ID   # 可选 Bearer；不带凭据即只读观战
```

选角（每方只能提交一次，双方都选完立即开打）：

```http
POST /api/matches/MATCH_ID/team
Authorization: Bearer YOUR_TOKEN

{"team":["aegis","vex","kestrel"]}
```

`team` 是三名**不同**角色的出场顺序。同一方不能重复，双方可以选到相同的角色。

提交决策窗口（每 15 帧一次，双方同时提交，收齐后统一推进）：

```http
POST /api/matches/MATCH_ID/decisions
Authorization: Bearer YOUR_TOKEN

{"inputs":[{"dir":"F","btn":null},{"dir":"F","btn":null},{"dir":"D","btn":null},{"dir":"DF","btn":null},{"dir":"F","btn":"HP"}, … 共 15 帧 … ],"note":"可选简注"}
```

- `dir` ∈ `N` `F` `B` `U` `D` `UF` `UB` `DF` `DB`，**相对朝向**（`F` 永远是你面前那一侧）。
- `btn` ∈ `LP` `HP` `LK` `HK` `G`，或 `null`。
- 不足 15 帧的尾部由裁判补中立；超过 15 帧、非法方向或非法按钮整条拒绝（不消耗本窗口的提交机会）。
- 同一窗口重复提交返回 `409`。
- 双方都提交后推进整整 15 帧。等待期间游戏时间不推进，所以本模式不奖励网络速度。

真人练习模式另有一条逐帧通道（网页用它驱动键盘）：

```http
POST /api/matches/MATCH_ID/step
{"input":{"dir":"F","btn":"LP"}}
```

攒满 15 帧返回 `{"accepted":true,"advanced":true}`。

观察字段包含完整公开战场（无战争迷雾）：`fighters[]`（位置、速度、朝向、生命、气槽、防御槽、当前状态与出招帧进度）、`projectiles[]`、`players[]`（队伍、当前出场位、统计）、`round`/`roundLog`、`stage`、`rules`、`catalog`、`events`。

不提供对局持久化：重启服务即清空。回放与系列赛归档由竞技框架单独保存。

## 模型对战与回放

双击根目录 `WatchFightingBattle.bat`，或打开 <http://127.0.0.1:8796/?replay=latest>。回放支持选系列、选局、暂停、0.5/1/2/4 倍速、拖动时间轴。

回放入口只读，不会替换练习局保存的席位。URL 的 `run=run-时间戳` 固定系列，新比赛不会覆盖旧回放。

`fighting/arena/train.py` 负责模型竞赛：

```powershell
python fighting/arena/train.py --players opus sol --rounds 3 --prepare-seconds 1800 --port 8796
```

三名角色由模型在 `entry.json` 里自行选择（`team` 字段），出场顺序也是策略的一部分。每轮冻结策略后交换座位打两局；每 15 帧同步决策。准备预算默认 30 分钟，可用 `--prepare-seconds` 调整。客户端 effort 设为 medium；跨厂商同名 effort 不代表计算量相同。

继续双方各自上一版：

```powershell
python fighting/arena/train.py --players opus sol --continue-both --from-run fighting/arena/control/<旧系列目录名> --rounds 3
```

参赛程序在 WSL Bubblewrap 隔离工作区运行，双方看不到对方文件；比赛执行阶段工作区只读、无网络，也不挂载模型凭据。公开规则源码去掉了练习电脑。策略程序每次响应硬上限 5 秒；崩溃、超时或非法响应记技术负，和游戏内胜负分开报告。

`node fighting/arena/audit.js <比赛目录>` 从初始状态重新执行全部双方输入，逐帧核对每一个快照，并核验引擎、角色目录及冻结策略的哈希。对局结果衡量本次策略在当前帧数据下的表现，不是模型综合能力排名。

## 验证

根目录运行 `npm test`。铁拳谱的测试覆盖：角色目录完整性（六人、每人 4 普通技 + 3 必杀 + 1 超必杀、每人都要有远程手段）、无克制关系、火力预算自检、选角原子性、车轮战换人与残血继承、判定帧窗口、防御上下段、连段递减与下限、投技不可防御、投射物、霸体、架式格挡反击、超必杀气槽条件、防御崩解、起身无敌、超时判定、输入校验、同输入必得同结果、终局不可变、以及全部 30 组角色对位都能打出结果。另有 HTTP 测试覆盖席位隔离、同步决策等待语义、越权、凭据不泄漏与静态文件安全。
