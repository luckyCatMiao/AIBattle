## 实际采用的策略

### 1. 按公开源码预测，而非按文字摘要猜参数

文字规则中的判定半径、体力和跳跃描述不完全一致，采用公开 `catalog.js` 与 `simulation.js` 的实际实现：20Hz，球每帧4个子步，二次空气阻力、重力、球网反弹和端线出界；拍面基础半径0.38，随体力缩小；上手和下手各自的扫掠弧线。球员按地面/空中不同加速度、惯性、体力速度修正和冷却更新。

预测约45帧来球，接发球时计算剩余冻结时间和服务端选择的发球角度。每次仅提交前10帧，下一观察重新规划。程序不依赖跨观察文件写入。

### 2. 搜索击球点与上手/下手时机

枚举预计接触帧、挥拍类型、起手时刻、是否起跳及是否冲刺，实际逐帧模拟移动、挥拍和各子步球位置，只有拍面真正进入有效半径才算候选。常规拍龄采样2/4/6，无解后扩大到2/3/4/5/6及左右位置偏移。候选高度过滤覆盖地面与跳跃，避免只追球的水平坐标。

上手高点击球且靠网时有更高评分；普通上手略优于下手，但下手能在低球或安全上手不可行时救球。没有每帧盲目挥拍，预计命中后窗口剩余帧开始回位。若本窗口打不到，先向未来下降球的可接位置移动。

### 3. 将“接到球”与“安全回球”分开

对候选接触点复现服务端出球分类、角度枚举、速度二分和落点。使用观察中的实际网高，额外检查物理碰网所用的子步最小高度，而不只检查插值过网高度。触球点按四种小扰动、对手按三个可能位置检查，危险候选扣40分。

危险拍是**软惩罚**，不是绝对禁用：所有候选都不安全时仍可能选一个。对方位置采样也不是完整对手预测。明显飞出端线的来球留出较大余量后放过。

### 4. 体力、冲刺与回位

不蓄力：服务端本来就按落点求速度，额外加速容易导致出界，且蓄力减速耗体力。普通移动目标速度限制在3.12，低于源码跑动耗体力阈值3.2，但冲刺、惯性、挥拍和跳跃依然会消耗体力。冲刺和起跳设体力门槛，候选评分扣除体力成本。

本轮最终改动很小：相对起始版，杀球候选奖励4→6，额外起跳惩罚1.2→0.7；每点体力成本权重保持0.14。回位仍为左3.05及镜像。不是新写了一个全新的引擎，也没有采用未经验证的对手建模。

## 对照实验与选择依据

首先用 seed=7114 复现起始版对自己历史版本 `retained_start` 的两侧败局：7:11、8:11（比分按起始版自身视角）。起始版对 `round1` 两侧11:4、11:7。

随后实际测试节能候选 `r3_econ.py`：杀球奖励降到2、体力成本权重提高到0.28、起跳惩罚提高到1.8。seed=7114 对 `r3_start`、`retained_start`、`round1` 各换边两局，**1胜5负**。体力虽较健康，进攻与得分反而退化，记录 `r3_econ_test.json`。因此未采用。另生成 `r3_ground.py` 但没有运行对局，不作效果判断。

积极候选 `r3_attack.py` 在相同6场中6胜，随后扩展到60场本地测试。最终 `agent.py` 与这个候选内容一致。以下均为自己的对手程序，不是真实参赛对手。

## 局限与尚未解决的问题

1. 半秒开环、有限接触候选及观察取整，仍可能在边缘判定漏接。
2. 高网对下手防守策略可能打满240秒，甚至仅1:0；进攻效率并不稳定。
3. 固定回位没有完整预测下一拍，对某些随机网高和左右位置仍失利。
4. 体力可能接近耗尽，起跳奖励增加并非免费的提升；低体力测试的15:14也有很大偶然性。
5. 安全检查是有限扰动与对手位置枚举，既不保证完全不挂网，也不保证所选落点难以接到。
6. 对抗对手均来自自己的历史版本或简单基线，缺少真实对手多样性；没有读取或推断真实对方策略。
