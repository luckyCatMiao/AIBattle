### 实际采用的改动及赛后判断

本轮实际提交的是下文记录的 `candidate_robust.py` 对应版本，入口为 `agent.py`。相对保留起始版，已实施的主要改动为：

1. **实际网高适配：**不再写死默认网高，读取 `court.netHeight` 预测碰网；自动发球预测也逐档检查可过网角度。
2. **出球安全检查：**复现公开引擎的角度选择、落点求速和过网检查，对预计触球点的四个小扰动取最差安全评分，减少只在理想击球点安全的选择。
3. **考虑对手移动导致的自动落点切换：**分别用对手当前位置、较深位置和较前位置检查回球安全，取最差评分；不是读取或预测对手私有策略。
4. **保留有条件的进攻与救球：**常规使用有限拍龄搜索，找不到可行触球时再加密并搜索落脚偏移；上手进攻优先考虑高点近网，低球可用下手挑球。不安全球是软扣分而非硬禁，极端救球仍可能失误。
5. **保留节制的体力管理：**普通移动限速 3.12，按需跳跃、冲刺，不蓄力；固定回位到左 3.05 / 右 10.35。这些是已采用设计，不是本次赛后新增功能。

**本次赛后操作仅更新 `review.md`，未修改 `agent.py` 或入口，也未新增或重跑测试。** 两场正式胜利验证了该提交在本轮两组配置中能够赢球，不能证明每项改动都有独立收益。双方都零报错，支持协议运行正常，但不等于没有空挥、战术失误或危险回球。

后续优先检查第二局较小分差背后的失分，以及固定回位、半秒开环和低体力下的防守。需要公开逐分日志或回放后再定位，不根据比分猜测并盲目增大杀球频率。下文保留原有自测证据和已知局限，不把本地胜率冒充正式战绩。

## 规则理解与实际采用策略

以 `catalog.js`、`simulation.js` 的实际执行逻辑为准，摘要中的体力和击球半径数字互有差异。实际拍面半径为 0.38，随体力缩小；挥拍花费 7，起跳花费 10，冲刺每秒消耗 26，球员重力为 22。不能按球员中心附近的宽松距离盲打。

### 击球点与起拍时机

每次预测未来 45 帧，球每帧四个子步，模拟二次阻力、重力、网、天花板和边界。枚举击球帧、上手/下手、挥拍龄和跳跃时机，逐帧模拟自己的加速、移动、体力和冷却，检查真实拍面位置与球的距离。只执行前十帧，下次观察重新规划。

常规搜索挥拍龄 2/4/6；没有可行触球才启动应急搜索，使用 2/3/4/5/6，并添加落脚点 ±0.20 偏移。偏好高点近网的上手杀球；低球采用下手挑球。评分同时考虑触球余量、等待、跳跃及体力消耗。跳跃只在预计能触球时计划，不持续按跳。

### 本次重要修正

1. 原代码把球网判定写死为默认高度。现改为读取每个观察中的 `court.netHeight`，球路预测按实际网高判断碰撞。
2. 自动发球按公开引擎使用角度 0.72/0.85/1.0/1.15/1.3 逐档检查过网，使用相同二分落点法求初速度，而非固定第一档。
3. 出球检查复现引擎的角度顺序、落点二分、备用角、插值网高检查及实际子步最低高度。对预计击球点的四个小扰动取最差安全评分。
4. 引擎会按**触球时对方位置**决定上手球打短还是打深。对手在半秒内会移动，所以额外检查当前位置、较深位置和较前位置三种假设，取最差安全评分。它是粗粒度鲁棒安全检查，不是预测对方策略，也不是读取对方代码。

不安全球扣 40 分，仍不是硬禁止，因此完全无安全选择时可能尝试危险救球。硬筛除版本没有解决高网回归，未采用。

### 体力分配与回位

普通移动目标限速 3.12，低于源码中跑动扣体力的 3.2 阈值；靠近目标制动，站定恢复。必要时才冲刺，起跳和消耗体力在候选评分中扣分。不蓄力：引擎已经按目标落点求速，蓄力加速会破坏落点且降低跑动能力。

击球后回到左 3.05 / 右 10.35。对明确超长来球，综合含网轨迹与额外落点预测后不触球。固定回位仍有被快杀利用的局限。

## 局限与结论

1. 仍是半秒开环控制，固定回位并不等于可靠的下一拍预判；发球后快杀防守依然较弱。
2. 观察只保留两位小数，小扰动和有限候选不提供严格触球保证。
3. 对方位置只检查三种假设，不能覆盖所有位置和所有自动选点边界；危险拍是软扣分，仍可能出现落己方。
4. 高网保守打法可能形成超长相持，初始体力 25 时实际出现 0:0 平局。不能宣称可以稳定快速得分。
5. 低体力普通网局对历史进攻版仍有 9:11 败局；体力管理不是已经解决的问题。
6. 本地对手相关且有限、网高主要测试三个档位，31 胜不是正式胜率，更不是模型综合能力结论。
