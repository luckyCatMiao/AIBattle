# 第 1 轮策略与本地自测

## 提交

- `entry.json`：`{"mode":"program","command":["python","agent.py"]}`。本机 `python3` 命令不存在，已改用所有本地对抗测试实际使用的 `python`。
- `agent.py` 为独立 Python 标准库程序，逐行接收观察，每次输出十帧、每帧一名球员，并立即 flush。运行不访问文件、网络或其他进程。

## 机制理解与实际策略

规则说明中的若干数值相互不一致，因此以公开 `catalog.js`、`simulation.js` 的执行行为为准：20 Hz、每帧四次球子步，拍面半径约 0.38，起跳消耗 10，挥拍消耗 7。实际起跳受较大的球员重力约束，不能按文字中的理想高度估计。

1. **弹道预测**：以 0.0125 秒子步推演二次空气阻力、重力、球网反弹、天花板、出界和落地。发球冻结阶段复现服务端的速度二分求解，提前选择接发位置。
2. **拍面而非身体拦截**：枚举未来约 2.25 秒内的击球时刻、上手/下手、挥拍龄 2/4/6、起跳时机和普通/冲刺移动；复现球员加速、跳跃、体力、冷却及拍面位置，检验球的四个子步是否真正进入有效拍面。保留约 0.035 格余量来抵抗观察四舍五入。
3. **击球点选择**：优先可构成杀球的高点上手；无法高点击球时仍搜索地面上手和低位下手救球。使用实际接触高度与离网距离评估杀球，不把起跳本身视为进攻成功。
4. **体力管理**：普通移动限速约 3.12，低于源码中 3.2 的持续跑动扣体力阈值；紧急远距离拦截才考虑冲刺。对体力开销和起跳额外扣分，避免为了同样的上手球反复无效起跳。没有默认蓄力：服务端已经按目标落点求解速度，再加速容易打出界。
5. **回位**：自己刚击球时向左侧 3.05 / 右侧 10.35 回位，改善对深区杀球的防守。得分冻结阶段中立休息。发球方不抢击自己的发球。
6. **滚动重规划**：每次只执行十帧，下一窗口用新的观察重新规划。不假设知道对手即将提交的输入。

## 自测方法

`test.js` 通过独立 Python 子进程控制双方，每十帧同时提交，使用原公开仿真推进。公开 `simulation.js` 末尾导出了已经删除的 `canSwingNow`、`predictContact`，直接 require 会报错；测试仅在内存加载源码时删除这两个悬空导出名字，未改动任何物理或受保护文件。

对手均由自己编写或由自己的历史版本产生，没有读取对手工作区：
- simple：预测下降位置、接近时连续挥拍。
- aggressive：上述策略加冲刺和跳跃。
- baseline：首版完整预测策略，回位较靠前、起跳成本偏低。
- defensive：调整回位但未提高起跳成本的中间版本。
- ground：最终策略禁止新起跳，其余相同。
- lift：最终预测框架仅用地面下手挑球。
- main：最终策略内战。

### 调参中实际发现的问题

第一版内战最长回合只有一拍，接发杀球几乎直接得分；回位调整后，面对首版两侧打出 11:8、11:6，但对 ground 两侧均 7:11，体力曾降到约 2。提高起跳/体力成本后，最终版本对首版、该中间版均两侧获胜，体力明显改善。中间测试数据分别保存于 `defense_results.json`、`stamina_results.json`，并非最终提交策略的正式战绩。

### 专项场景

`scenarios.js` 构造 48 个场景：左右两侧 × 初始体力 20/50/100 × 初始站位两种 × 低球/快速球/高球/出界球。结果保存于 `scenario_results.json`：
- 低球：12/12 成功触球。
- 高球：12/12 成功触球。
- 快速球：10/12 成功触球；另外 2 例未触球，但球自然出界，控制方得分。
- 明显出界球：0/12 触球，12/12 不碰球并自然得分。

这些测试的成功触球不等于之后一定赢分；场景在首拍成功或得分时停止。另已用真实起始样例验证 stdin/stdout 协议、十帧格式和程序正常退出；一次最初的辅助检查因为 Windows 默认 GBK 解码 example.json 失败，指定 UTF-8 后通过，正式程序也明确使用 UTF-8。

## 局限

- 自写对手和固定开局高度相关，重复相同 seed 不会创造统计独立样本；上述胜率不能外推到正式对手。
- 同策略/ground 内战仍有明显接发与座位效应，都是 14:15，不能据此声称已解决防守。
- 没有完整模拟对手未来移动和挥拍，不在球尚未被对手击回时猜测其精确新弹道；半秒窗口中的突然反击仍可能无法反应。
- 候选是离散采样，不是连续最优控制；低体力、边界、观察误差及跨窗口挥拍状态仍可能漏掉可接球。
- 评分偏好杀球，不完整评估服务端最终选择的击球角、网前球或对手到达时间，仍有球落己方半场的失误。
- 目前偏向省体力的地面球，可能放弃某些需要果断跳跃的高点进攻。专项覆盖不是所有合法球路的穷举。

## 实际采用的策略

1. 继续用公开物理的四子步弹道、球员移动/跳跃/体力和拍面位置做滚动搜索。每次规划约 2.25 秒，只提交前十帧；枚举上手/下手、挥拍龄 2/4/6 和有限起跳时机。
2. 保留偏好高点近网杀球、低球下手救球，以及普通移动限速 3.12、紧急情况冲刺、对体力和起跳开销扣分的策略。固定回位仍为左 3.05 / 右 10.35。没有默认蓄力，避免服务端求解完落点后额外加速造成出界。
3. 新增 `shot_quality`：复现服务端根据击球点、对方位置、前进输入选择杀球/吊球/高远/挑球、目标落点、候选角度及速度二分。先按引擎的选拍逻辑找第一条通过其安全检查的轨迹，然后用实际子步穿网的较低端点高度再检查一次。预计不过网、落己方或出界的候选扣 40 分；若没有其他候选仍允许救球尝试，不保证零失误。
4. 这里区分两种网高检查非常重要：`chooseShot` 用穿网插值高度和 1.65 的门槛，实际球推进用子步两端最低高度和 1.62 的门槛。本策略额外用 1.63 作小幅安全余量，不会因为理论上能选另一角度就假设服务端会选择它。
5. 预测接触内缩量由 0.035 缩小为 0.005，使候选出球评估更接近真实首次触球点，而不是以过晚的拍面深处接触推算出球。观察仍只有两位小数，不能完全消除时机误差。
6. 对候选按原评分排序，仅对有机会胜出的候选进行出球检查，并缓存接近的接触参数。没有采用粗略对方可达性加分：本地回归没有显示其稳定收益。也没有增加网络、文件或外部进程依赖。

### 场景与扰动测试

- `node scenarios.js`：左右 × 初始体力 20/50/100 × 两个站位 × 四种球路，共 48 场景。低球 12/12、快球 12/12、高球 12/12 成功首拍；明显出界球 0/12 触球且 12/12 不碰球自然得分。快速球中存在原本会出界的球，触球成功不是理性放球的证明，也不是后续赢分证明。原始数据为 `scenario_results.json`。
- `OFFSET=.55 RESULT=round2_offset_results.json node varied_test.js round1`：两侧初始站位向网偏移 0.55，对首轮策略仍为 15:13、11:9。仅扰动初始站位，后续每分由服务端重置，覆盖有限。
- `STAMINA=25 RESULT=round2_tired_results.json node varied_test.js round1 lift`：双方初始体力 25，对首轮策略两侧均 **9:11 失利**；对 lift 为 11:8、11:1。这是明确的低体力短板，不用正常体力结果掩盖。
- 直接用 `example.json` 向最终 `agent.py` 持续进程发送四个左右交替观察，检查十帧格式、动作范围、flush、无 stderr、退出码 0，约 0.065 秒完成。最终去除未启用的对手可达性计算后重跑了该协议测试和 48 场景，行为不变；完整 14 场回归在去除此段恒不影响返回值的死计算之前完成。
- 一次辅助汇总脚本未指定 UTF-8，在 Windows GBK 默认编码下读取含中文结果失败；指定 UTF-8 后正常汇总为 2351 窗口。该错误不发生在参赛程序，后者已明确配置 UTF-8。

## 实验过但未采用的方向

中间版本和结果保存在 `round2_*` 文件，不当作最终成绩：

- 将固定回位全面前移至 3.75：对首轮策略 14:15、6:11，后场明显退步，未采用。2.5/2.8/3.2/3.4 的扫描也没有证明全面改善。
- 更密集地枚举挥拍龄和左右 0.18 站位偏移：对首轮策略 9:11、15:14，并在长回合中更耗体力，未采用。
- 按预计对方后场击球调整回位：对首轮策略 9:11、9:11，未采用。
- 把实际子步撞网规则直接替换进选拍角度逻辑：这是错误的服务端建模，因为引擎不会按这个规则重新选角，曾对 lift 左侧 1:11，已修正并保留失败版本作记录。

## 本轮局限

- 尚未获得第 2 轮正式结果，本节不冒充赛后复盘。
- 半秒开环控制、不模拟对手真实未来动作、固定回位的网前漏洞依旧存在。
- 观察四舍五入、首次接触误差、候选缓存量化和离散动作可能让出球评估偏离实际；新检查不能保证无触网或无自失。完整回归仍出现球落己方的失分。
- 对预测不安全球的惩罚是评分，不是硬禁止；没有安全候选时仍可能回出坏球。对出界球也没有完整的主动放球策略，专项快球已经显示会回击某些自然出界球。
- 未启用对方可达性评分；靠高点偏好和安全筛选，不是博弈最优。内战仍有座位差异，低体力对首轮双败。
- 自测不含对方策略，seed 在公开引擎中不能产生独立随机球路。两侧交换和少量扰动只能揭示部分问题，不能替代正式评测。
