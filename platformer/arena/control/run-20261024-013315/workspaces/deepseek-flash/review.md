# 横版闯关竞速 · deepseek-v4.1-flash 第 2 轮策略与自测说明

> 口径说明：本文写于**本轮提交之前**，只包含「实际采用的策略」与「离线自测」结果。
> 本轮正式对局尚未进行，因此本文没有任何对局复盘内容，也不引用任何对局数据。

## 一、总体策略

程序（`agent.py`，单文件、仅标准库、常驻进程、逐行读 stdin / 写 stdout 并 flush）在每次 0.25 秒的决策窗口里做三件事：

1. **精确复刻规则**。用 Python 复刻 `simulation.js` 的玩家物理（加速/摩擦/重力/起跳、X→Y 两段碰撞、移动平台带人）、危险判定（地刺、食人花高度曲线、锯齿圆碰撞、怪物盒）、以及 `generateLevel`
   （关卡 seed = `seed*131 + round*977`）。因此从观察里的 `seed`/`round` 就能**提前知道**每个移动平台、锯齿、食人花的周期与相位，而不是只靠观测值外推。
2. **滚动前向搜索**。以 20 Hz 逐帧模拟 2 秒（40 帧），枚举「跳 / 不跳」。主搜索只允许**全速向右**（竞速里主动让出时间几乎等于让出领先）；它失败后的第一兜底放松为「地面仍只许全速、空中允许 `move ∈ {1,0,-1}` 微调落点」。评分 = 先活着、再尽量靠前。
   每 0.25 秒重规划一次，只执行前 5 帧。
3. **失败时的兜底阶梯**（严格按“尽量不损失前进距离”排序）：
   `空中修正的全速方案` → `远处卡点先跑` → `原地等 k 帧 / 后退 k 帧再全速` → `空中刹车` → `被顶住时的后跳脱身` → `后退` → `原地等`。

另外两条固定规则：

- **卡死图**：地图里出现连续 ≥3 格地刺时（物理上跳不过去，实测安全跨越上限是 2 格），本局改为「最大化 maxX」：全速跑到刺前、在最后一刻起跳，maxX 记到 `s+3.07`（理论最优），做到后回起点等待超时判定。
- **推挤**：被对手贴身顶住时，后方玩家会被压到 4.2 格/秒且**不能后退**（`resolvePush` 把 rear.x 夹到 prevX），唯一出路是起跳越过；被尾随时则绝不原地等，避免被顶进危险物。

## 二、本轮相对第 1 轮的改动

第 1 轮赛后复盘定位到的问题 + 本轮自测新发现的问题，逐条改动：

1. **塌陷砖上不能等**。真实规则是「站上去 0.55 秒后逐层塌」，站着等会跟着一层层沉下去、最后掉坑。
   - 脚下是塌陷砖时（按静态地图判断，不看模型里的 `gone`）绝不原地等待，优先「起跳脱离」；
   - 后退落点检查 `_safe_behind` 同时排除坑、塌陷砖列、地刺列。
   - 自测中这修掉了 `seed 7022` 的沉砖死亡。
2. **观测量化的安全余量**。观察里的 `x/y/vx/vy/time` 只保留两位小数，2 秒预测的累积误差可达 ~0.02 格；在「食人花刚冒头 / 锯齿贴边」时足以翻转判定。
   - 规划用的 `hazard_hit` 对地刺 +0.05、食人花 x +0.04 / 高度阈值 -0.08、锯齿 +0.05、怪物 +0.05；
   - **卡死图的 maxX 搜索里关掉这些余量**，保证 maxX 仍是理论最优（否则会少 0.05–0.3 格，在按 maxX 判定的平局里直接变成输）。
   - 自测中这修掉了 `seed 7028` 第 2 局「差 0.004 格」的食人花临界死亡。
3. **空中修正进入主兜底**。主搜索（只允许全速）失败后，先试「地面全速 + 空中 1/0/-1 逐帧修正落点」，它是前者的超集，能多找到「起跳后空中刹车、落在危险物前面」的方案，从而**少掉进等待/后退兜底**。竞速里后退 0.5 格基本等于把领先让出去。
4. **远处卡点先跑**。40 帧内找不到全速存活方案时，如果全速最多还能活 ≥1.3 秒，说明必死点还在 9 格以外，这一窗口先按「活得最久」的前进方案跑，下一窗口再带着新相位重规划；但要求这一窗口不能把位置跑成「停在塌陷砖 / 食人花或锯齿巡逻带里」。
5. **从慢速对手头顶跳过**。被贴身顶住、且对手明显比自己慢时（对手贴住会把自己压到 4.2 格/秒），跳跃不损失水平速度，验证安全后跳过去。
6. **站在“迟早会被打到”的位置时不要原地等**：能安全后退就后退，退不了就挑一条活得最久的前进路线硬闯。

## 三、自测方法与结果

自测环境：Node 驱动**真实** `simulation.js`（与裁判同一份引擎），Python agent 以子进程方式常驻，逐窗口收发；地图随机、与正式对局同一套生成器。所有数字均为离线自测，**不是**正式对局结果。

### 3.1 单人跑图（35 个种子 × 2 局 = 70 局）

agent 坐 1 号位（起点在前），对手挂机（不挡路），统计每局到达终点用时、死亡、maxX；「理论下界」= 1 秒冻结 + `(goalX − startX)/6.8`。

| 版本 | 可达局数 | 可用局总时长 | 可达局内死亡 | 相对理论下界平均损失 | 最差单局 |
|---|---|---|---|---|---|
| 第 1 轮版本 | 50 / 70 | 1316.00 s | 3 | 1.152 s | +20.56 s（一次死亡） |
| 本轮版本 | 50 / 70 | 1270.15 s | **0** | **0.344 s** | **+0.65 s** |

- 70 局里 20 局是「连续 ≥3 格地刺」的物理卡死图，两个版本都过不去；这些局的 maxX 与理论最优 `s + 3.07` 的偏差均值为 **+0.002 格**（区间 −0.03 ~ +0.01），即双方都只能拿满分。
- 逐局对照：本轮版本在 17 局更快、11 局更慢、22 局完全相同；最差的单局只慢 0.65 s，而第 1 轮版本有两局因为死亡多花 18.6 s / 20.4 s。

### 3.2 机制专项

- **后方推前方**：贴身时后方被压到 4.2 格/秒、且 `rear.x` 被夹到 `prevX`（**不能后退**），唯一出路是起跳；实测对手原地不动时，一窗口内从 9.73 起跳越过、落到 12.98，完成反超。对手全速时不会触发（同速追不上）。
- **跳跃能力边界**：实测「脚底高于地刺顶面」的可用水平窗口约 3.4 格，跨越 N 格地刺需要 `N + 0.72` 格，故 2 格可过、3 格必死——这也是卡死图判定的依据。
- **按 maxX 判定的图**：一口气跑/跳拿到的 maxX 与该图理论最优一致（见上）。

### 3.3 与第 1 轮版本对打

同一进程内同时驱动两套 agent（各自一个常驻子进程），**双方交换座位**，用真实引擎跑完整三局两胜：

| 对局数 | 本轮版本胜 | 第 1 轮版本胜 | 平局 |
|---|---|---|---|
| 60（30 个种子 × 2 个座位） | 22 | 27 | 11 |

解读：
- 22 : 27 : 11 在统计上**没有拉开差距**（胜负比例 22/49，p ≈ 0.32）。逐局看，大部分局的胜负由「座位/出生点」和地图随机性决定：两个版本在同一种子下经常是同一个座位赢（这时谁赢只取决于代码坐在哪边），真正「换座位也赢」的种子只有个位数。
- 自测期间做过消融（同为 20 个种子 × 2 个座位，同期基准 15 胜）：去掉「跳越慢速对手」后 14 胜、去掉「安全余量」后 16 胜，都没有提升，说明这些改动在对打层面至少不是负收益。
- 结论：**本轮改动的主要收益在「单人跑图质量」和「不犯致命错」上（见 3.1：可用局 0 死亡、平均只比理论下界慢 0.34 秒），而不是对同一份旧代码的胜率。** 对打数字说明这版没有因为保守化而变得更差。

### 3.4 耗时

单次响应平均约 5–30 ms，最大约 230 ms，远低于 5 秒硬上限；本地单人跑图时一局（约 25 秒的可达局）约 3 秒跑完。

## 四、已知局限

1. **连续 ≥3 格地刺的图无法通过**（本批自测 20/70 ≈ 29%）。这类局只能比 maxX，双方都做到 `s+3.07` 时基本是平局；赢面只能来自对手失误。
2. **不建模对手的未来输入**。推挤/被推挤只有启发式处理（被顶住不原地等、对方明显变慢时跳过去），没有博弈层；如果对手正好卡在危险物前，自己也可能被迫在“等被顶进去”和“冲进危险物”之间二选一。
3. **观察只有两位小数**，临界相位仍有 ~0.02 格的误差；用安全余量覆盖，代价是偶尔多等 0.1–0.5 秒。
4. **怪物刷新位置依赖领先者 x 与随机数**，没有预测，只在观察出现后规避（刷新点至少在领先者前方 16 格，反应时间足够）。
5. **单人自测的对手是挂机玩家**，与真实对手的对抗强度不同；对打结果见 3.3。
6. 本轮改动集中在“少死一次”和“少等一帧”，属于低方差优化，不改变整体打法；面对同样接近最优的对手时，胜负仍主要取决于谁先犯错。
