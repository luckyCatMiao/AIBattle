# 第 1 轮准备记录（赛前）

## 实际提交

- `entry.json`：`{"mode":"program","command":["python","agent.py"]}`。
- 本机 `python3` 不在 PATH，`python` 可用（Python 3.14），因此将示例命令的解释器改成 `python`，已通过实际子进程启动验证。
- `agent.py` 用二进制管道持续转发 JSON 行给 `node agent_core.js`，避免 Windows GBK/UTF-8 中文乱码；每行输出后立即 flush。
- 没有读取对方工作区、控制目录内容、对方进程或网络；没有修改规则、模拟器、目录参数和例子等受保护文件。

## 策略

1. 使用公开 `simulation.js` 的真实物理，而不是近似抛物线。由观察的 seed、round 和公开生成函数重建移动平台、锯齿及食人花轨迹；玩家、怪物、塌陷计时等由当前公开观察同步。
2. 每个窗口进行约 2 秒（40 个物理帧）的束搜索，宽度 110。每帧可选向右、静止、向左以及相应跳跃；在空中去掉重复的跳跃动作。
3. 按水平进度、速度和落脚安全评分，过滤预测死亡、深度跌落和过于贴近机关的轨迹。加入约 0.035 格机关余量，降低观察保留两位小数造成的擦碰风险。
4. 搜索后仅执行前 5 帧，下一观察重新规划。逐帧起跳，不使用整个窗口统一按跳。
5. 物理模拟包括后推前、前方阻挡以及玩家垂直重叠判定。近身时对候选输入额外模拟对手继续跑、停住、连续跳三种方式，尽量选择当前窗口均安全的候选。不为了推人而主动牺牲通关。
6. 没有把 invuln 当作机关免疫：公开源码虽然递减该字段，但危险物判断并未利用它过滤伤害。

## 实际运行的自测

所有结果均为本地公开模拟器上的自测，不是正式比赛或对手复盘。`public_results.json` 为空，尚无正式赛果。

### 随机地图对抗

测试脚本 `selftest.js` 每张地图测首局，交替座位，对手采用四种自写基线：持续跑、连续跳、反应式避坑/怪物、前方停住挡路且后方追跑推挤。真实模拟逐帧推进、每 5 帧调用一次策略。

最终策略结果：

| 地图种子 | 首局胜利 | 到旗胜利 | 超时距离胜利 | 失败 |
|---|---:|---:|---:|---:|
| 100–107 | 6/8 | 4 | 2 | 2 |
| 300–319 | 19/20 | 12 | 7 | 1 |
| 合计 | 25/28 | 16 | 9 | 3 |

- 原始结果保存在 `selftest_100.json`、`selftest_300.json`，包含死亡事件和单次规划计时。
- 300–319 批次我方死亡事件共 15 次，主要为地刺，也有怪物与锯齿；不能宣称随机图零死亡。
- 最终两批平均单次规划约 15 毫秒，最大约 54 毫秒，低于 5 秒上限（仅是本机测量，非运行时保证）。
- 中间版本另测 200–211，12/12 首局胜利、10 次到旗；这是调试数据，不并入最终版本样本统计。

### 定向对抗场景

`targeted_test.js` 构造 2 格坑、3 格坑、1 格台阶、迎面怪物、后方紧贴推向坑、前方静止挡路六种场景，各测两个座位：12/12 均到达测试目标、零死亡。手工场景在测试中显式注入相同公开物理状态，不作为随机生成地图的预测测试。

此外，在未修改的一张随机地图上，从公开观察重建状态，连续 100 帧施加相同输入，玩家位置最大误差为 0。该测试没有覆盖中途随机刷新怪物。

### 协议与运行

- JavaScript 语法检查、Python 编译检查通过。
- 用 `entry.json` 的真实命令启动程序，连续发送三条含中文的 UTF-8 JSON 行（准备阶段与竞速阶段），均返回合法 5 帧输入，退出正常。
- 这三次端到端响应约 42–59 毫秒。
- 调试时直接把格式化的多行 `example.json` 重定向给逐行程序，出现了预期的 JSON 解析错误；改成单行 JSON 后协议测试通过。Windows 编码错误也已用二进制管道修复并复测。

## 观察到的问题与局限

- 连续 3 格地刺是主要卡点：在人工平地场景中，枚举 300 个满速起跳位置、每次模拟 17 帧，没有安全越过的样本。地刺按整格检测，而非视觉尖端碰撞；这不证明所有状态都不可过，移动平台、台阶或推力可能改变条件。
- 有些地图上会在这类障碍前等待、试探甚至仍因取整或预测误差死亡；最终 28 图里有 3 次首局失败。没有声称已解决这些地图。
- 搜索深度有限，评分偏向短期进度，束搜索可能删掉必要的远期等待/后退路线；并非完整可达性证明。
- 对手不是已知程序，仅作少数行为假设。近身多场景验证只覆盖前 5 帧，不保证对任意主动推挤都安全。
- 搜索不预测未来随机刷新的新怪物（预测状态将刷新计时设得很大）；已有怪物按真实规则运动。每个观察到来后会同步实际刷怪。
- 初始观察坐标取整、塌陷计时取整仍可能造成偏差，安全余量不能完全消除。
- 依赖本机 Python 和 Node，以及比赛工作区内允许读取的公开规则源码；执行阶段不写文件、不联网。

本文件仅记录准备、自测与已知局限，未编造正式比赛复盘。
