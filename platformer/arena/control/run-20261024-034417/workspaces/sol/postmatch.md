# 赛后复盘

## 1. 结果与口径

本复盘针对本次正式比赛的 6 局记录：`r1-g1`、`r1-g2`、`r2-g1`、`r2-g2`、`r3-g1`、`r3-g2`。我是 **sol**。正式结果按双方座位归一化如下：

- **4 胜、2 平、0 负**。
- 第 1 轮：`r1-g1` 以 0:2 取胜，`r1-g2` 以 1:0 取胜。
- 第 2 轮：`r2-g1` 以 0:1 取胜，`r2-g2` 以 1:1 战平。
- 第 3 轮：`r3-g1` 以 1:1 战平，`r3-g2` 以 1:0 取胜。
- 6 局合计小局战绩：**6 胜 2 负 2 平**（这里的“胜/负/平”是各局内的得分小局，不是 6 局的胜负；比赛战报中的 `wins` 是按座位排列，不能直接把第 0 项当作 sol）。

模拟器是 20 Hz，因此 1 个物理帧约等于 0.05 秒；每个决策窗口推进 5 帧，约等于 0.25 秒。战报中的 `duration` 是运行耗时，不能拿它直接除以 0.05 推断模拟时间；下面的“帧数”指战报的模拟帧/快照帧，`frames / 20` 只用于粗略理解仿真推进了多久。正式战报没有随本工作区附带 8211–8232 的逐帧回放事件，所以我不会虚构某个具体碰撞发生在第几帧；能够精确确认的是总帧数、窗口数、比分、死亡数和最终 `maxX`。

## 2. 实际采用的策略

提交的是 `python agent.py`，由 Python 持续桥接到 Node 规划器。核心不是固定脚本，而是基于每次观察的滚动规划：

1. **重建公开物理。** 根据 seed、round 和公开关卡生成逻辑重建地图，把玩家、机关、平台、食人花、锯齿、怪物、塌陷砖状态同步进本地模拟器。规划时使用公开的真实物理推进，而不是只用一个理想抛物线估算跳跃。
2. **滚动束搜索。** 常规搜索宽度 150、深度通常 45 帧；检测到超过约 3 秒没有明显推进时，深度扩大到 60 帧。每次只提交前 5 帧，下一窗口重新观察和规划，因此不会把一次早期判断硬执行很久。
3. **动作候选。** 在每帧尝试向右、停住、向左以及带跳跃的组合；空中不重复消耗跳跃动作。评分主要奖励水平进度、速度和稳定落脚，并过滤预测死亡、深跌落及机关碰撞。
4. **危险余量和近身复核。** 对地刺、食人花、锯齿、怪物等保留约 0.035 格的额外余量。与对手接近时，额外用停住、持续跳跑、反应式跑、先刹车再跳、向左等情景检查未来 10 帧，尽量避免因对手的推挤把我送进机关。
5. **针对地刺的紧急起跳。** 发现前方是即将接触的地刺时，优先提交一次向右跳，避免普通评分因“停在地刺前仍然安全”而选择刹车等待。
6. **加入历史最远距离目标。** 赛制超时按 `maxX` 判定，而不是按超时瞬间的当前位置判定。若我方历史纪录没有领先对手至少 0.5 格，并且剩余时间很少或长时间停滞，就进入抢纪录搜索：寻找能把历史 `maxX` 提高至少 0.3 格的路线。这个分支允许承受一定死亡风险，但没有被当成“死亡也安全”。已经领先 0.5 格时则回到普通安全推进。
7. **不主动把推人当主要武器。** 近身时会利用碰撞和速度差自然推进对手，但目标仍是通关和保留历史纪录，而不是为了推人主动牺牲自己的路线。

## 3. 按局的帧数判读

### `r1-g1`：sol 以 0:2 取胜

- seed 8211，双方座位为 deepseek-flash、sol；战报 `wins: [0, 2]`，因此 sol 赢下本局。
- 共 **1007 帧、202 个窗口**，约 50.35 秒的模拟推进；运行耗时为 7.45 秒。这个局面结束得很快，说明没有进入长时间僵持。
- `deaths: [1, 0]`、`maxX: [88.4, 181.3]`。按座位换算，sol 零死亡并推进到 181.3，对手死亡一次且最远 88.4；这是最清楚的一局“持续推进、即时避障有效”的样本。
- 关键段可以定位到比赛后半段的推进收束：总帧数已到 1007，sol 的纪录已经接近 `goalX=181`，而对手只到 88.4。由于没有事件级回放，不能声称某个具体障碍在某帧被越过；能确认的是最终差距不是靠超时边缘的几十分之一格，而是路线推进质量形成的明显差距。

### `r1-g2`：sol 以 1:0 取胜

- seed 8212，sol 在第 0 座位，`wins: [1, 0]`。
- **4114 帧、823 个窗口**，约 205.70 秒模拟推进；运行耗时 32.8 秒。相较于 `r1-g1`，这是一个明显更长的局面，说明规划器需要反复处理地图机关、重跑或较长的竞速过程。
- `deaths: [0, 0]`，`maxX: [155.1, 154.2]`，即 sol 零死亡，以约 0.9 格的纪录优势完成胜局。这是“保守但稳定”的代表：没有用死亡换纪录，最后仍在非常接近的终点竞争中占先。
- 关键判读是最后阶段的细微差距：双方 `maxX` 几乎相同，不能用“对手明显失误”解释；每个 5 帧窗口的跳跃时机、落脚位置和机关余量都可能影响最终先后。这里滚动重规划比一次性规划整条路线更重要。

### `r2-g1`：sol 以 0:1 取胜

- seed 8221，sol 在第 1 座位，`wins: [0, 1]`。
- **4193 帧、839 个窗口**，约 209.65 秒模拟推进；运行耗时 30.21 秒，是本次最长的局面之一。
- `deaths: [1, 1]`，`maxX: [25.0, 25.1]`。两人都各死一次，而且最终都只到约 25 格；按座位换算 sol 的历史纪录是 25.1，比对手多约 0.1 格，因此这不是“先到旗”，而是极窄的超时/最远距离判定胜利。
- 这是本次最重要的帧数信号：4193 帧并不代表路线走得远，而是大量时间消耗在起点附近的重跑、试探或障碍处理上。普通评分只奖励短期位置会误以为仍可继续等待；新增的历史 `maxX` 目标避免了把当前领先误判为已经安全，但本局也显示 0.1 格的纪录优势非常脆弱，不能把“赢了”误记成策略已经解决了连续障碍。

### `r2-g2`：1:1 平局

- seed 8222，sol 在第 0 座位，战报 `wins: [1, 1]`，因此双方各取一小局，整局平分。
- **2926 帧、585 个窗口**，约 146.30 秒模拟推进；运行耗时 31.3 秒。
- `deaths: [1, 0]`，`maxX: [125.0, 176.2]`。按座位换算，sol 有一次死亡、对手零死亡；最终对手的历史纪录明显更远，但双方已经各有一分，所以没有继续用一局的最后纪录覆盖前一局的结果。
- 关键段的教训是掉坑/碰怪后的重跑并不会抹掉 `maxX`，但会消耗真实时间和当局机会。对手能在零死亡情况下到 176.2，说明此局的主要差距不是单纯“谁更敢冲”，而是我方有一次风险决策打断了连续推进。当前的抢纪录逻辑能处理临近超时的纪录目标，却不能把一次早期死亡的时间损失完全追回。

### `r3-g1`：1:1 平局

- seed 8231，sol 在第 1 座位，`wins: [1, 1]`。

- seed 8232，sol 在第 0 座位，`wins: [1, 0]`。

## 4. 我的失误与可改进之处

### 4.1 失误：把“能活”与“能赢超时判定”混得不够彻底

`r2-g1` 是反例：两边都重跑，最终只在 25 格附近，sol 只领先 0.1 格。虽然历史纪录分支已经存在，但它仍是手工阈值和启发式搜索，不能保证在剩余时间内找到真正可行的纪录路线。改进方向是把以下量放进同一个评分，而不是事后才触发：剩余时间、对手 `maxX`、达到 0.5 格判定门槛所需的距离、死亡后的重跑成本、以及当前路线的可达性。

### 4.2 失误：对“停滞”诊断仍偏粗

`r2-g2` 和 `r3-g1` 说明长时间运行不一定等于有效探索。当前 `stalledFor` 主要看我方 `maxX` 在一段时间内是否增加；它不知道卡住的原因是连续地刺、平台周期、塌陷砖、对手位置还是候选去重过强。改进时应记录停滞前后的机关类型、可达落脚点和每条候选的死亡原因，并对“没有安全候选”与“安全候选被评分压掉”分别处理。

### 4.3 失误：近身推挤的鲁棒性覆盖仍有限

近身时只用少数代表性的对手行为检查 10 帧，不可能覆盖任意逐帧输入。推挤是碰撞结果，不是一个可完全预知的单独动作；对手在坑边、地刺边、锯齿边的速度差可能在很短时间内改变我的落点。改进方向是把不确定性扩展到更长的窗口，并且针对“我方脚下安全、下一帧被横向推入机关”的情况提高惩罚，而不是仅验证当前位置是否已经碰撞。

### 4.4 失误：对怪物的未来刷新没有预测

规划器能避让已经出现在观察中的怪物，但把尚未刷新的怪物近似为不存在。怪物会在 4–6.5 秒刷新，长局中这会使 45/60 帧搜索看不到更远处的动态威胁。应当在候选评估中加入“未来刷新风险”的保守模型，至少考虑怪物出现在预计落脚点附近的情形；同时不能因为保守而把所有可行路线都删掉，需要保留风险分层。

### 4.5 失误：关键障碍时仍可能过于相信模型重建

平台贴边、观察值只保留两位小数、机关计时和塌陷状态都会造成模型与真实状态之间的微小差异。0.035 格余量有帮助，但不是证明。下一版应在平台边缘、锯齿扫过路径、食人花周期切换和塌陷砖剩余时间附近增加不确定性采样，并在连续多个窗口中验证同一落脚点，而不是只看单条最高分束。

## 5. 对四类机制的理解变化

### 5.1 平台跳跃：关键不是“跳得远”，而是“落点和时机”

赛前更容易把平台跳跃理解成固定距离约 4.5 格的抛物线问题。实战后更明确：移动平台的横向位置和速度、起跳时的水平速度、落脚时的平台周期、平台后方的下一块安全地面共同决定路线。一次跳跃即使在几何上够远，也可能因平台正在离开、落点贴边或下一帧被推挤而失败。因此现在的策略坚持短提交、滚动重算，而不是提前把整段跳跃动作锁死。

### 5.2 推人：不是“攻击键”，而是改变碰撞状态的外力

推人不能简单理解为主动造成伤害。后方玩家可以把前方玩家横向推移，前方玩家也可能挡住并反过来改变双方速度；推挤本身不直接判死，真正致死的是被改变后的落点碰到坑、怪物、地刺、食人花或锯齿。实战中，推人既可能帮助我跨过一段路，也可能把我从原本安全的轨迹推到危险边缘，所以我把“避免近身机关”放在“主动推人”之前。

### 5.3 怪物：速度慢不等于风险低

怪物只有约 1.7 格/秒，直觉上容易认为只要持续向右就能甩开。但它会在墙和坑附近改变行为，且会动态刷新；玩家如果因为连续地刺、平台等待或重跑而停在局部区域，怪物就会从“远处的小威胁”变成封锁落脚点的移动障碍。当前规划能处理已观测怪物，却还不能可靠预测未来刷新，这是长局和停滞局的明显短板。

### 5.4 掉坑重跑：死亡不是归零，但时间和节奏会归零

掉坑或碰到危险物后回起点重跑，通常保留历史 `maxX`，并有短暂无敌；因此死亡不是直接输，也不能把死亡后的当前位置当成从零开始。真正损失的是时间、速度节奏、平台周期和再次经过同一障碍的机会。`r2-g1` 证明了这一机制的两面性：双方都能重跑，但长时间反复重跑后，最终胜负可能只剩 0.1 格历史纪录差。策略上应把“可重跑”理解为有限的纠错机会，而不是可以无成本试错；越接近超时，越需要比较一次冒险能增加多少 `maxX`，而不是只看这次是否可能短暂前进。

## 6. 后续改进优先级

1. **把超时判定做成一等目标。** 显式计算达到对手 `maxX + 0.5` 所需的最低纪录，并用剩余时间和预计重跑成本评估是否冒险。
2. **建立停滞诊断。** 区分地刺不可达、平台等待、候选去重、怪物围堵和对手推挤，保存每个失败候选的第一死亡原因。
3. **扩大机关边缘的不确定性模拟。** 对平台、锯齿、食人花、塌陷砖的计时和两位小数观察误差做多样本预测。
4. **把怪物刷新纳入风险层。** 对未来 4–6.5 秒内可能出现的怪物位置做保守评估，同时保留低风险和高收益候选，不用单一最坏情况堵死所有路线。
5. **加强对手交互回归测试。** 尤其覆盖坑边、连续地刺、锯齿扫过、等待平台以及近身推挤后的 20–30 帧，而不是只验证 10 帧内当前玩家没有立刻死亡。

## 结语

这次比赛最重要的收获不是“持续向右就能赢”，而是确认了三层目标必须同时满足：先找到物理上能到达的落脚点，再避开对手和动态机关，最后还要在有限时间内把有效推进转化为足够的历史 `maxX`。实际策略在 4 胜 2 平、没有输局的结果中证明了滚动束搜索、机关重建和短窗口执行的价值；但两局平局以及 `r2-g1` 的极窄纪录优势也说明，超时目标、停滞诊断、未来怪物和推挤鲁棒性仍未被彻底解决。
