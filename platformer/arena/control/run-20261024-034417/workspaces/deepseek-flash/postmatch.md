## 二、我实际采用的策略

### 2.1 程序结构

`agent.py` 是单文件、仅标准库、常驻进程：stdin 每行一个 JSON 观察，stdout 回一行 5 帧输入。它逐行复刻了 `simulation.js` 的加速/摩擦/重力/起跳、X→Y 两段碰撞、移动平台带人、塌陷砖、地刺/食人花/锯齿/怪物判定，以及关卡生成器；因此能直接从 `seed/round` 推出移动平台、锯齿、食人花的周期与相位，而不是只靠观测外推。

### 2.2 每 0.25 秒的决策

每个决策窗口做一次“先活着、再往前”的前向搜索，只执行前 5 帧：

1. `build_frame_data` 预生成 112 帧（5.6s）的动态机关状态；
2. 主搜索 `search_survive` 视界 40 帧（2s），地面只允许全速向右，枚举跳/不跳，目标是 40 帧内存活并尽量靠前；
3. 主搜索失败后退到 `search_survive_wait`（48 帧，允许地面停下/后退）、`search_survive_air`（34 帧，空中允许 `-1/0/+1` 修正）；
4. 再失败则走兜底阶梯：`KEEP-RUN` → `WAIT` → `CRUMBLE-JUMP` → 前缀等待/后退 → `FALLBACK-AIR` → 原地等；
5. 观测只有两位小数，因此对地刺、食人花、锯齿、怪物分别留 `+0.05 / +0.04 / +0.05 / +0.05` 的安全余量（食人花高度阈值再减 0.08），并用 `boundary_ok` 做量化后的边界复核。

### 2.3 特殊分支

- **卡死图 maxX 模式**：地图出现连续 3 格地刺时，物理上无法通过。程序改为“全速跑到刺前起跳，把 `maxX` 做到 `sx+3.07` 左右，死亡回起点后待机”。死亡帧会先更新 `maxX` 再判定，所以这是规则内的最优得分方式。阈值从第 1 轮的 `sx+2.8` 提高到第 3 轮的 `sx+2.95`。
- **`JUMP-OVER`**：被慢速对手贴身挡住时，后推只会把自己压到 4.2 格/秒、把对手送快，因此优先跳过去。
- **`PUSH-PLAN` / `IDLE-ANTIPUSH`**：对手在身后 1.05 格内时，用“每帧 +0.20 格前推”的影子世界重搜；卡死图待机时若对手从身后贴近并向右移动，原地起跳（跳跃时垂直重叠不足 0.3，推挤不生效）。
- **第 3 轮新增的追尾模型 `PF_REAR`**：对手在前方 0.02–4.0 格且（距离 <2 格或明显减速）时，`_predict_opp` 假设前车会为锯齿急刹，`_clamp_rear` 把我方夹到 `ox-0.72`、速度压到 4.2，再搜索。
- **没有做的事**：没有读取对手代码、没有联网、没有学习；没有主动“把对手推进机关”的规划；没有预测怪物刷新点；没有跨窗口的全局路线承诺。

### 2.4 三轮改动与实战效果

| 轮次 | 新增 / 修改 | 预期 | 实战 |
| --- | --- | --- | --- |
| 第 1 轮 | 物理复刻 + 2s 前向搜索 + maxX 模式 + 观测余量 | 稳定不失误 | 0:2、0:1；R2 的 0.005 格坑沿量化掉坑 |
| 第 2 轮 | `search_survive_push`、`IDLE-ANTIPUSH`、推挤分支的 strict 边界复核 | 防“被身后对手推进机关” | 0:1、1:1；防推分支只在 `r2-g2` 触发 20 个窗口，未覆盖实际失分的“我在后追尾”和“相位差” |
| 第 3 轮 | `PF_REAR` 追尾夹速、maxX 阈值 2.8→2.95、`BOUND_CHECK` 默认开、`FAST_MODE` | 修正第 2 轮的追尾失分 | 1:1、0:1；`PF_REAR` 净负向，阈值 2.95 有效 |

- frame 3751 我复活回起点，sol 随后 x=147.28 到终点。
- **判读**：这是“我在前、被后车推”的致命分支。第 2 轮的防推逻辑只覆盖了“对手在身后”的部分场景，没有把“前车被顶 0.17 格后仍可能进入机关判定”完整纳入边界复核。

## 四、我的失误与可改进之处

### P0：`PF_REAR` 是负向改动，应先回退或加双世界校验

- 证据：`r3-g1` R1 frame 190–194；预测 sol 停在 62.10，实际 0.45s 后到 64.82，误差 2.72 格；直接导致撞锯。
- A/B：`r3-g1` 只改变 10/575 个窗口，`r3-g2` 0/823 个；没有观察到任何收益。
- 改法：默认关闭；或要求候选计划在“前车急刹”和“前车全速/起跳”两个世界都至少存活 40 帧，否则退回自由世界；把急刹判据收紧为“前车在地面、距锯齿 <0.8 格、且未起跳”。

### P0：推挤模型是“单边”的，必须统一成前后双向

- 现有模型只覆盖“对手在身后推我”，但本次系列赛的致命推挤覆盖了全部四种位置关系：
  1. **我在后追尾前车**：`r2-g1` R1 被夹到 4.2 掉坑；`r2-g2` R1 相对摆动 0.82 格；
  2. **我在前被后车顶**：`r3-g2` R3 被顶 0.17 格撞锯；`r1-g2` R1 在起点被顶 11.8 格进花；
  3. **对手在后追尾我，对手自己被限速**：`r2-g2` R3 我因此获胜；
  4. **对手在后追尾我，我被推快**：`r3-g1` R3 我把 sol 顶进花（`minFront` 放大到 +0.66）。
- 改法：把 `resolvePush` 完整复刻成 `_clamp_rear` + `_clamp_front`，在搜索和 `boundary_ok` 里都加入“前 5 帧每帧最多 +0.20 格前推”的影子世界，并复刻 `max(prevX, maxRear)` / `minFront` 的放大；在危险物 3 格内，把“与对手水平距离 <1.2 格”本身当作风险，而不是只在对手位于身后时才检查。
- 另一个便宜的改进：危险走廊前若对手在身后 2 格内，优先用一次跳跃拉开垂直重叠（跳跃时 push 不生效），而不是继续贴地跑。

### P1：量化边界要留“支撑余量”，不能只做一次边界复核

- 证据：`r1-g1` R2 的 0.005 格坑沿；第 3 轮 `BOUND_CHECK` 默认开启后没有再出现同类事故，但这是“事后复核”，不是“事前避免”。
- 改法：落点评价里拒绝“支撑宽度 <0.08~0.10 格”的坑沿；执行 5 帧后按两位小数重新量化状态，再做一次短视界存活搜索；把观测 `x` 当作区间 `[x-0.005, x+0.005]` 而不是点。

### P1：缺少“推迟 0.1–0.3 秒进入危险走廊”的候选

- 证据：`r1-g2` R3 输 0.87 格、`r2-g2` R1 输 1.65 格，都是“先到者被迫刹车、后到者吃相位”。这不是判定错误，而是目标函数只最大化自己的 x，没有比较“晚一点进走廊、保持全速”的相对收益。
- 改法：在锯齿/食人花前 8–12 格把视界从 2s 延到 3s，显式加入“延迟进入”候选；评分从“自己的 maxX”改成“到终点的预计相对位置”，并保留“落地后 0.5 秒的速度保持”项。

### P2：怪物只做当前帧规避，没有方向外推

- 证据：`r2-g2` R2 frame 745（t=37.25），我在 x=57.68 被一只向左巡逻的怪杀死；这是 73 次刷新里唯一一次怪物击杀，发生在我做刺墙 maxX 冲刺的起跳/下落段。
- 改法：在 2s 预测里按 `dir×1.7` 外推怪物位置，尤其是刺墙前的下落段；把怪物当成“移动的禁落区”，而不是看到才躲。优先级不必太高——73 次刷新只杀 1 次——但这是廉价且确定的改进。

### P2：maxX 阈值 2.95 仍偏保守，且“提前收手”需要复核

- 证据：`r2-g1` R3 我在 25.03（`sx+3.03`）就停止，sol 做到 25.07；虽然 0.04 远小于 0.5 判平线，但这是唯一一次低于 `sx+3.06` 的收手。
- 改法：阈值提高到 `sx+3.0`，或在达到 `sx+2.95` 后再做一次最优尝试；同时保留“死亡不扣分”的卡死图逻辑，避免为了 0.04 格多花 10 秒。

### P1（流程）：赛前评估覆盖不足，模型被上一轮的失分“过拟合”

- 第 2 轮结束后，我针对“后车追尾”加了 `PF_REAR`，但它只覆盖“前车会急刹”这一种假设；A/B 只统计了计划差异窗口数，没有跑“前车起跳/全速”的对抗回归。结果它在 `r3-g1` R1 直接造成死亡。
- 改法：每次改动必须配三类回归：①上一轮真实回放的关键窗口；②对手“急刹/全速/起跳”三种脚本化反应；③held-out 种子的自对弈。对只改变 <2% 窗口的改动，要额外证明它在失败模式上不会反噬。

### 关于“进攻性推挤”的取舍

- 我两胜都来自对手死亡，但都不是我主动规划的：`r2-g2` R3 是 sol 追尾后被限速踩刺，`r3-g1` R3 是 `minFront` 把我被动顶到花上。
- 推挤可以把 0.2–0.7 格放大成生死差，理论上是可训练的进攻手段；但它同时要求自己处在“前车”或“后车”的致命走廊里，方差很高。下一轮若要做，应该只作为“领先 <1 格、对手在身后、前方 3 格内有贴地机关”的条件战术，并先在模拟器里做 1000 局回归，不能直接上线。

## 五、对四类机制的理解变化

### 5.1 平台跳跃：从“局部躲避”到“不可逆的承诺”

- **赛前/早期**：把跳跃当成一次可以随时修正的躲避动作，2 秒搜索里枚举跳/不跳，空中再微调。
- **赛后**：跳跃是约 **2.3 格高、4.5 格远**的不可逆承诺；空中加速度只有 40，主要能力是刹车，不能把已经选错的起跳点“救回来”。真正决定生死的是**起跳时机相对于机关相位和对手位置**，而不是落地后的微操。
- 具体变化：
  - 先到锯齿/食人花走廊的人经常要空中刹车，后到的人反而吃到相位窗口；这让“领先”在走廊前不一定是优势（`r1-g2` R3、`r2-g2` R1）。
  - 3 连刺不是“难跳”，而是**不可通过**；正确反应是立刻切换到 maxX 模式，而不是反复尝试。8 张卡死图全部判平，说明这个识别是对的。
  - 塌陷砖不能站着等（0.55s 后塌），移动平台会带人；这两点程序复刻得比较准，本次没有因它们死亡。
  - 坑沿的最后 0.01–0.05 格不能作为落点；两位小数观测会把“刚好站住”变成“下一窗口踩空”。

### 5.2 推人：从“防御边缘情况”到“决定胜负的相对位置机制”

- **赛前/早期**：把推人理解成“对手在身后时可能把我推进机关”，所以只做了身后方向的防推。
- **赛后**：推挤是双向的、发生在机关判定之前的核心机制：
  - **后车**被压到 4.2 格/秒，损失的是速度；这在坑边就是“少 0.1 格撞壁”（`r2-g1` R1）。
  - **前车**被推快，收益是位置；但靠近机关时，+0.17 格就足以从“安全”变成“判定内”（`r3-g2` R3：0.630 → 0.460，阈值 0.53）。
  - `resolvePush` 还有 `minFront` 放大：`r3-g1` R3 的 +0.66 格远大于单帧 0.21 格。
  - 跳跃时垂直重叠 <0.3 格，推挤不生效；这是被贴身时最可靠的脱身手段（`IDLE-ANTIPUSH` 的原理）。
  - 起点待机不安全：`r1-g2` R1 被从 x≈4.6 推到 14.97，说明“回到起点等超时”必须配合防推。
- **对策略的影响**：不再把“贴着对手跑”当成中性；在危险物 3 格内，前后 1.2 格都视为风险区。推挤建模必须是双向影子世界，而不是单边防御。

### 5.3 怪物：从“主要威胁”到“低击杀率的路况扰动”

- **赛前/早期**：把怪物当成需要重点规避的追击者。
- **赛后**：73 次刷新只有 1 次击杀（`r2-g2` R2 frame 745）。怪物的实际影响主要是：
  - 迫使你在错误时机空中刹车或改变落点；
  - 在 maxX 冲刺的起跳/下落段与刺墙重叠时，偶尔补刀；
  - 刷新在领先者前方 16–34 格、只刷在连续平地，遇墙/坑掉头，速度 1.7 格/秒——它更像“移动的禁落区”，而不是主动追杀。
- **对策略的影响**：不值得为怪物做重型建模，但应该做两件廉价的事：①按 `dir×1.7` 外推 2 秒位置；②刺墙前下落时优先选择没有怪物巡逻的落点。复活时起点前方 12 格怪物会被清除、2 秒无敌，所以复活点本身是安全的，不需要额外防怪。

### 5.4 掉坑重跑：死亡不是统一的“坏”，要分局面讨论

- **赛前/早期**：把死亡一律当成需要避免的损失。
- **赛后**：死亡的成本完全取决于局面：
  - **可赢的干净竞速**：一次死亡 = 回起点 + 重跑，干净跑完要 22–27 秒；对手只要领先 8 格以上，本局基本结束。`r1-g1` R2（37.85s 掉坑，sol 领先 8.00 格）和 `r2-g1` R1（13.65s 掉坑，sol 随后 26.50s 到终点）都是这样输的。
  - **3 连刺卡死图**：死亡是得分动作。死亡帧先更新 `maxX`，再复活；真正的最优是“冲到 `sx+3.0x`、死一次、回起点待机”。这时追求“零死亡”反而会少拿 maxX。
  - **已经锁定平局/领先时**：待机要防推，不能站在起点前的食人花/地刺走廊里。
- **对策略的影响**：目标函数不该是“全局最小化死亡”，而应是“在可赢子局中保护完整跑；在不可赢子局中最大化 maxX，并接受一次计划内死亡”。这也是为什么我的总死亡 15 次、sol 52 次，但 sol 在真正决定胜负的子局里只死了 2 次——总死亡数不能直接比较。

## 六、结论

1. **核心系统是可靠的**：物理复刻 + 2 秒前向搜索 + maxX 模式，6 场 0 技术失误、0 超时；8 张卡死图全部拿到 `sx+3.0x` 并判平。说明“确定性机关 + 短视界搜索”这条路是对的。
2. **差距在“干净竞速”**：双方都不死的 3 个决胜子局，我 0 胜 3 负，分别输 2.14 / 0.87 / 1.65 格；两胜都依赖 sol 死亡。要真正赢系列赛，必须把“先到走廊被迫刹车”的 0.9–1.8 格损失补回来，而不是等对手失误。
3. **最大的直接失分来源是推挤与自身模型错误**：7 个负子局里，4 个是我方死亡（掉坑 1、追尾掉坑 1、模型误判撞锯 1、被推撞锯 1），3 个是纯速度。`PF_REAR` 是唯一一个“改了就立刻输一局”的负向改动。
4. **下一轮优先级**：①回退/双世界化 `PF_REAR`；②统一前后双向推挤影子世界，危险物 3 格内保持 1.2 格以上间距或用跳跃断开推挤；③锯齿/食人花走廊 3 秒视界 + 延迟进入候选；④落点支撑余量与执行后重量化；⑤怪物方向外推（低优先级）。
5. **一句话总结**：这次我赢在“活得久”和“会认不可赢的图”，输在“干净跑不过 sol”以及“在关键 0.2 秒里把对手的意图猜错”。下一次要把这两件事分开处理：速度问题用更长视界和延迟进入解决，安全问题用双向推挤世界和量化边界解决。
