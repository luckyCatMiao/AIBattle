## 〇、关键结论

1. **两场结果：`r3-g1` 1:1 平，`r3-g2` 0:1 负于 sol。** 六个子局合计：我方 1 胜、2 负、3 平。

2. **两个决定子局生死的事件都是推挤，而且方向相反：**
   - `r3-g1` R3（frame 2724）：我方在后，把 sol 从 x=148.31 一路顶到 x=148.97（共 +0.66 格），
     推进 x=149.5 食人花的判定范围，sol 死亡；我方随后 196.13 到终点。这是本场唯一的“推人致死”进攻事件，且是被动发生的。

   在 `r3-g2` 改变 0/823 个；其中 frame 195 这个窗口的变化直接输掉 R1。关闭 `PF_REAR` 时同一窗口改为“先跳”，可安全越过锯齿。

   `r3-g1` R2 71.08（刺 68–70）、`r3-g2` R1 104.07（刺 101–103）、`r3-g2` R2 18.06（刺 15–17），
   对应 `sx+3.08 / +3.07 / +3.06`，均高于本轮阈值 `sx+2.95`。三局都判平，阈值没有造成提前收手。
5. **两场 0 技术失误、0 超时；33 次怪物刷新、0 次怪物击杀。** 死亡全部来自地刺、锯齿、食人花。

- 两场 33 次刷新、0 次怪物击杀；所有死亡原因均为地刺（46 次）、锯齿（3 次）、食人花（1 次）等固定机关。
- 最危险的一次是 `r3-g2` R2 frame 2555：怪物 x=14.87 距 sol 0.85 格；sol 在 0.55s 后（frame 2566）踩中地刺死亡，
  怪物没有补刀。

## 五、本轮改动与赛后评估

### 5.1 赛前实际提交的改动

本轮相对第 2 轮提交版，`agent.py` 的改动为：

| # | 改动 | 默认 | 赛前理由 |
| --- | --- | --- | --- |
| 1 | `_predict_opp` + `_clamp_rear`：我方在后方 0.02–4.0 格时，预测前车会为锯齿急刹，并把追尾后的 x 夹到 `ox-0.72`、vx 压到 4.2 | 开（`PF_REAR`） | 第 2 轮两次失分都是“后车追尾前车、被夹速后掉坑/踩刺” |
| 2 | 卡死图 maxX 停止阈值 `sx+2.8` → `sx+2.95` | 开 | 第 2 轮实测死亡帧 maxX 可达 `sx+3.03~3.07`，旧阈值会提前收手 |
| 3 | `BOUND_CHECK` 量化边界复核默认开启 | 开 | 防止“坑沿 0.005 格支撑”在两位小数观测后消失 |
| 4 | `FAST_MODE` 超时安全阀（单窗口 >2.5s 后跳过边界复核） | 开 | 保证 5s 硬上限 |

保留项：`IDLE-ANTIPUSH`、`PUSH_PLAN`、`JUMP-OVER`、怪物方向外推、观测安全余量等。

### 5.2 赛后评估：哪些改动作了用，哪些帮了倒忙

1. **追尾模型：净负向，且是 `r3-g1` R1 的直接死因。**
   - 它在 `r3-g1` 只改变了 10/575 个窗口的计划，在 `r3-g2` 改变 0/823 个；没有观察到任何可归因的收益。
   - frame 195 这个窗口，它把 sol 预测成“急刹停在 x=62.10”，实际 sol 跳过去了（0.45s 后 x=64.82）；
     模型据此把计划从“先跳”改成“晚 1 帧跳”，正好撞锯。
   - 关闭 `PF_REAR` 后，同一窗口改为“先跳”，agent 模型内可安全通过；真实引擎开环复算也把首次死亡从 frame 195 推到 frame 365。
   - 结论：这个模型把“前车遇到锯齿”一律当成“必刹车”，假阳性代价太高；而本轮两场真正的推挤都不是“我方在后被夹速”。
2. **maxX 阈值 2.95：有效。** 三张 3 连刺卡死图分别拿到 71.08 / 104.07 / 18.06（= sx+3.08 / +3.07 / +3.06），
   均超过 `sx+2.95`，程序在第一次死亡后正确转入待机；三局都靠理论值判平，没有出现第 2 轮那种 0.04 格余量风险。
3. **`BOUND_CHECK` / `FAST_MODE`：没有出现反例，但也不能单独归因收益。**
   两场 0 错误、0 超时；`r3-g2` 唯一一个窗口差异发生在比赛已结束后，与边界复核无关。
4. **进攻性推挤：没有专门实现，但 `r3-g1` R3 被动吃到了一次。**
   frame 2724 的 `resolvePush` 因为后车 `prevX > maxRear`，把前车额外顶了 0.45 格（总 +0.66），
   直接把 sol 送进食人花。这说明推挤规则的上限比“每帧 0.21 格”更大，值得建模，但不应依赖偶然。

### 5.3 若还有下一轮，优先改这三处（本轮未提交）

1. **修 `_predict_opp` 的假阳性：双世界校验。**
   当预测前车会急刹时，同时保留“前车全速/起跳”的自由世界；要求候选计划在**两个世界**里都至少存活 40 帧，
   否则退回自由世界的计划（本例即“先跳”）。或者把急刹判据收紧为“前车在地面、且锯齿距离 <0.8 格、且前车没有起跳”。
   依据：`r3-g1` R1，dx=1.16、前车随后直接起跳越过锯齿，模型仍判必刹车。
2. **补“我方在前、被后车推”的影子世界。**
   当对手在身后 2 格内、垂直重叠 >0.3 时，在搜索/边界复核中给我方每帧加最多 0.21 格前推，
   并复刻 `resolvePush` 的 `minFront = rear.x + 0.72` 放大效应；要求计划在这个影子世界里也存活。
   依据：`r3-g2` R3，0.17 格前推把到锯齿的水平距离从 0.630 压到 0.460（判定线 0.53），直接撞锯。
3. **把 `resolvePush` 完整复刻成 `_clamp_rear` + `_clamp_front`。**
   现有 `_clamp_rear` 只处理“我方在后”，且只把 x 夹到 `ox-0.72`；没有处理“我方在前被顶”以及
   `max(prevX, maxRear)` / `minFront` 造成的额外位移（`r3-g1` R3 实际 +0.66 格）。
   依据：两场唯一的两次决定性推挤都来自这条规则的不同分支。

可选项（未验证，不建议直接上）：在领先 <1 格且对手在身后、前方有贴地锯齿/食人花时，
主动选择“更早起跳/更早刹车”的线路，避免自己正好处在对手的推挤走廊里。本轮没有数据支持，先不做。

## 六、局限与诚实说明

1. **反事实是开环的。** 反事实用回放中对手的固定输入重放，只改变我方某一窗口的动作；
   对手不会因为位置变化而重新决策，因此只能证明“该死亡在相同对手动作下可避免”，不能证明“比赛结果一定反转”。
2. **样本小。** 两场 6 个子局、3 张卡死图；`r3-g1` 的平局和 `r3-g2` 的失利不能外推为模型强度结论。
3. **公开战报口径。** `deaths` / `maxX` / `level` 只取最后一个子局；本文的整场统计来自逐帧回放，两者不要混用。
4. **回放一致性。** `r3-g1` 575/575 窗口一致；`r3-g2` 822/823 一致，唯一差异在最后一帧、比赛已结束，不影响任何结论。
5. **未量化项。** 回放不记录单窗口响应时间，因此无法证明 `FAST_MODE` 是否触发；只能说两场没有超时/技术负。
6. **本轮没有实现**“主动把对手推下坑/推进机关”的规划；`r3-g1` R3 的推人致死是被动结果，不应写成主动战术。
