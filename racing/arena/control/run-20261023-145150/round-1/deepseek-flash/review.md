# 俯视角赛车 第 1 轮 · 实现与自测记录（deepseek-v4.1-flash）

> 尚未与对手交手。本文件只记录**实际做过的离线自测**与实现策略，不含任何虚构的对局复盘。

## 1. 提交形式

`entry.json` → `{"mode":"program","command":["node","agent.js"]}`。
单文件、无外部依赖、无网络、无子进程；stdin 每行一个观察，stdout 立即回一行 20 帧输入。

## 2. 总体思路：精确物理复制 + 窗口内前向模拟 + 滚动优化

1. **把裁判物理逐行复制进 agent**（`simulation.js` 的 `updateCar/moveCar`：推力、阻力、
   漂移抓地、转向增益、漂移蓄能、喷火、越野、撞墙全部照抄）。
   用 `tools/verify.js` 在真实赛道上喂 600 帧随机输入与官方引擎逐帧比对：
   **最大偏差 0.0**（完全一致）。
2. 服务端每 20 帧才收一次输入，等于有 1 秒「盲区」。因为物理可精确预演，
   agent 在窗口内**自己向前仿真 20 帧**，每帧用预测状态重算控制量，再把 20 帧一起交上去。
3. **短时域 MPC 选转向**：每帧对 11 个候选 `steer∈[-1,1]` 各向前仿真 H 帧
   （`H = clamp(0.95·v, 14, 26)`，高速时看得更远），
   代价 = 横向偏离赛线的平方和（后段加权）+ 出路面重罚 + 速度方向与切线夹角误差
   + **反向行驶重罚**（`Δs<0` 平方罚）+ 方向盘变化平滑项。
   这条物理里漂移会大幅侧滑且有明显滞后，解析式跟踪器很难稳定；MPC 直接把非线性吃进仿真，实测稳得多。

## 3. 各模块细节

### 3.1 赛道与行车线
`track.points` 重采样成 0.5 格间距的闭合折线，算切向/法向/平滑曲率 `κ(s)`。
行车线按曲率向弯内偏移 `d = sign(κ)·D·tanh(|κ|/0.07)`，`D = halfWidth − 1.4`，再沿弧长 ±2 格平滑。
车辆状态每帧投影到该线（**全局粗搜 + 局部细化**，避免被撞飞后锁死在错误赛段）。

### 3.2 油门与喷火：本轮最大的一个修正
初版把目标速度恒设为 14，喷火时油门公式看到 `v > 14` 就给出负油门（刹车），
**喷火 +30 的推力被 −26 的刹车几乎抵消**，能量白烧。改成「喷火时目标速度提到 20+」之后：

| 同一套 80 条随机赛道 | 平均完赛时间 |
| --- | --- |
| 修正前（喷火被刹车抵消） | 103.3 s |
| 修正后 `boostTarget=20` | 79.6 s |
| 修正后 `boostTarget=22` | 74.5 s |
| 最终 `boostTarget=23` + 出路面重罚 800 | 71.8 s |

喷火策略取最激进的一档：`boostEnergy > 0.05` 就点（不限制必须直线）。

### 3.3 漂移：常开
这条物理里漂移的本质是「车头转得比速度方向快」，侧向速度 0.985/帧保留、滑移角越积越大；
全舵持续漂移会打转并把速度崩到 2–3 格/秒。自测结论是「**只要打方向就开漂移**」最快：
转向速率 ×1.6、且侧向速度不被每帧 0.8 地削掉，弯中能保住 15–21 格/秒的总速度；
`|steer|<0.15` 时物理层自动断开并把蓄能一次性转入 `boostEnergy`，
于是直道上的小幅修正方向反而成了「免费加油」。
80 条种子对比：常开漂移 79.6 s vs 关漂移约 106 s；代价是出路面比例从 ~0.03% 升到 ~1–2%。

### 3.4 检查点保障
检查点半径只有 `halfWidth+0.6`，而高速切弯时车实际轨迹会比中心线更靠内，曾经出现「跑得飞快但漏点、
永远不计圈」的灾难（某条赛道 141 秒才完赛）。两层保护：
1. **赛线在检查点附近收窄**：以检查点为中心 ±6 格做余弦窗，把该段横向偏移压到 50%，让车更靠近检查点圆心；
2. **漏点回追**：若沿赛道弧长已越过下一个检查点 9 格仍未触发（`nextCp` 未推进），
   直接切到「朝检查点开」的应急模式（限速 8、关喷火），补到后自动恢复。

### 3.5 卡死恢复
被撞/冲出路面后可能「顶着地图边墙、速度≈0、低速又打不动方向」。
连续 14 帧速度 < 1.2 格/秒就倒车 26 帧 + 交替满舵，再恢复正常控制。

## 4. 自测结果（全部用公开 `simulation.js` 真实引擎 + 随机种子整局跑完）

| 项目 | 结果 |
| --- | --- |
| 物理模型一致性（600 帧随机输入） | 最大偏差 **0** |
| 随机赛道完赛率（**最终配置**：seed 2000–2039+2100–2139 共 80 局、7000–7099 共 100 局） | **180/180 全部完赛**，无技术负、无卡死（另在调参过程中跑过 400+ 局其它配置，同样无卡死） |
| 平均完赛时间（seed 7000–7099，100 条，最终配置） | **70.1 s**（赛道 450–650 格） |
| 平均最快单圈 | **22.1 s**（对应 450–650 格赛道 19–31 s） |
| 时间/单圈比 `finish / bestLap` | **3.17**（干净比赛约 3.1–3.2；漏点会 >4，本轮 100 局中 0 次） |
| 出路面帧占比 | **1.07%** |
| 平均速度（沿赛道） | 约 **21.2 格/秒**（峰值 25 格/秒），即 23 格/秒喷火上限的 ~92%；喷火时长占比约 80% |
| 与「同策略镜像对手」自对弈（10 局） | 双方正常完赛，碰撞 0 |
| 套圈较慢对手（对手限速 9.5，10 局） | 完赛时间与独跑基本持平（最多 +1 s），每局 0–5 次碰撞 |
| 单窗口决策耗时 / 进程往返 | 典型 2–5 ms / **最大 24 ms**（硬上限 5000 ms） |

调参过程中比较过但**未采用**的方案：
* 「弯前显式减速」速度曲线（`v≤a/√κ`）：慢 4–8 s，因为弯中掉速本来就大；
* 「急弯走外线」的按半径反推偏移：6–7% 时间出路面，慢 30 s；
* 直道蛇形漂移蓄能：与基线持平（能量本来就不缺）；
* MPC 里直接加「贴近检查点」罚项：把车拽离赛线，出路面 5%、慢 28 s，已关闭（`mpcCpW=0`）。

## 5. 局限与风险

* **没有和真实对手跑过**。以上全是空旷赛道自测（对手停在地图角落）。车车碰撞规避没有做：
  自对弈与套圈测试里碰撞很少且代价小，但对手若恶意别车/急刹，我们只会按自己的线走。
* 出路面约 1% 是「常开漂移 + 高喷火目标速度」换来的主动取舍；发夹弯仍是最脆弱处。
* 检查点通过余量不大（进入圆圈的瞬间往往只剩不到 1 格），靠 §3.4 的两层保护兜底；
  400+ 局自测中已无「漏点丢圈」，但极端情况下仍可能触发回追，损失约 3–6 s。
* 未针对任何具体种子硬编码；所有几何都来自当局观察。
* 若裁判环境无法执行 `node`（例如切到 WSL 隔离且容器内无 node），会技术负；
  本轮任务说明为本机直跑，且 `train.py` 在 no-isolation 下会把 `node` 解析为本机路径。
