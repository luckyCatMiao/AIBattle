# 第3轮提交说明与离线自测

## 状态与证据边界

本文件为第3轮赛前准备记录。尚未取得第3轮正式对局结果，不编造本轮复盘。前两轮文件保留在 `review-r1.md`、`review-r2.md`，上一轮程序备份为 `agent-r2.js`。本轮仅使用本人工作区中的公开规则、模拟器及自写策略，没有读取对方文件、上级 control 数据或对方进程，没有修改受保护的规则文件和引擎。

## 入口

`entry.json`：`{"mode":"program","command":["python","agent.py"]}`。

本机 `command -v python3` 无结果，`python` 可用，因此延续前两轮已运行的本机入口而非写入不可用的 python3。`agent.py` 用绝对路径启动同目录 `agent.js`，继承标准输入输出，实际控制在 Node 中执行。无第三方依赖、无网络、比赛时不写文件。每行输入对应一行 JSON，严格20帧，每帧一辆车。实际 Python 冷启动入口连续三行测试通过，总耗时154.9845毫秒，公开 API 接受所有输入。

## 实际采用的策略

1. 从每局观察读取真实中心线、路面栅格、检查点和宽度，建立累计弧长；通过线段投影求当前位置。没有种子特化，也没有固定赛道。
2. 前视目标方向结合车身朝向和侧滑角生成转向，全油门；使用短脉冲漂移蓄能、松漂转换能量，并请求喷火。转向小于0.16时退出漂移。控制器按照 `catalog.js` 实际参数工作，包括常规最高14、漂移转向倍率1.6，而不是依赖简述中的近似值。
3. 每窗口模拟 **38个参数候选×60帧**，提交最佳候选的前20帧，再从真实观察重新规划。原26个候选保留；新增12个弯内侧候选：前视10/14/18，6帧漂移2/4帧，内侧偏移1/2格。内侧方向根据前方中心线转角确定。
4. 评分包含沿线推进、末速度、路面/路缘代价、越过未通过检查点的惩罚；本轮增加每通过一个有序检查点10分。候选内部更新 `nextCp`，避免只优化无效的几何进度。
5. **冲线优先**：预测通过第三圈0号检查点即终止预测，给予高奖励，并优先选择更早冲线的候选。不再以冲线后的无意义距离抵消冲线收益。若预测提前结束不足20帧，则用合法直行输入补满窗口。
6. 保留上一轮补点：已越过下一检查点、尚未进入判定圆时，切回该检查点。预测通过点使用半径减0.1格的保守判定。
7. 单车前向物理复现公开规则，包含倒计时、油门、转向、侧滑、能量转换、喷火、草地和墙体。仍未预测车车碰撞，不假设知道对方未来输入。

## 实验筛选（不是正式比赛）

所有对手都是本人编写的策略或本人上一轮备份，未读取正式对手代码。种子由 `Math.imul(k+9071,2654435761) >>> 0` 生成，交替座位。

- 尝试“前视连线可能漏点就强制瞄准检查点”：对旧版200局仅10胜，静止实体车100局平均16.034秒；虽然漏点帧减少，但绕行代价过大，**默认不启用**。代码中的 `guard` 仅供实验，正式入口没有启用。
- 保持原路线、无新增奖励的100局镜像基线：50胜；仅加检查点3分：51胜。说明单加小奖励收益不足。
- 增加内侧候选、检查点奖励3分：对旧版200局125胜；静止实体车100局全完赛、平均14.494秒，但出草也增加。
- 在内侧候选上比较检查点权重：同一批150局，10分100胜，0分95胜。选10分后增加终圈冲线优先。
- 冲线优先版本在k=200–399对旧版200局149胜；k=400–499静止实体车100局全完赛、平均14.3955秒。80帧预测在k=200–299仅65胜，未采用，仍使用60帧。

这些实验存在种子复用，是调参结果；下列最终回归使用不重叠的新种子。

## 额外验证

`node r3validate.js`，记录 `r3-validation.jsonl`：

- 实际 Python→Node 入口三行协议测试通过，20帧合法字段；含冷启动154.9845毫秒。
- 60个新随机赛道人为漏点状态，交替座位，把车辆置于指定检查点之后“半径+1.5格”，速度12、朝向顺行、保留尚未通过的 `nextCp`：**60/60恢复并完成三圈**，最长23.6秒。测试限50秒，并非正常发车结果或任意撞后状态保证。
- 10条赛道共2000帧正负油门、变化转向、漂移及喷火输入，验证自写预测与公开物理的位置、速度、朝向和能量，最大误差 **0**；对手放远，未测试车车碰撞预测。
- `node --check agent.js` 通过。
- 最终公开精度对抗200局中单次规划最大43.9729毫秒；不含进程启动、序列化。硬限5秒仍留有明显余量，但这不是跨宿主性能保证。

## 局限

- 对未知正式对手没有胜率保证，尚无第3轮正式结果。上一轮自有程序不代表正式对手强度。
- 一秒窗口内忽略车车碰撞，碰撞后后续输入会偏离预测，只能下窗口修正；未加入专用倒车脱困或对手意图识别。
- 内侧切弯提升速度，同时带来更多草地帧、漏点风险。公开精度静止车100局仍累计543个“越过下一点半径+1格但尚未通过”的诊断帧；这是连续状态计数，不是543次独立漏点。不能声称彻底解决漏点。
- 补点与检查点评分仍是启发式，60帧有限视域不是全局最优。有些被干扰后的回补耗时明显。
- 内侧偏移固定为1/2格，没有做完整赛车线优化；全油门策略没有细致制动点规划。
- 物理一致性只在验证的非车碰撞情形成立；正式观察舍入和对手未知输入仍会造成误差。
- 入口使用本机已安装的Python和Node，不声称无需Node或已验证不可用的python3命令。
