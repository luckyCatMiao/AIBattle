## 二、机制分析（本轮所有改动的依据）

以下结论全部由 `simulation.js` / `catalog.js` 的公式推导并在 `tools/exp_dyn.py`、真实引擎上复现。

1. **“最高速度 23”是软上限，而且只限制前向分量 `vF`。**
   `updateCar` 里超过 cap 时执行的是 `vF = max(cap, vF - 18*dt)`，而喷火时每帧有
   `(boostAccel 30 + accel 17) * dt = 2.35` 的加速。持续喷火时净加速度为正，
   平地实验里 `vF` 会一路涨到约 48 格/秒；实际赛道受弯道限制，本轮实测最高总速度约 30 格/秒。
2. **总速度 = `hypot(vF, vL)`，漂移保留的侧向速度会叠加到总速度上。**
   所以“喷火 + 漂移”可以同时拥有 23+ 的前向速度和可观的侧向速度。
3. **蓄能公式**：漂移时 `driftCharge += (|vL|*0.12 + |vF|*0.02) * 0.55 * dt`，
   松漂时整段 `driftCharge` 一次性转入 `boostEnergy`（上限 1）。
   持续喷火耗能 0.6/s，因此**要维持喷火，平均蓄能速率必须 ≥ 0.6/s**：
   - `vF≈23` 时仅 `vF` 项只有 0.25/s，不够；
   - 需要平均 `|vL| ≈ 5.3`（约 13° 侧滑）才能打平；
   - 实测在高速段脉冲漂移的蓄能速率约 0.8–1.1/s，足以支撑很高占空比的喷火。
4. **漂移不能一直按住**：持续满舵漂移会让车头相对速度方向越转越多，最终失控打转。
   可行做法是**短脉冲**：漂 3–4 帧、松 1–3 帧，松的那一帧完成蓄能转能量并让抓地力把速度方向拉回车头；
   直道上脉冲方向按周期左右交替，抵消净航向偏置。
5. **第 2 轮的做法（漂移与喷火互斥、蓄到 0.20 才点火）恰好消除了持续喷火的可能**，
   这是当时 25–30% 喷火占空比的直接原因。

## 三、本轮实际采用的策略（已固化进 `agent.py` 默认参数）

### 3.1 控制结构

1. **循迹**：中心线弧长投影 + 纯追踪（前视 `2.6 + 0.9*v`，上限 12 格）+ 曲率前馈；
   `line_off=1.6` 朝弯心切内线。
2. **高速喷火速度剖面 `vfast`**：`v = turnRate * r_smooth * 1.1`（上限 30），
   再用 24 格/秒² 的反向传播算出刹车点。喷火只在 `vfast > 21` 的路段点火（直道/缓弯）。
3. **持续喷火**：能量 > 0.02 且未越野且目标速度允许时一直喷；
   **不再有**“蓄到 0.20 才点火 / 能量耗尽才退出”的两阶段状态机。
4. **脉冲短漂**：周期 6 帧、漂 3 帧；方向在过弯时顺着 `steer_track`，直道上按脉冲序号左右交替；
   漂移期间用 `drift_comp=0.6` 补偿 1.6 倍转向率，避免过转。
   仅在平滑半径 > 7 格、`|lat| < 0.95*halfWidth`、速度 > 6、能量未满时启用。
5. **总速度控制**：fast 模式下油门比较的是 `hypot(vF,vL)` 而不是 `vF`，
   避免“前向 23、总速 30”时误判没超速而错过刹车点。
6. **安全兜底（本轮最关键的新增）**：每帧用与引擎完全一致的 `step_car` 做 8 帧预测。
   第一帧用候选输入，其后用“回正 + 收油”的闭环策略推进（纯常量输入会高估高增益转向的后果）。
   若标称动作会出界，按“松漂 → 回正 → 收油+回正 → 刹车+回正 → 全力刹车+回正”依次降级，
   选第一个 8 帧不出界的；都不安全则选出界帧数最少的。
7. **防卡死**：连续 12 帧速度 < 0.35 时进入 12 帧倒车（左右交替打方向）。

### 3.2 关键参数（`agent.py` 的 `DEFAULT_PARAMS`，即提交值）

| 参数 | 值 | 说明 |
| --- | ---: | --- |
| `fast_on` | 1 | 启用本轮高速喷火模式 |

| `boost_gate` | 21 | 局部高速剖面 < 21 不点火（把能量留给直道） |

## 五、本轮试过但没有采用的方向（如实记录）

1. **直接瞄准检查点中心**（`cp_aim_on=1`）：在弯道中会把弦切到路外，
   20 条留出赛道越野帧从 0 涨到 375，平均圈速 5.05 → 5.89，放弃。
2. **检查点横向修正**（`cp_lat_gain>0`）：对个别极限通过（ratio 0.997）略有改善，
   但整体越野帧与圈速变差，默认关闭。
3. **低速“先蓄能再喷火”bootstrap**（能量 < 0.25 时不喷火）：蓄能期车速只有 14，
   蓄能速率反而更低，平均圈速变差 3–5%，放弃。
4. **更激进的剖面**（cap 40 / margin 1.6）：真实引擎上大量越野，最快圈也没有提升，放弃。
5. **更大的脉冲幅值/占空**（amp 0.45–0.6、周期 4/3）：喷火秒数更高，但路径变长 + 安全兜底频繁介入，
   圈速反而变慢，放弃。

## 六、局限与风险（必须如实说明）

1. **第 3 轮尚未开赛**：本文没有任何第 3 轮对局数据；对手策略、实际赛道种子均未知，
   以上全部是离线/自测结果。
2. **对手车没有进入 roll-out 模型**：8 帧安全预测只考虑赛道与自身物理。
   被对手撞击后，本窗口内（最多 1 s）的预测会偏离真实轨迹，下一窗口会从观察重新同步；
   自对弈中碰撞 0–4 次均未导致失控，但真实对手的挤压强度未知。
3. **检查点通过裕度并非绝对安全**：720 次通过全部成功，但个别种子（如 800020）
   最差一次的通过距离达到检查点半径的 0.997。若被撞偏一点导致漏检查点，
   需要多跑一整圈（约 5–8 s）。目前没有实现“漏点后掉头补点”，这是本轮最大的单点风险。
4. **能量-速度正反馈有失败模式**：在又长又窄、连续急弯的赛道上（典型 seed 900005，
   长度 115 格、半宽 3.25），脉冲蓄能效率只有约 0.52/s，喷火占空比掉到 30% 左右，
   圈速 6.1–7.3 s，明显慢于其他赛道（4.3–5.5 s）。本轮没有针对该失败模式做赛道自适应。
5. **调参样本有限**：调参主要用 900001–900020，留出验证用 800001–800020 与 900021–900060。
   真实比赛每局赛道随机，可能与这些分布不同；单一系列样本不能推断综合能力。
6. **物理利用依赖引擎实现细节**：本轮的收益很大一部分来自“软上限 + 漂移保留侧向速度”这一实现特征。
   若正式比赛的引擎/参数与工作区 `simulation.js` 不一致，收益可能显著缩水（但受保护的规则文件
   已做哈希校验，预期一致）。
