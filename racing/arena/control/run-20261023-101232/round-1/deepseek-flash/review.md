## 2. 核心思路

程序每收到一次观察就返回 20 帧输入。做法不是"每秒拍一次脑袋"，而是：

1. **从观察里现算赛道几何**：中心线折线 → 累积弧长、切向、曲率；每局赛道随机生成，全部现算，不硬编码任何赛道。
2. **在该帧精确复刻引擎物理**，用同一套输入做 20 帧闭环 roll-out，逐帧重新决策。
   `step_car()` 与 `simulation.js` 的 `updateCar/moveCar` 逐项对齐（含漂移判定、蓄能转移、喷火耗能、
   速度上限、墙反弹与 8 方向圆-墙检测）。**已验证：同一初态 + 同一输入跑 20 帧，位置/角度/速度/能量
   与引擎的差为 0.0**（含漂移、喷火两种工况）。
   → 这样每秒只在窗口边界同步一次状态，但控制仍是 20 Hz 的。
3. **横纵向解耦控制**：
   - 纵向：沿赛道的限速剖面 `v_lim = clamp(turnRate·r·margin, 4.5, maxSpeed)`，再沿弧长做
     **反向传播**（`v[i] ≤ sqrt(v[i+1]² + 2·a_brake·ds)`，`a_brake=24`）得到"提前刹车"的目标速度；
     油门按 (目标−当前) 三档输出。
   - 横向：纯追踪（前视 `Ld = 2.6 + 0.9·v`，封顶 12 格）+ 曲率前馈
     `steer = κ·|vF| / (turnRate·clamp(|vF|/8,0,1)) · 5.2`。
4. **对手感知**：用相对速度算未来 1.4 s 内的最近接近距离；若 < 1.55 格（即真要撞上）则按
   "最近点时间 < 0.45 s 且擦碰" 轻微减速；不发散硬拐。
5. **容错**：倒计时期间不推进内部模型、不触发防卡死；越野时前视缩到 3 格并以 5.5 格/秒回正；
   低速卡住 0.5 s 后倒车 0.6 s 脱离；观察缺字段/解析失败时复用上一窗口或直行，进程不崩。

## 3. 通过实验确认（而非假设）的机制

赛前用 `simulation.js` 做了定向实验，得到几个与直觉不同的结论：

- **漂移不是"更快的过弯"**：稳态实测，抓地满舵时路径半径 ≈ 2.85 格、速度 ≈ 8.2 格/秒；漂移满舵半径
  2.73 但速度只有 7.0 格/秒。原因是本引擎里侧向速度保留率 0.985/帧 → 车头转得再快，**速度矢量几乎不跟着转**，
  漂移主要是"甩尾 + 蓄能"，不是"更小半径"。
- **漂移蓄能换算很划算**：空地上 14 格/秒用 ±0.2 转向方波漂移 2 s，前进距离几乎不掉（28.07 vs 28.00 格），
  却蓄到 0.43 能量；1.0 能量 ≈ 1.65 s 喷火 ≈ 在同距离上省 1.4 s。**理论上很有价值。**
- **但闭环上不成立**：把方波叠进真实循迹后，外环（纯追踪）把车头的摆动当成误差去修，
  正反馈发散；改成"蛇形参考线"后漂移又跟不上参考路径，直接冲出路面。
  实测各种组合（幅度 0.15–0.5、周期 0.12–0.4 s、蛇形波长 10–36 格）平均圈速从 6.5 s 恶化到 12–24 s。
  **结论：本版本放弃漂移/喷火，选择"全程抓地 + 切弯"的稳妥路线。**

## 4. 自测结果（离线，`simulation.js` 真实物理；均为本机跑分，非正式对局）

对手设定：`opponent=none`（对方车停在发车位不动，等价于"极慢对手"压力测试）、`opponent=self`（双方同一程序）。

| 测试 | 规模 | 结果 |
| --- | --- | --- |
| 圈速（300 个**留出**随机大种子，1…1e9） | 300 局 × 3 圈 | 平均 **6.41 s/圈**，最差 8.40 s，**0 局未完赛**，越野帧合计 3 帧 |
| 圈速（另一批 180 个种子） | 180 局 | 平均 6.50 s/圈，最差 7.90 s，0 局未完赛 |
| 检查点裕度（座席 0，360 种子） | 每局记录 12 个检查点的**全场最近距离/半径** | 最大 **0.75**，P95 0.63，>0.85 的 0 局 |
| 检查点裕度（座席 1，360 种子） | 同上 | 最大 **0.74**，P95 0.64，0 局漏检 |
| 双车同程序对跑（12 个种子） | 双方都在跑 | 两人均 5.85–7.80 s/圈，2 圈内结束（19–24 s），碰撞 0–1 次，越野 0 |
| 单局总时长 | — | 3 圈约 **19–24 s**（150 s 上限，余量很大） |
| 单次响应耗时 | 22 窗口 | 平均 1.7 ms，最大 21 ms（硬上限 5 s） |
| 兜底椭圆赛道（生成器 fallback） | 5 个种子 | 7.8 s/圈，3 圈完赛 |
| 物理复刻一致性 | 4 组工况 × 20 帧 | 与引擎逐项误差 **0.0** |
| 协议健壮性 | 缺 track / 缺 rules / 缺 countdownLeft / yourPlayer=1 / status=finished | 均返回合法 20 帧窗口，stderr 无异常 |

### 自测中真实踩到并修掉的坑

1. **曲率→半径夹取写反**：`r = 1/max(κ, κmin)` 把直道算成 2.35 格半径，整条限速剖面塌成 6.9 格/秒，圈速 17 s。修好后 9.7 s。
2. **参数表被局部变量遮蔽**（`P` 同时是参数表和点列表），每帧抛异常退化成"直行"。已修。
3. **倒计时误触发防卡死**：发车前 1.5 s 车不动，被判"卡住"→ 起步先倒车。改为倒计时窗口不推进模型、不计数。
4. **漏检查点（最严重）**：某一局 3 圈只跑完 1 圈——车在弯心被"让车"横向偏移推到路面外 0.8 格，
   通过检查点时距圆心 4.40 格 > 半径 4.22 格，**漏检后要多跑整整一圈**。
   排查后做了两处修正：让车只减速不横向偏移；前视距离封顶 12 格（14 格时最恶劣裕度 0.98，13 格 0.77，12 格 0.67–0.75）。
5. **前视过长会偶发死循环**：`Ld` 上限 14–15 时个别种子出现半圈打转（16 s 一圈），封顶 12 后消失。

## 5. 调参方式

所有参数用 `tools/tune.js` 在**几十到几百个种子上扫**，按"平均圈速 + 最差圈速 + 越野帧数 + 未完赛数"排序，
再用**没参与过调参的 300 个随机大种子**复测（6.41 s/圈，与调参集一致，说明没有明显过拟合）。
关键参数的取舍：

- `speed_margin`（限速剖面松紧）：2.0 比 1.45 快约 6%，但 2.3 就会频繁跑宽（8.97 s），取 2.0。
- `lookahead_max`：18 → 6.53 s 但检查点裕度 0.98（危险）；12 → 6.68 s 且裕度 0.67–0.75。**为安全性选了 12。**
- `steer_gain`：1.0 时发散（10.3 s、30 帧越野），5.2 稳定；再高（6.5）最差圈变差。

## 6. 局限与风险

- **没有正式对局数据**，以上全部是离线自测；真实对手行为（堵截、别车、卡在路中间）无法预先覆盖。
- **完全不用喷火**：能量只能靠漂移获得，而漂移在本引擎的参数下"省不下时间"，这是主动放弃的上限；
  如果对手把"漂移蓄能 + 直线喷火"做出稳定的闭环，其圈速理论上还有约 10–20% 的空间。
- **对手避让是纯反应式**（预测 1.4 s 内最近距离），没有主动封堵、也没有"被追尾"的防御；
  被撞飞后只靠通用恢复逻辑（回正 + 防卡死倒车）。
- **控制律是"纯追踪 + 剖面"，不是时间最优赛车线**：切弯靠前视带来的弦切，未做真正的走线优化。
- 参数是在公开生成器的赛道分布上调的；若正式服改了 `rules`（物理参数），程序会在每局开场从观察里的
  `rules` 覆盖内部模型常数，但剖面参数（margin 等）没有针对新物理重新标定。
- 单一系列赛只有 6 局，样本很小；上面所有均值都只代表本程序在自测赛道上的表现，不代表对其他模型的优劣。
