## 一、一句话结论

**第 1 轮输在完全不用机制（整届 0 次漂移、0 次喷火）；第 2 轮学会了蓄能和喷火，但把“蓄能”和“用能”做成了互斥阶段；第 3 轮终于做出漂移+喷火重叠，速度明显提升，却仍然把漂移当成“直道补能”，没有把它当成“弯中转向工具”，线路始终没有真正切进弯心。**

第 3 轮 g2 是最有说服力的一局：我方喷火 **8.35 s**、漂移+喷火重叠 **3.75 s**，都高于 Sol 的 **7.65 s / 2.80 s**，移动平均速度也高于 Sol，但因为第 2 圈实际跑了 **96.81 格**，Sol 只跑 **78.06 格**，最终还是落后约 **25 格（0.29 圈）**。**能量已经不是瓶颈，线路才是。**

## 三、我实际采用的策略

### 3.1 控制器骨架

我提交的是程序 agent，不是端到端模型。核心是一个与 `simulation.js` 尽量一致的 20 帧闭环物理模型：

1. **定位**：把车投影到随机赛道的中心线折线上，得到弧长 `s` 和横向偏移 `lat`；
2. **循迹**：纯追踪（pure pursuit），前视距离 `Ld = 2.6 + 0.9·v`，上限 12 格；转向叠加曲率前馈；
3. **限速**：按局部曲率半径给目标速度 `v = 3.2·r·margin`，再用刹车减速度反向传播得到刹车点；
4. **蓄能/喷火**：漂移积累 `driftCharge`，松漂转入 `boostEnergy`，按住 `boost` 消耗能量；
5. **安全兜底**：每帧用候选输入做 8 帧 roll-out，预测会出界时依次降级为“松漂 → 回正 → 收油+回正 → 刹车+回正”；
6. **比赛约束**：优先保证完赛、按顺序过 12 个检查点、不越野；对手避让只减速、不横向让线。

这套骨架的优点是稳定：六局 0 越野、0 漏点。缺点是它把“中心线”当作默认最优线，所有线路优化都只是中心线附近的小偏移；这为后面的线路问题埋了伏笔。

| f287 / 14.35 s | Sol 第 3 圈 3.90 s 冲线；我方落后 **93.2 格（0.91 圈）** | 负 |

**判读**：这一局双方路径差不大（我方第 2 圈 100.25，Sol 96.67，只多 3.58 格），差距完全来自速度：我方平均 16.18、最高 24.60；Sol 平均 22.66、最高 **29.53**。Sol 在 5.85 s 连续喷火中，靠短漂补能，把总速度维持在 26–29；我方 7 次喷火、3.90 s，且喷火期间完全不蓄能，能量耗尽就退出。**这一局之后，“漂移+喷火必须允许重叠”变成了明确结论。**

## 五、我的失误

### 1. 第 1 轮把“稳”误当成策略

第 1 轮我基于离线测试认为“漂移掉速比蓄能收益更贵”，直接关闭漂移和喷火，整届 **0 次漂移、0 次喷火**。结果是最高速度 14.65–14.67，而 Sol 21.43–25.84。**在一个以漂移蓄能和喷火为核心机制的游戏里，主动放弃两个核心机制，等于把比赛让掉。**

### 2. 第 2 轮把“蓄能”和“用能”设计成互斥阶段

`weave_boost_off=1`、弯道漂移要求 `not in_boost`、两阶段状态机蓄到 0.20 才点火——这套设计导致两局 **漂移+喷火重叠 0 帧**，喷火占空只有 25%–30%。第 2 轮 g1 的胜利掩盖了这个问题：那是 Sol 越野送的。**我把“管理能量”理解成了“分阶段使用”，而对手是“边喷边补”。**

### 3. 第 3 轮门槛太硬，把最需要漂移的紧弯排除了

`pulse_r_min=7.0` 只允许在平滑半径 >7 格的直道/缓弯漂移，`boost_gate=21` 又要求高速剖面 >21 才点火。r3-g1 半宽只有 3.571，紧弯半径 4–6 格，正好全部落在门槛之外：弯中速度 15.15–15.38，Sol 21.09–25.54。**这不是执行问题，是参数把正确动作禁止了。**

### 4. 线路只有“偏移量”，没有真正的内线

`line_off=1.6` 只是把追踪目标朝曲率中心偏 1.6 格，高速下没有漂移提供的 1.6 倍转向率，车仍被推向外侧。r3-g2 第 2 圈路径 **96.81**，Sol **78.06**；r3-g1 第 2 圈 **87.44**，Sol **78.80**。**我一直在“中心线附近”开车，Sol 在“赛道内侧”开车；中心线长度不是圈速的下限。**

### 5. 安全兜底降级太硬

回放输入里能看到两次典型的兜底/救车序列：f128–f134（f128 右满舵 +1.0 → f129 左满舵 −1.0 → f131/f133 −1.0 油门 → 回正）和 f216–f222（f216 断喷 → f218 右满舵 → f219 左满舵 → f222 −0.35 油门）；同一版 agent 的调试计数为 5 次。速度从 f129 的 22.0 掉到 f140 的 15.15。8 帧预测 horizon 把“可能出界 1 帧”当成“必须刹车”，**用很大的速度代价换取很小的越界风险**。在 12 s 的短比赛里，这种保守会被持续放大。

### 6. 起步固定慢 0.2–0.3 s

Sol 每局都是 f37 / 1.85 s 首次漂移；除 r1-g2 首次实际喷火在 f58 / 2.90 s 外，其余五局都在 f41 / 2.05 s。我方第 2 轮首次漂移 f45–f46（2.25–2.30 s），首次喷火 f66 / f86（3.30 / 4.30 s），第 3 轮首次漂移 f43（2.15 s），首次喷火 f47（2.35 s）。第 3 轮已经把差距缩到 0.3 s，但仍未追平。短比赛总共 10–20 s，**0.3 s 的起步差就是 3–5 个车身**。

### 7. 优化指标选错了：盯着喷火秒数，而不是圈速和路径

第 3 轮 g2 我方喷火 8.35 s、重叠 3.75 s，都高于 Sol，却输了 25 格。喷火秒数、漂移秒数、点火次数都只是中间量；**真正的目标是“用更短路径、更高弯速完成一圈”**。`boosts` 更是点火次数，不是喷火时间，不能拿来做主要 KPI。

### 8. 离线测试分布偏乐观

赛前离线留出赛道平均飞行圈 5.05 s、60/60 完赛，但实战 r3-g1 只有 4.50 s 的最快圈、r3-g2 3.95 s（赛道更短），且两局都没跑完。离线测试没有覆盖“窄赛道 + 高对手压迫 + 实际路径变长”的组合，**把单车的稳定误判成了对抗中的速度**。

## 六、可改进之处（按优先级）

### P0：把漂移从“直道补能”改成“弯中转向 + 补能”

- 在平滑半径 **4.5–7.5 格**、速度 **12–23 格/s** 时允许 3–5 帧短漂，`drift_comp` 保持 0.5–0.7，松漂即把 charge 转入能量；
- 漂移期间允许喷火，不再要求 `not in_boost`；
- 目标：紧弯速度 ≥20 格/s，r3-g1 弯中不再出现 15 格/s；同时 0 越野。
- 这是第 3 轮 `pulse_r_min=7.0` 的直接修正。

### P0：把“内线”做成显式目标，而不是 1.6 格偏移

- 目标横向位置设为 `sign(κ) · min(halfWidth − 1.0, 0.6·halfWidth)`，在弯前 2–4 格开始偏移，出弯回中心；
- 验收指标：飞行圈路径 ≤ 中心线长度 + 2 格；弯内线占比 ≥65%（当前 r3-g2 第 2 圈几乎整圈在弯外，r3-g1 也只有约一半帧朝弯心）；
- 用路径积分而不是“看起来贴内”来做回归测试。

### P1：喷火门槛自适应，而不是固定 21

- `boost_gate` 按 `halfWidth` 和局部半径自适应，窄赛道降到 17–18；紧弯允许“漂移中喷火”，用 1.6 倍转向率抵消高速转向不足；
- 目标：喷火占空 ≥60%，但**先看圈速和路径，再看占空**；如果提占空导致路径变长，回退。

### P1：安全兜底改成“先松漂/回正，刹车最后”

- 预测出界 1–2 帧时只用“0 油门 + 回正”，不要直接 −0.5/−1.0 刹车；
- 保留漂移和喷火，除非预测到连续 ≥2 帧越野；
- 目标：r3-g1 这类窄赛道不再出现因兜底导致的 <16 格/s 弯速；兜底触发时速度损失 ≤10%。

### P2：起步与能量 bootstrap

- 目标首次漂移 **f37–f40（1.85–2.00 s）**、首次喷火 **f41–f43（2.05–2.15 s）**；
- 起步后先用 2–3 帧短漂把能量从 0 拉到 0.05–0.08，立即点火，不再等 0.20；
- 预计每局可追回 0.2–0.3 s。

### P2：领先/落后时的比赛管理

r2-g1 我方在 f160 领先 **59.22 格**，最后只赢 **5.2 格**——领先时我仍按保守配速跑，Sol 则持续推进。下一版需要根据对手进度切换模式：领先 >20 格时保稳，落后或领先 <10 格时提高攻击性。**不能让对手在最后 12 s 追回 54 格。**

### P2：验证集必须覆盖“窄 + 弯多 + 有对手”

- 至少 30 条留出种子，按半宽分桶（<3.4 / 3.4–3.8 / >3.8），每桶 ≥8 条；
- 用回放对手作为 ghost，测试实际路径和超车压力；
- 验收：100% 完赛、0 越野、0 漏检查点；飞行圈路径 ≤ 中心线 + 2 格；最快圈与 Sol 同场差距 ≤0.2 s；任何一项导致越野 >2 帧/场，回退。

## 七、对赛车机制的理解变化

| 机制 | 赛前 / 早期的理解 | 现在（六局之后）的理解 | 本系列证据 |
| --- | --- | --- | --- |
| **随机赛道** | 种子只是换一条形状，中心线就是最快线；调好一套参数就能通用 | 中心线只是参考线，不是赛车线；**内侧线可以比中心线更短**；半宽和弯半径分布决定策略，硬编码半径门槛会过拟合；不同种子长度 87.5–106.3，绝对圈速不可直接跨轮比较 | Sol 在 r3-g2 第 2 圈只跑 **78.06 格**，赛道中心线长 **87.53 格**；我方同圈 **96.81 格** |
| **漂移蓄能** | 漂移会掉抓地、掉速度，是“用速度换能量”，不划算；能少漂就少漂 | 漂移同时是**转向倍率**和**能量转换器**：`gripDrift=0.985` 保留侧向速度，转向 ×1.6；3 帧（0.15 s）漂移约产生 **0.0825** 能量，按 0.6/s 耗能可换约 **0.14 s** 喷火；短漂应发生在弯里，不是直道 | 第 1 轮 0 漂移 → 圈速 6.9/6.2；第 3 轮短漂 + 喷火 → 4.5/3.95；但 r3-g2 重叠 3.75 s 仍因路径多跑 18.75 格而输 |
| **喷火** | 喷火是有限资源，最高速度 23；只在直道用，攒够再喷 | 23 只是**前向分量**上限，侧向速度叠加后总速度可到 **29.53**；+30 加速度让出弯极强；1.0 能量≈1.67 s；可以“边漂边喷”持续补能；碎片化点火（平均 0.17 s/段）会让能量长期接近 0，反而没有有效喷火 | Sol r2-g2 f149–f265 连续喷火 **5.85 s**，最高总速度 **29.53**；我方 r3-g1 29 段平均 **0.17 s**，能量均值 **0.047** |
| **碰撞** | 碰撞会失控、掉速，应该尽量让线甚至刹车避开 | 车车碰撞是弹性碰撞（恢复系数 0.55），**没有想象中致命**；真正贵的是越野和撞墙。一次低速接触后双方都能继续，不应为此放弃线路或重刹；但也不能主动撞，接触会损失一点速度并改变出弯节奏 | r2-g1 f61 中心距 1.10 格、相对速度 3.23，双方各记 1 次碰撞，均未失控；同局 Sol 的 48 帧越野才是决定胜负的事故 |
| **越野 / 墙** | 只要不撞墙就行，压一点路肩没关系 | 越野限速 **7**、加速度只有 35%、额外阻力，2.35 s 越野就足以把一场胜利送掉；**“留在路上”优先级高于任何线路收益** | Sol r2-g1 f94–f140 越野 47 帧，速度 3.1–4.4，首圈从可能 4.8 s 变成 9.45 s；我方六局 0 越野 |
| **检查点** | 只要沿中心线走就不会漏 | 12 个顺序检查点 + 半径判定；随机赛道可能很窄，切内线过头或越野都可能漏点；可靠性比单圈速度更基础 | 六局双方均无漏点；我方 0 次技术错误 |

### 7.1 随机赛道：从“一条赛道”变成“一个分布”

第 1 轮我还会拿不同轮次的绝对圈速直接比较，这是错的：第 2 轮赛道 102–106 格，第 3 轮只有 87.5 格。更合理的比较是：
- 同场同圈的直接对比；
- 路径/中心线长度的比值；
- 弯中速度与局部半径的关系；
- 半宽分桶后的表现。

随机赛道真正教会我的是：**参数不能只对一条赛道调**。`pulse_r_min=7.0` 在宽赛道可能没问题，在 r3-g1 这种半宽 3.571 的窄赛道就是把紧弯全部排除。下一版必须让半径门槛、喷火门槛跟着 `halfWidth` 和局部曲率走。

### 7.2 漂移蓄能：从“掉速手段”变成“弯中武器”

第 1 轮我把漂移看成纯损失；第 2 轮把它看成“直道蓄能”；第 3 轮才部分理解它是“弯中转向 + 蓄能”。回放里 Sol 的漂移段大量是 **3–4 帧（0.15–0.20 s）**，不是长漂：松漂就把 charge 转入能量，然后立刻喷火。这样既用 1.6 倍转向率过弯，又不断补能。我的第 3 轮脉冲漂移也是 3 帧，但只敢在半径 >7 的直道用，等于只学了“补能”，没学“转向”。

### 7.3 喷火：从“有限爆发”变成“可持续的高速状态”

早期我以为喷火是“攒满—直道—放掉”的爆发。实际是：只要能在喷火期间用短漂补能，喷火可以维持很久；而且 `boostMaxSpeed=23` 只限制前向分量，漂移保留的侧向速度会让总速度超过 23。第 3 轮 g2 的 2.20 s + 2.15 s 两段连续喷火证明这套节奏可行；但同一局也证明，**喷火多不等于圈速快**——路径多 18.75 格会把速度优势全部吃掉。

### 7.4 碰撞：从“必须躲”变成“可以接受，但不能主动换线”

整个系列只有 r2-g1 f61 一次碰撞，样本很小，不能下强结论。但至少这一次：两车中心距 1.10 格（正好是车身半径和），相对速度 3.23 格/s，双方都没有失控、没有越野，比赛继续。相比之下，Sol 的 48 帧越野损失了约 2.35 s 和大量速度。**如果重来，我不会为了躲一次低速接触而重刹或让出内线；我会把“不越野、不撞墙”放在“不接触”之前。**

## 八、结论

1. **第 1 轮的问题是“不用机制”**：0 漂移、0 喷火，纯追踪被 14 格/s 封顶；线路不差，速度差 15%–38%。
2. **第 2 轮的问题是“机制互斥”**：学会喷火，但蓄能和用能分开，重叠 0 帧；唯一一胜来自对手越野。
3. **第 3 轮的问题是“机制用了，线路没跟上”**：g2 喷火、漂移、重叠都超过 Sol，平均速度也更高，却因为每圈多跑 15–19 格而输；g1 则是窄赛道门槛 + 安全兜底把弯速压到 15 格/s。
4. **下一版的第一优先级不是提高喷火占空，而是“弯中漂移 + 显式内线 + 路径约束”。** 如果只能改一件事：把 `pulse_r_min` 从 7.0 降到 4.5–5.0，允许在紧弯漂移，并把目标横向位置真正指到弯心；然后用“路径 ≤ 中心线 + 2 格、0 越野”做验收。
5. **可靠性仍然是我的优势**：六局 0 越野、0 漏点、0 技术错误，唯一一次碰撞也未失控。这个底子不能丢；改进必须在不破坏可靠性的前提下做。

### 局限

- 样本只有 6 局、1 个对手；对 Sol 的策略描述来自回放输入/状态，不是其源码。
- 未冲线局的终局差是按对手冲线帧的中心线展开弧长差计算的，和“剩余距离”口径可能相差几格；跨轮绝对圈速受赛道长度影响，只作趋势参考。
- 路径积分包含横向摆动，能反映“实际跑了多远”，但不能单独区分“线路长”和“漂移摆动多”；下一版需要同时记录弯内线占比和横向偏移。
- 本文所有“下一轮改动”都尚未写入 `agent.py`，也未做真实引擎验证；当前 `agent.py` 仍是第 3 轮提交版本（SHA-256 `5b556f8f…0a1e85`）。
