# 「俯视角赛车」第 2 轮准备复盘（deepseek-flash）

> **状态说明（必读）**：本文写于第 2 轮**提交之前**。第 2 轮正式对局尚未开始，因此本文**不含任何第 2 轮对局结果**，也没有编造复盘。下面所有数字都来自离线模拟器（`simulation.js` + 自建 Python 复刻）和自建测试台，属于"赛前自测"，不是比赛成绩。第 1 轮的赛后复盘已备份到 `tools/review_r1_backup.md`，本文只保留其结论要点作为对照。

## 一、第 1 轮结论回顾（本轮的出发点）

第 1 轮两局都以对手冲线结束，我方每圈慢 **0.75–1.65 s**。复盘的关键结论：

1. **差距几乎全部来自"喷火"**：对手在每局 16–18 s 里喷火 **5.05 / 6.75 s**，均速 16.46 / 19.76 格·s⁻¹；我方全程 0 漂移、0 喷火，均速固定 14.29。
2. **漂移要当"能量采集器"用，不是过弯方式**：对手是每圈 1.5–2.1 s 的**短漂脉冲**，蓄能后出弯/直道喷火；第 1 轮赛前测的是"持续漂移过弯"，结论不适用于这种用法。
3. 我方代码里 `drift_on=0`、`weave_amp=0`，且旧的弯道漂移触发条件（`v_t < 11`）在限速剖面下恒假，是**死代码**。
4. 可靠性不是问题：0 错误、0 越野、检查点全过、0 碰撞。

本轮的目标因此非常明确：**在保持"0 漏检、0 未完赛、尽量 0 越野"的前提下，把漂移蓄能 → 喷火这条链路真正跑起来。**

## 二、本轮实际采用的策略

### 2.1 总体结构（提交版 `agent.py`）

程序仍然是常驻进程：stdin 每行一个观察，stdout 每行一个 20 帧窗口并立即 flush；单窗口实测 0.4 ms（上限 5 s）。

内部保留第 1 轮已验证正确的骨架：

- **赛道现算**：从观察 `track.points` 重建累积弧长、切向、曲率、限速剖面；不硬编码任何赛道，换种子的赛道会自动重建。
- **物理复刻**：`step_car()` 与 `simulation.js` 的 `updateCar/moveCar` 逐项对齐（漂移判定、蓄能转移、喷火耗能、限速、墙反弹、8 方向圆-墙检测）。本轮用固定输入序列与真实 `simulation.js` 逐窗口比对，240 帧后最大偏差 **0.0013 格**（源于 JS/Python `hypot` 末位差异），可视为一致。
- **横向**：纯追踪 + 曲率前馈；**纵向**：曲率限速 + 反向刹车传播。
- **对手感知**：预测未来 1.4 s 最近距离，只在可能擦碰时轻微减速，不做横向让线（第 1 轮教训：让线容易被挤到路外漏检查点）。
- **容错**：倒计时窗口不推进内部模型；越野降速回正；卡死倒车；非法/缺字段观察复用上一窗口或直行，进程不崩。

### 2.2 本轮新增/重写的四个机制

**(1) 直道受控摆尾短漂蓄能（`weave`）**

在循迹转向之上叠加一个低幅周期摆动，让 `|steer|` 周期性越过 0.15 的漂移阈值，从而形成"短漂—松开—蓄能"的循环：

- 波形用 `sign(sin)·|sin|^0.45`（`weave_shape=2`），比纯正弦更长时间远离零，提高漂移占空比；
- 幅值 0.55、周期 1.10 s；
- 只在**平滑半径 > 8.5 格**的小曲率段、基础循迹转向 < 0.5、横向偏移 < 1.7 格、车速 9.5–19 时启用；
- 叠加一个横向居中项 `-0.12·lat`，防止摆尾把车带向路沿；
- 旧版"方波蛇形"（`farm_on`）保留但默认关闭。

**(2) 弯道短漂（`corner_drift`）**

用**平滑曲率半径**触发（旧版用限速触发，恒假）：半径 < 7.5 格、车速 8–15、非喷火阶段、单次最多 8 帧。它的作用是"在本来就要转弯的地方顺便蓄能"，弯道里侧滑角天然更大。

**(3) 喷火两阶段状态机（`boost_sm`）**

第 1 轮式的"能量一到 0.05 就点火"会产生大量 0.1–0.2 s 的碎片喷火，车还没到 23 就没能量了。本轮改为：

- 蓄能阶段：不喷火，摆尾攒能量到 **0.20**；
- 点火条件：当前喷火限速 > 14，且**前方 2/5/8/11 格的喷火限速都 > 16**（即前方是能持续加速的路段）；
- 喷火阶段：一直烧到能量 ≤ 0.02 或前方限速掉到 14 以下；
- 喷火期间的**目标车速用独立的喷火限速剖面** `v_boost = turnRate · r_smooth · 1.0`，再做刹车反向传播（减速度 22），避免"喷进必须刹车的弯"；一旦需要减速就退出喷火阶段。

**(4) 走内线（`line_off`）**

把前视目标朝曲率中心偏移（最大 1.6 格，按曲率饱和，并用 `halfWidth-1.5` 和当前横向偏移做双重收窄），切弯心缩短实际路径。实测路径从 268 格/3 圈降到 278 格左右的同时圈速更快（内线带来的路径缩短抵消了摆尾造成的路径增加）。

## 四、局限与风险（如实记录）

1. **没有第 2 轮对局数据**。本文所有性能数字都是离线自测；对手第 2 轮会怎么跑、会不会针对我方，完全未知。不能把"留出种子 5.4 s/圈"直接换算成对 sol 的胜负。
2. **对手模型缺失**。自测是对固定赛道、无敌车/同程序车；真实对局中的碰撞、被挤压、对手走线差异没有覆盖。当前避让策略只减速不让线，遇到故意挤压可能仍会吃亏。
3. **高速漂移被保守地关掉**。第 1 轮对手可能用"漂移+喷火重叠"把合速度抬到 23 以上；本轮尝试过重叠（4 组参数），都因为高速侧滑甩出赛道而放弃。这是当前与对手最快圈（如 5012 的 4.85 s）仍有差距的主要原因之一；这是**有意的安全取舍**，不是不知道。
4. **弯道半径估计是平滑近似**。`kappa_sm` 用 13 点滑动平均，个别赛道的最紧弯仍可能被低估；越野帧集中在"出弯靠边 + 下一段是直道"的场景，代价通常是 0.1–0.3 s，而非漏检。
5. **参数是经验调出来的**。调参用了 10 条赛道，验证用了两组各 60 条、双座位；虽然验证集未参与调参，仍存在一定过拟合风险，尤其是摆尾幅值/周期这类对相位敏感的参数。另外，这套控制器对前视长度很敏感：任何"靠边时缩短前视"的改动都会引入振荡（实测把越野帧从 45 提高到 300–900），因此最终版本没有加这类保护。
6. **检查点保护未启用**。第 1 轮的 `cp_guard` 因不稳定默认关闭；本轮靠"限制横移 + 平滑曲率 + 低速弯道漂移"把漏检率压到 240 场 0 次，但没有数学保证。
7. **首圈天然更慢**。从静止起步 + 发车位在起跑线前 4–8 格，首圈比飞行圈慢约 0.7–0.9 s；这部分无法通过策略消除。
8. **单帧响应虽快，但整场进程依赖 Python 环境**。已确认只 import 标准库、不读工作区外文件、不联网；若执行环境缺少 Python 3 会直接技术负（与本轮改动无关，`entry.json` 用 `python3` 由 runner 映射）。

## 六、一句话总结

第 2 轮的提交把第 1 轮"只跑干净、不用能量"的策略换成了**"直道摆尾短漂蓄能 + 两阶段喷火 + 走内线"**，离线 240 场留出验证全部完赛、0 漏检，平均飞行圈从 6.25 s 降到 **5.4–5.6 s**（约 11%）；同时明确保留了高速漂移、检查点保护等未解决/主动放弃的风险点。正式对局结果待赛后另行记录，本文不做预测。
