# 「俯视角赛车」第 1 轮赛后复盘（deepseek-flash）

**一句话结论**：本轮两局都由 sol 冲线获胜。我方（deepseek-flash）没有技术故障、没有碰撞、没有越野、检查点全部通过，但每圈慢 **0.75–1.65 s**。差距不在可靠性，而在速度：sol 用“短漂蓄能 + 全程按住喷火”把 **5.0–6.75 s** 的喷火时间塞进 16–17 s 的比赛里，我方整场 **0 次漂移、0 次喷火**。

## 一、比赛与数据口径

- 复盘对象：`run-20261023-101232` 第 1 轮两局，对局 ID 为 **r1-g1**、**r1-g2**。
- 数据来源：用户提供的公开战报；以及同一运行目录下的回放 **`r1-g1.json.gz`**、**`r1-g2.json.gz`**（逐物理帧存档，含双方输入窗口）。本复盘没有读取 sol 的工作区或源码；对 sol 策略的描述均是对公开回放中输入/状态的观察，不是对其内部实现的推断。
- 座位对应：两局交换座位，战报里的 `laps`、`finishTimes`、`bestLaps`、`boosts`、`driftTimes`、`collisions` 等数组**按 seats 顺序**对应，不能沿用上一局的“我方在前/在后”。
  - r1-g1：`seats=[deepseek-flash, sol]`，第 0 项是我方，第 1 项是 sol。
  - r1-g2：`seats=[sol, deepseek-flash]`，第 0 项是 sol，第 1 项是我方。
- `duration=0.35` 不是比赛时长。按 20 Hz、363/357 帧计算，模拟时长约 **18.15 / 17.85 s**，与 `finishTime=18.1 / 17.8` 一致；战报未说明 `duration` 的定义，本文不使用它做性能比较。
- `finishTime` 是**含 1.5 s 倒计时**的绝对时间；回放 `lap` 事件的圈速从发车（GO）起算，首圈包含起步。
- `bestLaps` 有舍入（例如 r1-g1 的 sol 显示 5.2，回放圈速为 5.25/5.20，最佳实际是第 3 圈 5.20）。本文圈速优先取回放 `lap` 事件的 `time`，必要时保留到 0.05 s。
- `boosts` 是**点火次数**：引擎在 `boosting` 由 false→true 时加 1。sol 在两局所有记录窗口的每一帧都把 `boost` 设为 true，能量一恢复到 0.02 以上就会重新点火，所以会出现“38 次喷火、但实际喷火 6.75 s”的现象。
- `driftTimes` 是实际 `drifting` 帧数 ÷ 20；回放补充统计的 boosting 帧数 ÷ 20 分别为 **5.05 s（g1）**、**6.75 s（g2）**。
- 差距（gap）用回放位置投影到中心线、展开弧长后计算；`progress` 字段在过圈边界会出现跳变（例如 r1-g1 第 169 帧附近），未直接使用。
- 终局差距是**外推值**：用 sol 冲线时我方剩余弧长 ÷ 最近 2 s 平均速度；同时给出“按上一圈圈速再跑一圈”的估计范围。我方两局都没有真正冲线，因此不能把外推值当成官方完赛时间。
- 两局 `errors` 均为 0，`technicalFailure` 均为 `null`，赛道审计 `valid=true`、`startOnRoad=true`、`gridOnRoad=true`。

## 四、原因分析

1. **首要原因：我方没有喷火，sol 有 5.0–6.75 s 的喷火。**
   - sol 两局的蓄能总量分别为 **2.941 / 3.994**，按 `boostDrain=0.6/s` 对应 **4.9 / 6.66 s** 喷火；实际 boosting 帧为 **5.05 / 6.75 s**，能量收支完全对得上，没有第二个能量来源。
   - 喷火把纵向速度上限从 14 提到 23。sol 第 2 圈均速 16.46 / 19.76，正是“常规弯速 + 直道喷火”的组合；我方全程 14.29。
   - 两局第 2 圈的圈速差 0.95 s / 1.65 s，与喷火秒数 5.05 / 6.75 s 同向变化；g2 喷火更多，差距也更大。

2. **漂移的作用被我们赛前误判了：它是“蓄能手段”，不是“更小半径的过弯方式”。**
   - 赛前离线实验测到：抓地满舵半径约 2.85 格、速度约 8.2；漂移满舵半径 2.73 格、速度只有 7.0。于是我们得出“漂移不划算”的结论，并把 `drift_on`、`weave_amp` 都设为 0。
   - 但 sol 的用法是**短漂**：每圈只漂 1.5–2.1 s，分成很多 0.25–0.55 s 的脉冲，目的是在弯中蓄能，然后在出弯/直道喷火。它并不指望漂移本身降低半径。赛前实验测的是“持续漂移过弯”，与这种用法不是同一个问题。
   - 从结果看，sol 的“短漂 + 全程按住喷火”是正收益：g1 每圈比我们快 0.75–0.95 s，g2 快 1.3–1.65 s。

3. **我方代码路径决定了 0/0，而不是“临场判断不用”。**
   - `agent.py` 的 `DEFAULT_PARAMS` 里 `drift_on=0.0`、`weave_amp=0.0`，所以 `corner_drift` 和 `farm` 都不会触发；没有漂移就没有 `driftCharge`，`boostEnergy` 始终为 0，`boosting` 条件（能量 >0.05）永远不成立。这与回放里 0 漂移、0 喷火、0 蓄能完全一致。
   - 还有一个隐藏问题：即使把 `drift_on` 改成 1，`corner_drift` 仍要求 `v_t < drift_vmax=11.0`；而 `speed_margin=2.0` 把 `v_lim` 抬到 14，回放中我方飞行圈速度也从未低于 14.00，说明 `v_t` 实际没有低于 14，所以这个条件在本轮两条赛道上**根本不会成立**。下一轮不能只改一个开关，必须改触发条件。
   - 同理，`farm` 需要 `weave_amp>0`，而赛前的蛇形漂移实验在外环纯追踪下发散了，所以这条路也被关掉。

4. **走线不是主要差距。**
   - g1 第 2 圈：sol 路径约 86.4 格，我方约 88.6 格，sol 只短 2.5%；均速却高 15.2%。
   - g2 第 2 圈：sol 路径约 95.8 格，我方约 92.9 格，sol 反而长 3%；均速高 38.3%。
   - 两局的横向偏移统计也说明我们没有“不会走线”：我方 P95 为 1.82/2.01 格（半宽 3.598/3.259），没有越野；sol 的 P95 为 2.24/2.19 格，只是略宽。把差距归因于“线不够好”会掩盖真正的问题。

5. **可靠性、检查点、碰撞都不是原因。**
   - 两局 `errors=0`、`technicalFailure=null`、`collisions=[0,0]`、越野帧 0；检查点每圈 12/12 全部按顺序通过，没有漏检、没有回退、没有卡死。
   - 我方 19 个（g1）/ 18 个（g2）决策窗口全部正常返回，没有触发 5 s 响应上限；引擎日志为空，没有 stderr 异常。
   - 因此这场失利不需要从“防崩、防漏检、防撞”方向找原因，应该直接改速度能力。

6. **发车位与座位不是决定因素。**
   - g1 我方 p0 发车位比 sol 近约 4 格（约 0.3 s），仍然以 0.75–0.95 s/圈的速度差落败；g2 sol 拿到 p0，差距更大。
   - 两局都交换了座位，结果一致；把两局都归因于“座位不好”与数据不符。

7. **可解释的赛道效应（假设，未证实）。**
   - g2 更窄（3.259 vs 3.598）、更长（104.707 vs 97.333），生成器到第 39 次尝试才通过自检，弯道更紧。我方圈速变慢 4.8% 是合理的；sol 反而更快 7.6%，说明其“短漂蓄能 + 喷火”在窄弯上的相对收益可能更高。
   - 但两局赛道不同、座位也不同，无法把“赛道效应”和“sol 的策略适应”分开；这只能作为下一轮调参的假设。

## 五、我的改动

> 说明：两局之间没有改代码；两局使用的是同一份冻结的 `agent.py`（工作区文件与 `round-1/deepseek-flash/agent.py` 逐字节一致）。下面分“本轮赛前已采用”和“赛后拟议、尚未实施”两部分，避免把计划写成已完成的改动。

### 5.1 本轮赛前已采用（提交版）

**提交物**

| 文件 | 内容 |
| --- | --- |
| `agent.py` | Python 3 参赛程序；stdin 逐行读观察，stdout 每窗口输出 20 帧并立即 flush |
| `entry.json` | `{"mode":"program","command":["python","agent.py"]}` |
| `python3.bat` | 兜底垫片：若运行方按 `python3` 调用，也能解析到同一个程序 |
| `tools/` | `race.js`（整局回归）、`tune.js`（多参数多种子扫描）、`cpstat.js`（检查点裕度统计） |

**核心实现**

- **赛道现算**：从观察的 `points` 重建中心线，计算累积弧长、切向、曲率、限速剖面；不硬编码任何赛道。
- **物理复刻**：`step_car()` 与 `simulation.js` 的 `updateCar/moveCar` 逐项对齐（漂移判定、蓄能转移、喷火耗能、速度上限、墙反弹、8 方向圆-墙检测）。赛前验证：同一初态 + 同一输入跑 20 帧，位置/角度/速度/能量与引擎误差 **0.0**（含漂移、喷火工况）。
- **纵横向控制**：
  - 纵向：`v_lim = clamp(turnRate·r·2.0, 4.5, maxSpeed)`，再按 `v[i] ≤ sqrt(v[i+1]² + 2·24·ds)` 反向传播做提前刹车；油门按目标速度三档输出。
  - 横向：纯追踪，`Ld = 2.6 + 0.9·v`，上限 12 格；曲率前馈 `steer = κ·|vF| / (turnRate·clamp(|vF|/8,0,1)) · 5.2`。
- **对手感知**：预测未来 1.4 s 最近接近距离；只有 miss <1.55 格才轻微减速；`avoid_lat=0`，不做横向让线（避免被挤到路外漏检查点）。
- **容错**：倒计时期间不推进内部模型；越野时前视缩到 3 格、目标速度 5.5；低速卡住 0.5 s 后倒车 0.6 s；观察缺字段/解析失败时复用上一窗口或直行，进程不崩。
- **默认关闭漂移/喷火**：`drift_on=0.0`、`weave_amp=0.0`；`boost_energy_min=0.05`、`boost_vmin=16.0`。这是本轮的主动取舍，也是两局 0 漂移/0 喷火的直接原因。

**关键参数**

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `lookahead_base` / `gain` / `max` | 2.6 / 0.9 / 12.0 | 12 是防漏检查点的安全上限 |
| `steer_gain` | 5.2 | 纯追踪转向增益 |
| `speed_margin` | 2.0 | `v_lim = 3.2·r·2.0`，本赛道上普遍高于常规极速 |
| `brake_ahead` | 24.0 | 反向传播的保守刹车减速度 |
| `offroad_speed` / `offroad_ld` | 5.5 / 3.0 | 越野恢复 |
| `drift_on` / `drift_vmax` | 0.0 / 11.0 | 漂移关闭；`drift_vmax` 条件在 v_lim≈14 时也不会触发 |
| `weave_amp` / `weave_T` | 0.0 / 0.15 | 直道蛇形蓄能关闭 |
| `boost_energy_min` / `boost_vmin` | 0.05 / 16.0 | 喷火阈值（因无能量而不会触发） |
| `avoid_ttc` / `avoid_miss` / `avoid_brake_t` | 1.4 / 1.55 / 0.45 | 对手避让 |
| `avoid_lat` / `avoid_cp_block` | 0.0 / 8.0 | 只减速不让线，临近检查点不横移 |
| `cp_guard` | 0.0 | 检查点保护关闭（实测引入不稳定） |

**赛前离线自测（非正式对局，仅作基线）**

| 测试 | 结果 |
| --- | --- |
| 300 个留出随机种子，3 圈 | 平均 **6.41 s/圈**，最差 8.40 s，0 局未完赛，越野合计 3 帧 |
| 另 180 个种子 | 平均 6.50 s/圈，最差 7.90 s，0 局未完赛 |
| 检查点裕度（360 种子，座席 0/1） | 最大 0.75 / 0.74，P95 0.63 / 0.64，0 局漏检 |
| 双车同程序（12 种子） | 5.85–7.80 s/圈，19–24 s 结束，碰撞 0–1，越野 0 |
| 单次响应 | 平均 1.7 ms，最大 21 ms（硬上限 5 s） |
| 物理复刻一致性 | 4 组工况 × 20 帧，逐项误差 0.0 |

**赛前踩到并修掉的坑（都属于本版改动）**

1. **曲率→半径夹取写反**：`r = 1/max(κ,κmin)` 把直道算成 2.35 格半径，限速剖面塌到 6.9 格/秒，圈速 17 s；修正后 9.7 s。
2. **参数表被局部变量遮蔽**：`P` 同时是参数表和点列表，每帧抛异常退化成直行；已修。
3. **倒计时误触发防卡死**：发车前 1.5 s 车不动，被判卡住并先倒车；改为倒计时窗口不推进模型、不计数。
4. **漏检查点（最严重）**：让车横向偏移把车推到路外 0.8 格，通过检查点时距圆心 4.40 > 半径 4.22，漏检后要多跑一圈；修正为 `avoid_lat=0`（只减速不让线）+ 前视上限 12 格。
5. **前视过长偶发半圈打转**：`Ld` 上限 14–15 时个别种子出现 16 s 一圈；封顶 12 后消失。

**本轮正式对局对这些改动的验证**

- 两局 0 错误、0 技术故障、0 碰撞、0 越野、检查点全过，说明“稳定、不漏检、不撞”的目标达成。
- 圈速 6.2/6.5 与赛前 300 种子均值 6.41 同量级，说明控制与物理复刻没有在正式环境失真。
- 但“放弃漂移/喷火”的赛前结论被 sol 的表现直接否定：这不是实现 bug，而是策略取舍错误。

### 5.2 依据本轮结果拟定的后续修改（尚未实施、尚未验证）

以下改动**还没有写进 `agent.py`，也没有跑过离线/正式验证**，只是下一轮的候选方案；在验证前不应把它们写成已生效。

1. **修掉“漂移触发条件永远不成立”的死代码（P0）。**
   - 现状：`corner_drift` 要求 `v_t < drift_vmax=11.0`，但 `v_lim = clamp(3.2·r·2.0, 4.5, 14)` 在本轮赛道上普遍是 14，条件恒假。
   - 改法：用曲率/转角触发，例如 `tr.kappa_s[idx] > 1/4.2` 或 `abs(alpha) > 0.10`，同时满足 `speed>4.5`、`|lat| < halfWidth-1.2`、`not off`；不要再用限速阈值作为漂移开关。
2. **加入“短漂脉冲”管理器（P0）。**
   - 只在弯道入口开始漂移，目标持续 **0.25–0.55 s**；出弯或 `|alpha|` 开始下降时松开，把 `driftCharge` 转入 `boostEnergy`。
   - 中止条件：`|lat| > halfWidth-1.0`、航向误差 >0.35 rad、速度 <10、或单次漂移 >0.6 s。宁可少蓄能，也不能冲出路面或漏检查点。
   - 不恢复赛前的“直道蛇形”方案；赛前实测它会被纯追踪外环当成误差放大，导致发散。
3. **漂移时改用速度方向控制（P0）。**
   - 现状的 `alpha` 是“目标点方向 − 车身朝向”；漂移时速度矢量滞后于车头，继续用车身朝向会把侧滑当成转向误差，越修越大。
   - 改法：漂移期间把误差混合为 `angle_diff(desired, atan2(vy,vx))`（速度方向）与车身误差的加权，降低 `steer_gain`，并加一个小的横摆阻尼项；这是赛前闭环漂移发散的根因，需要优先解决。
4. **喷火策略对齐“能量一到就点火”（P0）。**
   - 回放显示 sol 的 `boost` 输入恒为 true，能量一恢复就重新点火；这比我方“等一个大直道再喷”更简单，也更充分利用能量。
   - 改法：`boosting = boostEnergy > 0.05 and v_hi > 16 and not off and vF > 3`（现有条件），但把 `boost` 输入保持为 true；有能量时用 `vlim_hi` 作为目标速度与刹车剖面，能量耗尽时回落到 `vlim` 的保守分支，避免喷火时冲过弯心。
5. **重新标定喷火工况下的速度剖面（P1）。**
   - 喷火时 `boostMaxSpeed=23`，刹车距离变长；`speed_margin=2.0`、`brake_ahead=24` 是为 14 格/秒标定的，未必适合 18–23 格/秒。
   - 在 `vlim_hi` 上重跑 `speed_margin`（候选 1.6–2.0）与 `brake_ahead`（候选 20–24），用“平均圈速 + 最差圈速 + 越野帧 + 漏检数”排序。
6. **验证协议（P0，先于正式比赛）。**
   - 赛道：本轮真实种子 **5011、5012** 必测；另取 ≥200 个未参与调参的留出种子。
   - 座位：0/1 都测；对手：`none`（压力测试）与 `self`（同程序对跑）。
   - 指标：平均/最差圈速、越野帧、漏检数、碰撞数、未完赛数、单窗口响应时间。
   - 验收线：**0 未完赛、0 漏检、0 越野**；碰撞不高于当前版本；g1 类赛道飞行圈目标 ≤5.4 s，g2 类 ≤5.0 s（对标本轮 sol 的 5.25/4.85）。达不到就回退，不拿正式局做实验。
7. **回退方案（P1）。**
   - 如果“短漂 + 喷火”在 200 种子上仍不稳，先退到“只在最长直道前蓄一次能、直道喷完”的最小版本；若仍不稳，保留当前 0 漂移/0 喷火版本，接受约 0.8–1.65 s/圈的差距，优先保证完赛与不漏检。
8. **检查点裕度复测（P1）。**
   - 喷火后速度更高，过弯更宽；赛前 12 格前视上限是按 14 格/秒调的，需要重新统计“最近检查点距离/半径”，避免为了快 0.2 s 丢一整圈。

## 六、结论与下一轮重点

1. **本轮结果是“跑得干净但不够快”**：0 错误、0 碰撞、0 越野、检查点全过，可靠性目标全部达成；两局分别慢 0.75/0.95 s（g1 前两圈）和 1.3/1.65 s（g2 前两圈），终局外推 2.7–2.9 s / 4.0–4.3 s。
2. **差距主要来自速度，而喷火是最主要的速度来源**：sol 用 5.05/6.75 s 的喷火把均速从 14.29 提到 16.46/19.76；走线只贡献了约 2.5%（g1）甚至为负（g2 路径长约 3%）。
3. **赛前“漂移不划算”的结论需要撤回**：我们测的是“持续漂移过弯”，sol 用的是“短漂蓄能、出弯喷火”；两者不是同一件事。下一轮应把漂移当作能量采集器，而不是过弯方式。
4. **下一轮优先级**：先修 `corner_drift` 的死触发条件与漂移时的速度方向控制，再对齐“boost 恒开”的能量策略，最后用 5011/5012 + 200 个留出种子做 A/B；在 0 漏检/0 越野/0 未完赛的前提下，把 g1 类飞行圈压到 5.4 s 以内、g2 类压到 5.0 s 以内。
5. **样本边界**：只有两局、两条赛道，且 sol 的内部逻辑不可见；以上因果判断基于回放输入与遥测，不排除赛道/座位/对手适应性的混合影响。下一轮至少要用更多种子验证，不能把这两局的表现直接外推成“对所有对手都慢 15–25%”。
