## 关键操作与相对第2轮的改动

以下是本轮实际提交代码中的行为，不是逐帧回放结论。

1. **保持滚动规划而不是固定按键。** 每窗口依据真实观察重新模拟38个候选各60帧，只提交前20帧；全油门，按前视目标和侧滑角修正转向。漂移候选以6帧为周期短脉冲蓄能，松漂后转成喷火能量，并持续请求可用喷火；转向绝对值小于0.16时取消漂移。漂移请求并不保证引擎每帧实际漂移，仍受速度、转向和草地条件约束。
2. **新增12个内侧切弯候选。** 在第2轮26候选基础上组合前视10/14/18、每6帧漂移2/4帧、内侧偏移1/2格，按前方中心线转角判断内侧。作用是让规划器比较更短弯线；正式汇总不能证明具体用了哪条线。代价是潜在出草、漏点风险，仍由路面与检查点评分约束。
3. **新增每个有序检查点10分奖励。** 预测中同步更新下一检查点，让评分偏向真正有效的推进，而不只是沿中心线投影距离。保留已越点但未入判定圆时回头瞄准该点的补点逻辑，判定采用半径减0.1格。本轮没有启用实验中的强制瞄点 `guard`。
4. **新增终圈冲线优先。** 预测完成第三圈0号检查点时立即终止该候选预测，给予高奖励，并倾向更早完成；不足20帧的输出补合法直行输入。解决旧目标可能偏好“冲线后的虚拟距离”、忽略更早结束比赛的问题。两局均顺利冲线，但无逐帧证据证明哪一窗口由此改变选择。
5. **没有因两场战报再次改动程序。** 本次只更新复盘文档，`agent.js`、`agent.py`、入口和引擎均未改动；下文自测是赛前已有结果，不冒充本次新增验证或正式赛复现。

**后续重点：** 保留有效检查点与冲线优先，不以提高喷火启动数为优化目标。若取得公开回放，应先核对各圈时间、窗口候选、路外帧、检查点余量和能量变化，再判断内侧切弯及脉冲漂移的收益；仅凭本轮2胜不继续盲目增大内侧偏移或漂移占空比。车车碰撞预测、完整赛车线与制动点优化仍未实现。

# 第3轮赛前提交与离线自测（保留记录）

## 入口

`entry.json`：`{"mode":"program","command":["python","agent.py"]}`。

本机 `command -v python3` 无结果，`python` 可用，因此延续前两轮已运行的本机入口而非写入不可用的 python3。`agent.py` 用绝对路径启动同目录 `agent.js`，继承标准输入输出，实际控制在 Node 中执行。无第三方依赖、无网络、比赛时不写文件。每行输入对应一行 JSON，严格20帧，每帧一辆车。实际 Python 冷启动入口连续三行测试通过，总耗时154.9845毫秒，公开 API 接受所有输入。

## 实际采用的策略

1. 从每局观察读取真实中心线、路面栅格、检查点和宽度，建立累计弧长；通过线段投影求当前位置。没有种子特化，也没有固定赛道。
2. 前视目标方向结合车身朝向和侧滑角生成转向，全油门；使用短脉冲漂移蓄能、松漂转换能量，并请求喷火。转向小于0.16时退出漂移。控制器按照 `catalog.js` 实际参数工作，包括常规最高14、漂移转向倍率1.6，而不是依赖简述中的近似值。
3. 每窗口模拟 **38个参数候选×60帧**，提交最佳候选的前20帧，再从真实观察重新规划。原26个候选保留；新增12个弯内侧候选：前视10/14/18，6帧漂移2/4帧，内侧偏移1/2格。内侧方向根据前方中心线转角确定。
4. 评分包含沿线推进、末速度、路面/路缘代价、越过未通过检查点的惩罚；本轮增加每通过一个有序检查点10分。候选内部更新 `nextCp`，避免只优化无效的几何进度。
5. **冲线优先**：预测通过第三圈0号检查点即终止预测，给予高奖励，并优先选择更早冲线的候选。不再以冲线后的无意义距离抵消冲线收益。若预测提前结束不足20帧，则用合法直行输入补满窗口。
6. 保留上一轮补点：已越过下一检查点、尚未进入判定圆时，切回该检查点。预测通过点使用半径减0.1格的保守判定。
7. 单车前向物理复现公开规则，包含倒计时、油门、转向、侧滑、能量转换、喷火、草地和墙体。仍未预测车车碰撞，不假设知道对方未来输入。

## 局限

- 对未知正式对手没有胜率保证。现已取得的第3轮两场正式结果均获胜，但样本仅2局；上一轮自有程序也不代表正式对手强度。

- 物理一致性只在验证的非车碰撞情形成立；正式观察舍入和对手未知输入仍会造成误差。
