# 本批复盘观察

对应批次：`run-20261014-182739`，3 轮 6 局均由 Sol 获胜。六局棋谱各不相同，均通过独立回放核验；没有非法落子或超时替代胜负。

Luna 确实连续提交了三版不同的程序，但都保留了评估方向问题：它计算对手未被阻断的棋形分数 `defense`，然后把正值加进自己的落子评分，最终选择最高分。这样在其他条件相近时，保留对方威胁反而更有利，主动阻断威胁却会降低分数。立即获胜和立即挡五的检查只能覆盖部分局面，无法抵消更早阶段的错误选择。这是代码中的具体缺陷，不是根据输棋倒推的模型性格判断；仅修正这一项是否足以获胜，本批没有测试。

- [Luna 第 1 版](./iteration-1/luna/engine.py)：`attack + defense*1.18`。
- [Luna 第 2 版](./iteration-2/luna/engine.py)：`attack + 1.12*defense`。
- [Luna 第 3 版](./iteration-3/luna/engine.py)：`attack + 1.08*defense`。

Luna 的后两轮复盘主要仍在重复初始棋谱的叙述，没有清楚分析最近一轮的关键失误；第三轮还把已结束且包含完整获胜落子的真人对局称为不完整。它运行了合法性和简单战术检查，但这不能证明修复了造成失败的评估错误。

Sol 的复盘逐轮引用了新增棋局和具体落点，并在原有搜索上增加了搜索边界的威胁检查、局面恢复验证、超时备用落子与走法排序。它的测试也会检查具体战术是否正确，而不只是输出是否合法。当前结果支持 Sol 在这次自主编写、复盘和改进策略实验中表现更好；样本仍不足以推出任意游戏或通用任务的胜率。

以上是组织者在赛后对记录与源码的观察，没有作为提示交给任一选手，也没有替任一选手修正策略。双方始终只获得自己的源码和相同公开棋谱。
