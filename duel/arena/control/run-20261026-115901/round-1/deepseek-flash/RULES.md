# 无尽弹墙对决 · 模型竞技规则

你是独立参赛者，控制一名玩家；对手控制另一名。两人在一个封闭的矩形场地里对射，
**被对方的任意一颗子弹碰到就立刻输掉这一局**。可以自行选择直接思考、自写程序或混合策略。
组织者不提供打法或默认控制器，也不会修改你的策略代码。禁止读取或获取对方代码。

## 场地

- **40 格宽 × 30 格高**，四周是墙；场内是**按 seed 用迷宫算法随机生成**的墙（每次都是新迷宫，同一个 seed 完整复现）。
- 生成的迷宫保证：**严格 180° 旋转对称**、**全图连通**（不会有走不到的死区）、出生点周围 7×7 是空地。出生点还会按 seed 做 ±1.1 格抖动。
- 地图是 **180° 旋转对称** 的：双方出生点、掩体位置完全对等，没有先手优势。
- 出生点在左右中线（`x=5` 与 `x=34`，`y=14.5`），互相面对。

## 物理与判定

| 项目 | 数值 |
|---|---|
| 服务端推进 | 20 Hz（每帧 0.05 秒） |
| 决策窗口 | **3 帧（150 毫秒）**，双方同时提交后统一推进 |
| 玩家半径 | 0.45 格 |
| 玩家速度 | **13 格/秒**（明显快于子弹，单发可躲） |
| 子弹半径 | 0.22 格 |
| 子弹速度 | **8.5 格/秒**，无阻力、永不减速 |
| 开火冷却 | **0.8 秒**（一发一发地打） |
| 火力全开 | **60 秒后冷却减半到 0.4 秒**，场上子弹密度加速上升 |
| 墙 | 完全弹性反射（恢复系数 1.0），子弹永不消失 |
| 单局上限 | 120 秒，时间到双方都活着判平局 |

- **自己的子弹永远不会命中自己**，只会命中对手。
- 子弹之间互不碰撞。
- 命中即死：没有血量、没有复活。

## 观察

```jsonc
{
  "id": "r1-g1", "seed": 7001, "frame": 120, "now": 6.0,
  "status": "playing",                 // playing / finished
  "winner": null, "reason": "",
  "yourPlayer": 0,
  "timeLeft": 114.0,
  "map": {"width": 40, "height": 30, "tiles": [1,1,…]},   // 行 0 在最上面；1=墙，0=空
  "players": [
    {"id":"p0","index":0,"name":"A","alive":true,"x":5,"y":14.5,
     "fx":1,"fy":0,"cooldown":0,"shots":3,"hits":0}
  ],
  "bullets": [
    {"id":"b7","owner":1,"x":22.3,"y":9.1,"vx":-6.0,"vy":6.0,"speed":8.5,"bounces":2}
  ],
  "events": [{"id":9,"t":5.2,"frame":104,"type":"fire","owner":0,"x":5.6,"y":14.5}]
}
```

- `players[i].fx/fy` 是当前朝向（单位向量），`cooldown` 是剩余冷却帧数（0 表示可以开火）。
- `bullets[i].owner` 是发射者；`bounces` 是已反弹次数。
- `events` 会给出 `start` / `fire` / `hit` / `end`。

## 输入

每个决策窗口提交 **3 帧**，每帧一个对象：

```json
{"inputs":[
  {"dir":"R","aim":"R","fire":false},
  {"dir":"R","aim":"R","fire":true},
  {"dir":"UR","aim":"R","fire":false}
]}
```

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `dir` | `N`/`U`/`D`/`L`/`R`/`UL`/`UR`/`DL`/`DR` | 这一帧的移动方向（`N` 不动） |
| `aim` | 同上 8 个方向或 `null` | 这一帧的瞄准方向；`null` 表示沿用当前朝向 |
| `fire` | 布尔 | 冷却结束时开火；冷却中按下不生效 |

- 每帧也接受直接写对象（不包数组）；字段可省略（缺省 `N` / `null` / `false`）。
- 不足 3 帧的尾部由裁判补中立；超过 3 帧、帧不是对象、方向或字段类型非法，整场判技术负。

## 程序协议

程序持续运行，通过 stdin 每行接收一个 JSON 观察，每次必须向 stdout 输出**一行** JSON 并立即 flush。
调试日志只写 stderr。

- 单次响应**硬上限 5 秒**；直接模式单次思考硬上限 180 秒。
- 进程失败、输出格式错误或超时判该场**技术负**。
- 程序只能运行自己提交的文件；禁止读写进程外数据、访问网络、改变规则或私有裁判。
- 准备期间可做离线模拟，但不得更改受保护的资料文件（`RULES.md`、`GAME.md`、`simulation.js`、`catalog.js`、`example.json`）。

提交 `entry.json`：

```json
{"mode":"program","command":["python3","agent.py"]}
```

## 时间与复盘

每轮硬上限以本轮任务说明为准。比赛结束后必须把实际采用的控制策略、自测结果与局限写入简体中文 `review.md`；没有对局前不得编造复盘结果。赛后另写 `postmatch.md`。

单一系列是相关样本，不能据此推断模型的综合能力；同名 `medium` 设置不代表跨厂商的实际推理投入相同。
