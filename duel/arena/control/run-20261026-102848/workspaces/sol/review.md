## 采用的策略

1. **按真实观察建图**：不假设固定柱子。观察 tiles 是随机迷宫；速度、半径等优先取观察 rules。资料部分描述与公开源码不一致，实际模拟使用未改动的 simulation.js / catalog.js。
2. **运动与弹墙预测**：模拟每帧先横轴再纵轴移动，以及每帧三子步、逐轴反弹。仅将对方子弹作为危险，己方子弹不会限制走位。
3. **迷宫寻路**：在半格网格上计算合法节点和八邻接边，Dijkstra 求至对手的距离场。圆周八采样检测尽量与源码一致；对角寻路边禁止穿角。
4. **短期规划避弹**：每次对未来 15 帧进行宽度 36 的束搜索，只执行前三帧再规划。空间桶加速威胁查询；前三帧碰撞惩罚远高于行进、开火奖励。观察坐标保留三位小数，墙边可能产生一个反弹子步的偏差，碰撞预测额外增加 0.23 格余量。
5. **防范新发射子弹**：估计敌方最近移动方向，并枚举停留及八个移动方向、八个射击方向，在冷却结束处生成假想威胁。即将实际执行的三帧对此施加更高风险权重，但不把所有假想弹当作必然存在。
6. **射击和距离**：依据双方冷却改变接敌距离；自身冷却时保持更远。枚举八个合法瞄准方向，对敌方九种运动假设计算短期命中分数，必要时评估约三秒的弹墙轨迹。始终按住 fire，实际发射由裁判冷却约束。移动与瞄准相互独立。
7. **协议**：持续读 stdin，每个观察输出一行三帧 JSON 并 flush；不调用网络，不读写外部数据。异常日志仅到 stderr，并有合法格式的应急输入，但应急输入不保证安全。

## 物理、协议和压力验证

`python verify.py` 的最终结果保存在 `verification_results.json`：

- 对公开 JS 模拟连续比较 381 个物理帧，移动位置最大偏差 **0.001077 格**。
- 既有子弹位置最大偏差 **0.199668 格**。最初要求误差小于 0.002 的断言失败；调查发现观察三位小数舍入会改变墙边反弹子步。验证脚本改为明确允许一个子步偏差，并在实际策略增加保守余量。这不是精确无误差的长时预测。
- 首次验证还遇到 Windows 默认 GBK 解码错误，已将测试子进程管道明确设置为 UTF-8。
- 通过真实 `python agent.py` 持续进程连续发送三行观察，全部返回合法三帧输入，退出码 0，stderr 为空。
- 使用 entry.json 中实际命令的额外启动冒烟测试成功，首个窗口含启动约 **0.117 秒**。
- 合成 **500 颗敌方子弹** 的观察连续计算五次，最慢约 **0.0683 秒**，均远低于 5 秒。此项仅测试计算耗时与格式，不代表在该危险局面能生存；也不是实际对局结果。

## 局限

- 束搜索只有 0.75 秒视野，可能剪掉长期安全的路径，或在狭窄区域进入后续无法逃脱的位置。
- 只枚举有限的敌方动作模式；真实对手可逐帧改变方向、延迟射击，九种恒定运动假设不能完整覆盖。
- 坐标舍入和离散反弹可能产生更长时间的轨迹分歧，0.23 格余量并非形式化安全保证。
- 半格路径网格对实际可走空间是近似，保守禁穿角可能遗漏一些合法捷径。
- 对假想弹的风险是软惩罚，不是严格最坏情况可达域；最终追击测试仍有一败。
- 开火估值不是完整博弈搜索，远期弹墙弹可能被困在无效区域；长期弹幕密度只通过滚动危险预测间接处理。
- 镜像测试只是相同实现之间的对抗，胜负主要反映局面差异，不证明策略优于自身。
