# 第 1 轮准备与自测记录

## 提交

- 选手：gpt-6.1-sol。
- `entry.json`：`{"mode":"program","command":["node","agent.js"]}`。
- 本机 Git Bash 中 `python3 --version` 返回 command not found，Node.js v24.13.1 可用。因此采用程序模式支持的命令数组运行 JavaScript，而非不可用的 python3 命令。
- 运行只使用自己的 `agent.js` 和公开 `catalog.js`，不访问网络、不读取对方文件、不写运行时文件。stdout 仅输出逐行 JSON；错误信息写 stderr。

## 实际策略

1. 按公开源码复现每帧移动的轴分离墙碰撞，以及每帧三子步的子弹反弹。子弹碰墙按中心点判断，不错误套用子弹半径。
2. 每个观察预测所有敌弹未来 24 帧（1.2 秒）。使用宽度 40 的束搜索，逐帧枚举 9 种移动，包括停止；同一空间附近合并状态以保留可达位置的多样性。
3. 排除距离敌弹小于 0.705 格的预测状态，在法定 0.67 格命中距离外保留数值余量；对近弹增加软惩罚。自己的子弹不列入危险源。
4. 敌方快能开火时避免近身；对手冷却且自己快能开火时倾向靠近。依据最近两次观察估计敌方速度，并用短期外推调整移动目标。
5. 通过空地网格广度优先距离提供绕柱指引，辅以缓慢变化的开放区域目标、边墙惩罚及轻微转向惩罚。
6. 只执行规划路径的前三帧，下一次观察重新规划。开火时比较八种方向，模拟未来 70 帧弹道及反弹，对当前敌方位置和多种短期提前量评分。低价值时略偏好对角弹道，以扩大长期覆盖。
7. 按真实冷却逻辑处理：冷却帧数大于零的帧只减一，不在该帧射击。

## 已完成的实际测试

测试全部在自己的工作区，直接调用未修改的公开 `simulation.js`；没有正式比赛结果，也没有读取对手程序。公开战报 `public_results.json` 为空。

### 物理校验：`node verify.js`

- 100 颗子弹各推进 1000 帧，共 100000 个子弹帧，预测位置相对公开模拟器的最大误差为 0；速度符号也逐帧校验。
- 随机移动 1500 帧，预测与公开模拟器位置一致。
- 人工 100 颗敌弹场景，20 次响应均输出合法三帧窗口，最慢 28.847 毫秒，明显低于 5 秒上限。
- 详细记录见 `verification_results.json`。

### 对抗自测：`node test.js turret rush kite wander orbit self`

所有自写基础对手均具备 12 帧弹道预测避险和持续开火，并非纯静止靶。

| 对手 | 我方座位 0 | 我方座位 1 |
|---|---|---|
| turret：偏好驻守、遇险移动 | 平局 120.05 秒 | 平局 120.05 秒 |
| rush：追击靠近 | 平局 120.05 秒 | 胜 11.40 秒 |
| kite：保持约 12 格距离 | 平局 120.05 秒 | 平局 120.05 秒 |
| wander：定期改变目标方向 | 平局 120.05 秒 | 平局 120.05 秒 |
| orbit：绕场目标移动 | 平局 120.05 秒 | 胜 60.10 秒 |
| self：同一正式控制器 | 平局 120.05 秒 | 平局 120.05 秒 |

- 最终版本对五类自写基础对手共 10 局：2 胜、8 平、0 负；另有 2 局同策略平局。
- 最终对抗测试的单次响应最大值 21.27 毫秒，局均约 4.84–6.57 毫秒。
- 120.05 秒来自公开模拟器浮点时间累加后的实际结束帧，不是修改时限。
- 结果详见 `test_results.json`。初版测试另保存在 `test_results_initial.json`，没有把两个版本混为独立证据。

## 已知局限

- 多数对抗局仍然平局，当前策略重视生存，未证明能稳定击败可靠避弹对手。
- 束搜索只保留有限状态，不能证明全局安全；弹道规划范围仅 1.2 秒。
- 观察坐标四舍五入，接近反弹临界点时轨迹可能与真实状态分叉；距离余量只能部分缓解。
- 尚未生成对手未来所有可能新子弹的联合轨迹，主要依赖距离与冷却惩罚防突然近身开火。
- 网格绕柱距离不是精确连续最短路；敌方运动与进攻提前量是启发式，遇到频繁变向可能失效。
- 如果候选状态全被判危险，存在退化行为，不能保证从任意包围局面脱困。
- 自测对手来自自己编写，样本少、风格有限，不代表正式对手或模型总体能力。
- 正式比赛尚未进行，本文不是正式赛后复盘；正式战果需赛后据实另记。
