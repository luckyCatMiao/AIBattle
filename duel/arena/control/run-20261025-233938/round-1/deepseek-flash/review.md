# 无尽弹墙对决 · 第 1 轮准备复盘（deepseek-v4.1-flash）

> 本文件写于正式对局开始之前。**尚未与真实对手交手**，因此不包含任何对局/比分结果；
> 下面所有数字都是我在本地自建的测试环境里跑出来的。

## 1. 提交内容

- `entry.json`：`{"mode":"program","command":["python3","agent.py"]}`
- `agent.py`：唯一被运行的参赛程序（只依赖 Python 标准库，无文件/网络访问）。
- `python3.cmd` / `python3.bat`：本机只有 `python.exe`、`where python3` 找不到，
  放一个只做 `python %*` 的转发壳作为兜底；若执行环境自带 `python3` 则完全不会用到。
- `dev/`：我自己的离线测试工具（不计入参赛逻辑）。

## 2. 实际采用的策略

### 2.1 精确物理预测
把 `simulation.js` 的推进逐条移植成 Python：20 Hz、每帧 3 个子步、子弹按“点”判定
墙面（轴分离、完全弹性）、玩家按半径 0.45 的 8 点采样判墙、发射点在朝向前方 0.79 格、
冷却 24 帧、命中半径 0.67。用随机输入对拍 226 个决策窗口，位置/冷却/弹数的误差全部在
快照 3 位小数的舍入范围内（0 处不一致）。

### 2.2 走位：束搜索（beam search）
- 每 150 ms 拿到观察后，对未来 `H=8` 帧（0.4 s）做 9 方向（N/U/D/L/R/UL/UR/DL/DR）束搜索，
  束宽 64；只执行前 3 帧，下一窗口重新规划。
- 代价 = 对最近 26 颗敌方子弹的软排斥（命中半径内直接 1e5）+ 墙/柱净空惩罚 +
  奖励开阔地 + 与对手的期望间距 + 站立惩罚。
- 叶子节点再加：若站着不动，未来 1.1 s 内子弹的静态风险（用于避开“0.4 s 后才会被堵死”的位置）。
- 安全缓冲：规划时把命中半径从 0.67 放宽到 0.77（`MARGIN=0.10`），抵消 3 帧盲区与模型误差。
- 因为自己的子弹永远打不到自己，**只要冷却到点就开火**（开火不消耗移动、不减速）。

### 2.3 进攻与站位
- 把“对手当前朝向的 8 条弹道（含反弹）”逐条模拟 4 s，对对手的几种运动模型
  （静止 / 当前速度 / 速度 ±45° / 速度 ±90°）加权评分，选最接近“会打中”的方向；
  另外加一个“整条弹道最近距离”的平滑兜底，避免 8 个方向同分时乱选。
- 位置评分里加了 `lane_score`：奖励“从该位置出发、第一段不撞墙的弹道能扫过对手”的点，
  于是会主动绕开中央柱去获得直射/斜射角度。
- 冷却相位：对手冷却 ≤6 帧时拉开到约 12 格；对手冷却 ≥12 帧（刚开过火）才压到约 4 格；
  其余时间保持约 8 格。若对手冷却 ≤4 帧，额外虚构一颗“从对手位置朝我当前位置射来”的子弹
  参与避让（相当于预判它的下一枪）。
- 所有行为带一个固定的极小随机扰动（`JIT=1.0`，种子固定），只用于打破平局/避免固定循环。

## 3. 自测方法与结果

### 3.1 测试环境
- **精确引擎**：`dev/harness.js` 直接 `require('./simulation.js')`，把观察通过 stdin 喂给
  `python agent.py`，收集 3 帧输入后调用 `advanceWindow`，与真实服务端同一条物理路径。
- **快速引擎**：`dev/selfplay.py` 用移植后的 Python 物理（已对拍）跑内置基线，用于批量参数实验。
- **基线**：`idle`（原地不动、只朝我开枪）、`random`（随机移动/瞄准）、`dodge`（每 3 帧贪心
  躲最近的子弹并朝我瞄准，精确引擎内置版）、`hunter`（贴身追击并躲子弹）、以及自博弈。

### 3.2 主要结果（均为 120 s 单局上限）
| 对手 | 结果 |
|---|---|
| idle（不动） | 胜，185 帧（约 9.3 s），我方 8 发 |
| random | 胜，约 215 帧（约 10.8 s） |
| hunter（Python，贴身） | 胜（多次自测均能击杀） |
| dodge（精确引擎内置贪心躲避） | 8 个随机种子 × 双方座位 = 16 局：**10 胜 6 平 0 负** |
| 自博弈（两个 agent.py 进程，精确引擎） | 120 s 平局，双方各 97 发、场上 194 颗子弹、0 命中 |

- 对 dodge 的 16 局中，胜局击杀时间约 21–116 s；6 平都是拖满 120 s（双方各约 97 发）。
- 单次决策耗时：平均约 33 ms，p95 约 38 ms，最大约 100 ms（含进程间 JSON），远低于 5 s 硬上限。
- `public_results.json` 为空数组，没有可参考的公开战报。

### 3.3 调试中发现的两个关键点
1. **同帧互射的座位不对称**：引擎按子弹加入列表的顺序判定命中。双方同帧互相命中时，
   座位 0 的子弹先被检查，座位 0 胜。早期“贴脸对射”策略在座位 1 的 8 局里输了 2 局；
   改成上面“冷却 ≤6 就拉开”的保守间距后，16 局 0 负。
2. **在冷却中贴脸最危险**：曾出现我在 1.1 格、对手冷却 0、我刚打完进入 24 帧冷却而被反杀。
   把“预判对手下一枪”的虚拟子弹触发窗口从冷却 ≤2 提前到 ≤4 后，生产种子在两个座位都转为获胜。

## 4. 局限与风险
- **对手未知**：所有基线都是我自己写的近似，10 胜 6 平 0 负只说明“能稳定压制一个贪心躲避脚本”，
  不能外推到真实对手。若对手是同样强度的搜索型 agent，很可能大量平局。
- **瞄准是启发式**：只有 8 个离散朝向，远距离单发很容易被躲；进球很大程度依赖子弹累加后的流弹。
  没有对对手策略做逆向建模（没有针对某个具体对手过拟合），也没有做“封走位/逼角”的主动围猎。
- **规划视野有限**：0.4 s 束搜索 + 1.1 s 静态风险尾部，不是博弈论最优；极端多子弹场面可能仍有漏判。
- **确定性**：模拟本身无随机；agent 的随机扰动种子固定，因此面对同一对手同一局面行为可复现。
  自测样本量有限（16 局/组），结论有噪声。
- 没有实际比赛对局，故无赛后复盘；等正式对局结束后再补 `postmatch.md`。
