## 2. 本轮改动

### 2.1 提交版本

```json
// entry.json
{"mode":"program","command":["python3","agent.py"]}
```

- `agent.py` 只依赖 Python 标准库；无环境变量、无文件读写、无网络访问。
- 比赛命令没有附带任何 `DUEL_*` 环境变量，因此全部走默认路径。

### 2.2 相对第 2 轮提交的行为改动（比赛时已生效）

第 2 轮提交版本 sha256 为 `809bf672...`（`round-2/deepseek-flash/agent.py`）。
本轮版本 sha256 为 `7012873e...`（`round-3/deepseek-flash/agent.py`）。
两次提交之间的默认行为差异只有一项：**对手贴身禁区**（第 2 轮赛后可复现实验中加入）。

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `DUEL_KEEP` | `1` | 总开关；`0` 恢复第 2 轮旧行为 |
| `DUEL_KFR` | `1.75` | 任何时候都避开的对手硬半径（格） |
| `DUEL_KFRR` | `2.60` | 对手冷却 ≤`DUEL_SCD`(6) 帧时的硬半径 |
| `DUEL_KFW` | `15000` | 硬半径内基础代价（低于子弹硬碰撞的 1e5） |
| `DUEL_KSR` | `3.40` | 软斥力半径 |
| `DUEL_OPPW` / `DUEL_OPPI` | `1.0` / `0.25` | 对手快能开火 / 装弹时的软斥力权重 |

实现要点（与 `review-r2-postmatch.md` 第 5 节一致）：

1. 用上一窗口速度外推对手未来位置，并取“当前位置距离 / 预测位置距离”的较小值，
   避免对手迎面冲锋或突然反向时低估危险；
2. 硬半径内按 `15000 × (1 + 3 × (r-d)/r)` 计费，越近代价越大；
3. 束搜索叶子对静态对手再加 0.5 倍硬/软贴身代价；
4. 未改动物理、瞄准、开火时机、威胁数量、外墙惩罚等任何其他默认逻辑。

## 6. 改动评估

### 6.1 对手贴身禁区：保留，评价为有效

- 目标风险（间距 <1.46 格、对手枪口可覆盖）本轮 **0 帧**；第 2 轮同一指标
  在 `r2-g1` 有 4 帧并直接导致失分。
- 副作用没有出现：97 发满射速、中位间距不变、贴墙率仍低、没有因为保守
  而被逼到墙角（两局最小墙距 1.60 / 0.45 格，仅短暂出现）。
- 不进一步收紧：第 2 轮曾把硬半径/软半径收到 3.2/3.8 格，暴露帧从 53 降到 21，
  但战绩变成 0 胜 2 负 4 平——安全指标变好、结果反而变差，因此本轮保持原参数。
- 但本轮对手行为与第 2 轮不同，不能把改善全部归因于改动；更准确的说法是
  “改动与结果方向一致，且没有可测的副作用”。

### 6.2 瞄准实验分支：继续默认关闭

- 本轮最接近命中的 `b160` 是一发 0 反弹直射弹，看起来支持“近距直射”；
  但它只是 97 发中的 1 发，且此前 24 局闭环 A/B 已证明直射整体更差。
  用一发结果反向开启 `DUEL_AIM` 属于赛后过拟合，不做。
- `DUEL_OPPV` / `DUEL_STW` 的默认值也保持第 2 轮行为，没有证据支持调整。

### 6.3 赛后没有修改策略代码

- 第 3 轮是最后一轮（`rounds=3`），没有后续对局可以验证新改动；
  此时修改 `agent.py` 只会让复盘对象与参赛版本脱节。
- 因此赛后只做测量与文档，不改变提交版本。

## 7. 局限与风险

1. **两局都是平局，胜负指标信息量很低**。一枪致命 + 子弹永不消失的机制下，
