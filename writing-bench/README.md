# 纸上见 · 模型创作评测

双击上一级 `StartWritingBench.bat`，或打开 http://127.0.0.1:8802/ 。启动页面不会自动发起新的模型调用。点击“出一道新题”，选择“故事与对白”或“SVG 绘画”，填写题目并选择参赛模型，才会开始新一轮。历史评测在右上角切换。

## 你先打分，再揭晓

默认隐藏作者型号，按随机稿号而不是裁判分数排列。每篇填写 0～100 整数分数及可选评语，点击“提交我的分数”保存；评分完成后仍保持裁判结果封存。你可以继续读下一篇，或主动点击“揭晓这篇的裁判评分”。揭晓后不再修改该篇的个人分数，保留你的独立判断。

全场作品都由你评分后，才可点击“揭晓全场评分与总榜”。裁判分数、评语、排序及报告导出受服务端校验，未揭晓的结果不会返回给页面。个人评分独立存于 `human.json`，不影响 Opus 的评分输入和结果。

模型名单和接口认证在每次启动 / 运行时从 `%USERPROFILE%\.claude\settings.json` 读取。密钥不复制到本项目、不返回网页，也不写入结果。调用遵循 `use-claude-proxy` 技能，通过 `claude_proxy/claude_proxy.py`；该模块来自 Unity 项目 `.agents/skills/use-claude-proxy/scripts/claude_proxy.py`。

## 首轮规则

- 27 个菜单模型，统一中文 JRPG 闲聊题，600～900 字；每模型一份作品。包括裁判同型号 Opus 5.5 的作品，单独标记为“同模型自评”。
- 每个作者是独立、无历史的 API 请求，没有工具、文件或他人的作品。使用相同 system / user 提示和 6144 输出 token 上限。
- 不沿用 Claude Code 为个别模型保存的 effort 设置。effort、temperature 均未显式指定，采用接口默认；不同模型的内部推理预算不保证相同。
- 使用配置中的原始模型 ID；接口报告的模型名和请求名同时保留。无法从兼容接口独立证明上游权重身份。
- 全部创作结束后，随机排序，Opus 5.5 逐份独立匿名评分；裁判只收到统一题目、固定标准、随机稿号和原文，不收到模型名、速度、其他作品或已有评分。
- 自然度 / 无 AI 味 50，人物区分 20，闲聊趣味 20，题目契合 10；总分由程序加总。没有分数归一化、强制拉开差距或人工改分。
- 校验各项范围和逐字原句证据。技术失败或评分格式不合法最多自动重试一次，保留每次尝试；有效作品不重写、有效评分不择优。失败显示未评分，不记为零分。
- 首轮有部分评语的引句未逐字对应原文：严格重试后如仍存在此问题，收尾检查只删除不匹配的引句，至少保留两条可核对原句；完全保留最后一次裁判返回的分项分数、总分和评语。修复记录存于 `evidence-validation.json`，绝不人工重打分。证据不足时保留为未评分。
- 对对象字段间误写成 `]["字段":` 的单个分隔符，允许无损改回 `],"字段":`；不修改字符串或数值，同样记录在上述校验文件中。其余无法解析的 JSON 不猜测补全。
- 网页可以隐藏模型名辅助读者阅读；此功能不是对浏览器开发者工具保密。评分请求的匿名化在后端单独完成。
- 单题、单样本、单裁判结果应作为这一轮的编辑评价，不能当作通用模型实力排行榜。题目与评语可能受裁判偏好影响。

## 第二题：SVG 视觉创作

题目是“恐龙倒立骑自行车，真实大小比例”，明确作为没有唯一标准答案的开放题。不因现实不可能而直接扣分，不预设唯一恐龙种类或姿态，也不把卡通画风自动判成比例错误。

- 同一批 27 个模型，各交一件独立静态 SVG；输出上限统一为 12000 tokens，没有工具或历史对话。
- 四项为：题意与动作 30、尺度与比例 25、画面完成度 30、创意 15。由 Opus 5.5 评分，不沿用对白的“AI 味”标准。
- 原始回复保持不变；仅提取 SVG 根元素（若附代码围栏），不重绘、不手工修补轮廓、姿态或比例。
- 用固定版本 `@resvg/resvg-js` 渲染为 PNG，最长边 1600 像素，保留画幅比例，以白色为透明背景。网页显示该 PNG，裁判的视觉请求传入完全相同的 PNG 字节，通过 SHA-256 核对。裁判不接收 SVG 源码、作者型号、用时或其他作品。
- 禁止外部资源、嵌入位图、脚本及动画。无法渲染的提交保留原始回复和错误，标记为未完成交付，不改图、不换作品、不记成作品零分，也不要求真人对空白图片评分。早期调用若产生了仅评价交付失败的裁判回复，会另存为交付记录，不计入视觉作品得分。
- 图片预览、原尺寸查看、SVG 下载、源码查看均不提前显示裁判分数。个人评分和揭晓门槛与第一题完全相同。
- 每篇的 `artwork.svg`、`preview.png`、`render.json` 和 `judge-input.json` 保存原图、像素哈希和视觉裁判输入记录。
- 源码文本哈希按 UTF-8 / LF 校验；另存 `source_file_sha256` 校验下载文件的实际字节，区分 Windows 的 CRLF 保存换行。图片仍按 PNG 原始字节核对，原始作品内容不因换行兼容处理而改写。
- 若裁判完整回复仅在 `scores`、`verdict` 后多出一个提前闭合根对象的 `}`，随后紧接 `strengths` 等其余字段，允许删除这一处结构字符再严格校验。所有分数和评语原值不变，使用最后一次完整回复，记录于 `grade-format-validation.json`；不以重打分挑选更高结果。
- 初始额度下没有交出任何正文的条目，再给一次统一 32768 tokens 上限的补交机会；原有失败记录保留。已经交卷的作品不重写、不择优；仍为空或接口超时的条目标为未交付，不记为零分。
- 少数 SVG 重复使用同一个元素 ID 时，resvg 与 Chrome 的引用选择不同。渲染副本保留首个同名 ID 的引用行为，与 Chrome 对照；原始 SVG 不变，调整记录存于 `render.json`。若涉及会改变外观的 CSS ID 选择器，则停止转换、等待核对，不猜测修图。

## 第三题：参考图纯 SVG 仿绘

- 使用 `svg_reference.py <本机参考图路径>` 创建独立评测，再运行同一批配置中的模型。参考图必须是静态 PNG / JPEG，原始字节复制存档，作者、裁判和网页都使用同一个 SHA-256 校验的文件。
- 只调用现有文本 / 视觉理解模型的 messages 接口，不提供工具，不调用任何生图接口。作者直接输出 SVG 源码；禁止 image、feImage、嵌入位图、外部资源、脚本和动画。渲染 PNG 只是把 SVG 显示出来。
- 统一输出上限 32768 tokens；有效作品不重写。技术失败最多重试一次，明确不支持图片输入时标记为不支持，不偷偷替换为文字提示或别的模型。
- 人物与关键形态还原 40、构图与空间 20、配色与光影 25、矢量完成度 15。裁判收到两张明确标注的图片：第一张参考原图，第二张参赛 SVG 渲染；第二张与人类看到的 PNG 字节完全一致。
- 评分保持封存，按原有规则由用户先评分、再揭晓；已直接公开的写作轮次不受影响。仿绘参考图和原作品都不修改，水印不作为评分重点。
- `writer-input.json`、作者尝试记录和 `judge-input.json` 保存参考图哈希、参数及图片顺序证据，不保存 base64 大块数据或凭据。

## 存档结构

`runs/<run-id>/run.json` 保存题目、规则、参数、作品和成绩；每份稿件的 `entries/<匿名稿号>/` 保存作者请求结果、原文、匿名裁判输入、裁判原始响应、结构化评分。`REPORT.md` 是带全篇作品的中文报告。原文有 SHA-256 可核对。

只保留最终答案和调用元数据，不导出模型隐藏思考内容。JSON、Markdown、正文均 UTF-8。

## 开发

Python 3 + httpx + Pillow，Node.js + `@resvg/resvg-js`；服务只监听 127.0.0.1:8804，标准库 HTTP 服务，无构建步骤。初次安装 SVG 渲染依赖可在本目录运行 `npm ci`。

```powershell
writing-bench\.venv\Scripts\python.exe writing-bench\server.py
writing-bench\.venv\Scripts\python.exe -m unittest discover -s writing-bench\tests
```

`--start-default` 参数会实际调用全部模型，日常打开请勿使用。服务重启后，未完成的评测可用页面上的“重试未完成项”继续；已经成功的作品和评分会复用。
