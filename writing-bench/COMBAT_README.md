# 当前轮次：真正 Claude Code 独立项目

当前重做批次由 `cc_combat.py` 启动真正的 Claude Code 2.1.296，每个配置模型独立工作区，17 路并行，显式 `--effort high`。不设置输出 token 覆盖、开发总时长、美元预算或工具轮数上限。Claude Code 自身及上游服务的固有限制仍存在。文件和 Bash 工具可用，作者自行创建项目、检查、修复，最终交付 game.html 并保留源文件。

WSL bubblewrap 只挂载该选手项目、独立会话目录和只读开发工具；宿主与其他选手源码不挂载。会话可恢复，技术错误持续交回原作者，不计入打击感评分。实际 CLI 命令、会话 ID、模型初始化记录、工具事件与项目物理行数逐项存档。仅从 CLI 日志确认所发送参数，不声称代理已证明上游推理强度。

本轮 GPT 兼容修正：实测配置中的代理会在 thinking 内容尚未结束时提前发送 content_block_stop，随后继续发送同一块的 delta，Claude Code 因而反复报 malformed stream。`cc_stream_proxy.py` 是只服务真实 CLI 请求的本地 HTTP 转发：请求体原样转发，不主动创建模型任务；仅延后过早结束事件、重映射复用编号，不修改模型文本和工具参数。所有内容增量保留，无法安全判断时中断并由原会话恢复。只记录事件类型和编号，不记录凭据或思考正文。Luna 已通过该路径实际执行 Write/Edit，后续 GPT 会话统一使用此兼容路径；细节见本轮 transport-compatibility.json。官方工具流/交错思考兼容选项的尝试也单独记录，不改 high 和输出额度。

下面是旧的直接 API 批次说明。旧写作、SVG、横版战斗 API 结果不能视为 Claude Code 项目能力评测，不与新轮混排名。

# 击感实验室

打开上级目录的 `StartCombatBench.bat`，或访问 http://127.0.0.1:8805/ 。打开页面只查看已有作品，不会发起模型制作请求。

本轮让配置中的 17 个模型独立制作同一道横版战斗试玩题。战斗设计没有标准答案，重点是输入与动作衔接、命中顿帧、受击反馈、攻防节奏和肢体破坏。模型通过 API 输出单文件 HTML，无外部素材、库或对手源码；每份文件保存在独立作品目录。

每次请求先申请 1,000,000 输出 tokens。如接口明确拒绝该额度，按其返回的限制协商单次额度；遇到 `max_tokens` 截断会自动续写，直到交付完成。不设本地总输出上限、总时长上限或 HTTP 读取超时。接口自身仍可能截断、限流、断连或因上下文超限拒绝请求；这些记录会保留。服务故障退避重试，不计为作品零分。

本轮实测 GLM 5.3 与 GLM 5.3 Flash 对相同短请求在 1,000,000 和 262144 单次额度下返回 502，在 131072 下成功，因此仅这两个模型采用验证可用的 131072 单次额度，触顶仍自动续写；诊断结果与参数变更保存在本轮 diagnostics 和 provider-token-caps.json。

流式进度文件采用独立临时文件与 Windows 文件占用重试；可选进度保存失败不会再中断模型回复。已因连接或旧存档故障中断的正文保留，重试时只交回原作者继续。多次服务失败后可以按自然函数边界逐段交付，直到完整闭合 HTML，不设总段数、总输出或总时长上限。分段交付与修复次数不参与评分。

本轮最初以 32768 tokens、1800 秒发起，用户随后要求放宽。预算变更、旧参数和中断前文件在 `combat-runs/<run>/budget-history/` 中保留。已完成作品保留，未完成任务使用新参数重启。交付检查失败的作品只把自己的源码与错误交回原作者自修；去掉了此前自修建议的 12000-token 紧凑目标。模型输出原文与每段续写均存档，主控不手工修游戏代码。

作品只在禁止网络访问的沙箱中运行。主机只做 HTML 提取和 `node --check` 语法检查，不在主机执行作品代码。正常 `/game` 路由展示原始交付；仅自动试玩的 `/game?sample=1` 路由追加统一的屏幕按键采样器，发送带 key/code 的标准键盘事件，并把作者提供的只读状态显示到画面。采样器不改变战斗逻辑，原始文件和下载内容不含采样器。

本轮采用 feel-only-v2：编译、启动与渲染错误持续交回原作者修复，不设修复轮数上限，不考核一次通过率、编码能力或修复次数。每次修复单独存档，旧截图与旧分数按源码哈希隔离。必须先确认能正常战斗，并实际验证命中及肢体破坏，才进入最终评分。操作取样不足时继续试玩，不据此给低分。此前包含技术故障影响的评分不作为最终结果。

Opus 5.5 匿名评审最终可玩版本的源码与实际 Chrome 试玩的离散截图：命中反馈35、动作衔接30、攻防节奏20、肢体破坏15。分数直接公开。截图不是录像，合成输入不是人类连续操作，音频未实际听取；评语须区分画面观察、源码推断和未确认部分。发现技术阻塞则不给分并退回原作者；证据不足则要求补充试玩。用户可自行试玩并保存独立评分，裁判分数只作为参考。

`combat_bench.py --serve` 只启动网页；`--create` 创建一轮（不自动发请求）；`--run <run>` 执行未完成制作；`combat_develop.py <run>` 持续跟进原作者修复；`combat_judge.py <run>` 在版本匹配的战斗验证与试玩材料存档后评审。凭据始终从用户现有配置读取，通过 `claude_proxy` 调用，不存入游戏或页面。
