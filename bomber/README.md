# 泡泡堂 / BLAST BUDDIES

一个无需安装依赖的网页 2–4 人炸弹对战游戏。双击项目根目录 `StartBomber.bat`，或运行 `npm run bomber` 后打开 <http://127.0.0.1:8797/>。

**所有席位操控完全相同的角色**：没有选角、没有角色差异、没有属性克制。地图上下、左右都镜像对称，四个出生角完全等价。胜负 100% 来自操作与决策。

## 玩一局

页面默认「本地对战」，右侧可以选 **人数（2/3/4）** 与 **真人数**，其余席位由练习电脑补足。点「开新局」立即重建。

| 席位 | 移动 | 放弹 |
| --- | --- | --- |
| 玩家 1 | `W` `A` `S` `D` | `空格` |
| 玩家 2 | 方向键 | `回车` |
| 玩家 3 | `I` `J` `K` `L` | `U` |
| 玩家 4 | 小键盘 `8` `4` `5` `6` | 小键盘 `0` |

规则要点：

- **一击即死**，没有血量；只有出生瞬间有极短保护帧。
- 炸弹引信 **2 秒**，爆炸是**十字形**，火焰持续 0.6 秒。
- **炸弹是实体障碍**：放下去之后自己也走不进去（只有刚放下的那颗例外，可以踩着走出去）。
  **放弹前必须确认有退路**——这是本游戏最容易犯的错。
- 火焰扫到的其他炸弹会**连锁引爆**。
- 硬墙阻挡火焰；软墙被摧毁后有 **55%** 概率掉落道具：**炸弹 +1 / 火力 +1 / 速度 +1**。
  踩到即拾取，火焰会烧毁地上尚未拾取的道具。
- 道具随局重置，每局所有席位都从 1 炸弹、1 火力、初始速度开始。

## 单局时限

> 每局 **150 秒**。时间到时仍有两名及以上角色存活，该局判平局（占用局数、不计分）。

没有涨水或战场收缩。对局由进攻与道具推动；时限只用来防止双方无限躲藏。赛制为**五局三胜**，同时死亡记平局。

## 多人同场

- 支持 **2–4 名选手**同时在一局里混战；任意席位可以是真人、外部程序或练习电脑。
- 2 人局取对角出生；3–4 人局使用其余出生角。每局轮换出生角与席位的对应关系，
  长系列里每人机会均等。
- 只剩最后一名存活者时该局结束；所有席位同时阵亡判平局。

## 外部程序 API

服务端以固定 20 Hz 推进。

创建对局：

```http
POST /api/matches
Content-Type: application/json

{"players":[{"name":"Agent A","kind":"api"},{"name":"Agent B","kind":"api"},{"name":"Agent C","kind":"api"}],"seed":1,"mode":"lockstep"}
```

支持 2–4 名选手；`kind` 为 `human` / `api` / `bot`，电脑席位不占凭据。响应 `{match, seats:[{player,token}], state}`。`player` 从 0 开始；房主不能是电脑。把各自 token 单独交给对应选手。

```http
GET /api/catalog            # 尺寸、炸弹参数、道具权重、单局时限
GET /api/health
GET /api/matches/MATCH_ID   # 可选 Bearer；不带凭据即只读观战
```

提交决策窗口（每 20 帧一次，所有席位同时提交，收齐后统一推进）：

```http
POST /api/matches/MATCH_ID/decisions
Authorization: Bearer YOUR_TOKEN

{"inputs":[{"dir":"R","btn":null},{"dir":"R","btn":"BOMB"}, … 共 20 帧 … ],"note":"可选简注"}
```

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `dir` | `N` / `U` / `D` / `L` / `R` | 不动 / 上 / 下 / 左 / 右，**持续按住即持续移动** |
| `btn` | `null` 或 `"BOMB"` | 放弹，**上升沿触发**，连续按住只算一次 |

不足 20 帧的尾部由裁判补中立；超过 20 帧或名称非法整条拒绝（不消耗本窗口的提交机会）；同一窗口重复提交返回 `409`。所有席位都提交后推进整整 20 帧。等待期间游戏时间不推进，所以本模式不奖励网络速度。

真人练习另有逐帧通道（网页用它驱动键盘）：

```http
POST /api/matches/MATCH_ID/step
{"input":{"dir":"R","btn":"BOMB"}}
```

观察字段包含完整公开地图（无战争迷雾）：`map.tiles`（行主序，`0` 空地 / `1` 硬墙 / `2` 软墙）、`map.audit`（上下左右镜像与出生区自检）、`spawns`、`timeLeft`（本局剩余秒数）、`fighters`（位置用 `px`/`py` 插值坐标）、`bombs`（含 `fuse`）、`blasts`、`drops`、`roundLog`、`rules`、`events`。

不提供对局持久化：重启服务即清空。回放与系列赛归档由竞技框架单独保存。

## 地图公平性自检

每局开局都会跑一次 `auditMap()`，结果随状态一起返回：

```json
{"asymmetric":0, "soft":135, "hard":90, "spawnBlocked":0, "spawnsCornered":true, "fair":true}
```

`asymmetric` 必须为 0——软墙严格上下、左右镜像，所有出生角周围无软墙。这是「所有席位起点完全相同」这句话的可验证依据，不是靠人肉感觉维持的。

## 模型对战与回放

双击根目录 `WatchBomberBattle.bat`，或打开 <http://127.0.0.1:8798/?replay=latest>。回放支持选系列、选局、暂停、0.5/1/2/4 倍速、拖动时间轴。

`bomber/arena/train.py` 负责模型竞赛：

```powershell
python bomber/arena/train.py --players deepseek-flash sol --rounds 3 --port 8797
```

每轮冻结策略后交换座位打两局；每 20 帧同步决策。**准备阶段默认不设时间上限**，模型完成自认为充分的准备后提交；`--prepare-seconds 1800` 可显式加单次上限。参赛模型统一通过 Claude Code CLI 运行，effort 设为 medium；跨厂商同名 effort 不代表计算量相同。DeepSeek 的模型 ID 为 `deepseek-v4.1-flash`。

参赛程序在 WSL Bubblewrap 隔离工作区运行，双方看不到对方文件；比赛执行阶段工作区只读、无网络，也不挂载模型凭据。公开规则源码去掉了练习电脑。程序单次响应硬上限 5 秒；崩溃、超时或非法响应记技术负，和游戏内胜负分开报告。

继续双方各自上一版：

```powershell
python bomber/arena/train.py --players deepseek-flash sol --continue-both --from-run bomber/arena/control/<旧系列目录名> --rounds 3
```

`node bomber/arena/audit.js <比赛目录>` 从初始状态重新执行全部双方输入，逐帧核对每一个快照，并核验引擎、规则目录及冻结策略的哈希。

## 验证

根目录运行 `npm test`。泡泡堂的测试覆盖：地图四向镜像与出生区空旷、2–4 人出生角轮换、炸弹引信与十字火焰、硬墙阻挡与软墙摧毁、连锁引爆、**炸墙掉落不被同一帧烧毁**、道具拾取与被烧毁、一击即死、同时死亡判平局、五局三胜赛制、**单局 150 秒时限与平局**、输入校验、同种子同输入必得同结果、终局不可变，以及 HTTP 席位隔离、同步决策等待语义、凭据不泄漏与静态文件安全。
