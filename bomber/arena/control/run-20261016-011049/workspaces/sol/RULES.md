# 泡泡堂 · 模型竞技规则

你是独立参赛者，目标是赢得比赛。可以自行选择直接思考、自写程序或混合策略。组织者不提供战术或默认控制器，也不会修改你的策略代码。禁止读取或获取对方代码。双方使用相同游戏规则；本轮任务会说明起点、推理设置及准备预算。

## 游戏与资料

阅读 GAME.md 的玩法与 API、catalog.js 的全部数值、simulation.js 的公开规则（已去掉练习电脑），以及 example.json 的起始状态与示例输入窗口。可用 node 执行测试。准备环境仅包含你自己的 `/workspace`；比赛时 `/workspace` 只读且无网络，只有 `/tmp` 可写。

**双方操控完全相同的角色**——没有选角、没有角色差异、没有属性克制。地图是 180° 旋转对称的，不存在先手几何优势。胜负 100% 来自你的操作与决策。

## 提交 entry.json

```json
{"mode":"program","command":["python3","agent.py"]}
```

也可提交 `{"mode":"direct"}`，由每个决策窗口重新调用你的模型并读取你写入的 `/workspace/action.json`。直接模式可以保留自己的 notes 文件；思考耗时不计入游戏时间。

## 决策窗口

裁判以 20 Hz 推进，每 **20 帧（1 秒）** 为一个决策窗口。双方同时看到同一帧，各自提交最多 20 条逐帧输入；**收齐两方之后**才统一推进 20 帧。等待思考期间游戏时间不推进，所以本模式不奖励模型网络速度。

每次观察都带 `yourPlayer`、`lastErrors`、`decisionWindows:true`、`framesPerWindow:20` 与 `exampleWindow`（一份可照抄的合法窗口）。

输出格式（一行 JSON，立即 flush）：

```json
{"inputs":[{"dir":"R","btn":null},{"dir":"R","btn":"BOMB"},{"dir":"N","btn":null}, … 共 20 帧 … ],"note":"可选的简体中文简注"}
```

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `dir` | `N` / `U` / `D` / `L` / `R` | 不动 / 上 / 下 / 左 / 右。**持续按住即持续移动** |
| `btn` | `null` 或 `"BOMB"` | 放弹。**上升沿触发**：连续按住只算一次 |

- 一整个窗口全填 `{"dir":"R"}` 表示向右走完这一秒。
- 不足 20 帧的尾部由裁判补中立；超过 20 帧、帧不是对象、方向或按钮名不合法，整场判**技术负**。
- 空 `inputs` 会按 20 帧中立处理，等价于站着不动。

## 核心机制

- **炸弹**：引信 40 帧（2 秒），爆炸为十字形，范围由 `blast` 决定，火焰持续 12 帧（0.6 秒）。
- **炸弹是实体障碍**：放下去之后自己也不能再走进去（只有刚放下的那一颗例外，可以踩着走出去）。
  **放弹前必须确认有退路——放弹不设退路等于自杀。** 这是本游戏最容易犯的错。
- **连锁**：火焰扫到的其他炸弹会立即引爆，可以连锁成大片区域。
- **硬墙**阻挡火焰；**软墙**被摧毁后可能掉落道具（炸弹 +1 / 火力 +1 / 速度 +1）。火焰落在道具上会把它烧毁。
- **一击即死**，没有血量。只有出生有极短保护帧。
- 每局双方都从 1 炸弹、1 火力、初始速度开始，装备**随局重置**。

## 涨水（反拖延机制）

> 开局 **40 秒**后，战场从四边向内收缩，每 **2.5 秒**淹没一圈。
> 站在水里的角色**立即死亡**。
> 出生点在距边 1 格处，**第 2 圈就会被淹**（约 42.5 秒）；中心区第 9 圈被淹（约 60 秒）。
> 单局硬上限约 65 秒。

**这条规则意味着「躲着不动」不可能拖出胜利——水会先淹死你。** 你必须主动结束对局，
要么炸死对手，要么把对手逼进正在收缩的死角。

## 赛制与计分

- 每局双方各一名角色，一击即死；一方死亡则另一方赢得该局。
- **五局三胜**：先赢 3 局者赢得该场对局；打满 5 局则按胜局多者判定。
- 双方同时死亡记为平局，该局不计分（仍占用局数）。
- 每轮两局，**交换座位**（谁先出手互换），策略在两局之间冻结。

## 程序协议

程序持续运行，通过 stdin 每行接收一个 JSON 观察，每次必须向 stdout 输出**一行** JSON 并立即 flush。调试日志只写 stderr。状态含完整公开地图（无战争迷雾）。

程序单次响应**硬上限 5 秒**；直接模式单次思考硬上限 180 秒。进程失败、输出格式错误或超时判该局**技术负**，并在结果中单独说明，不冒充游戏战术胜利。

程序只能运行自己提交的文件；禁止读写进程外数据、访问网络、改变规则或私有裁判。准备期间可做离线模拟，但不得更改受保护的资料文件（`RULES.md`、`GAME.md`、`simulation.js`、`catalog.js`、`example.json`）。

## 时间与复盘

每轮硬上限以本轮任务说明为准。比赛结束后必须把实际采用的控制策略、自测结果与局限写入简体中文 `review.md`；没有对局前不得编造复盘结果。赛后另写 `postmatch.md` 做整体复盘。

单一系列 6 局是相关样本，不能据此推断模型的综合能力；同名 `medium` 设置不代表跨厂商的实际推理投入相同。
