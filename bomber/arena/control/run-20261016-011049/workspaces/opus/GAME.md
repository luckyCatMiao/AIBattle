# 泡泡堂 / BLAST BUDDIES

一个无需安装依赖的网页 1v1 炸弹对战游戏。双击项目根目录 `StartBomber.bat`，或运行 `npm run bomber` 后打开 <http://127.0.0.1:8797/>。

**双方操控完全相同的角色**：没有选角、没有角色差异、没有属性克制。地图是 180° 旋转对称的。胜负 100% 来自操作与决策。

## 玩一局

默认「真人练习」模式：你对战内置规则电脑。

| 操作 | 按键 |
| --- | --- |
| 移动 | `W` `A` `S` `D` |
| 放弹 | `J` 或 `空格` |

规则要点：

- **一击即死**，没有血量。
- 炸弹引信 **2 秒**，爆炸是**十字形**，火焰持续 0.6 秒。
- **炸弹是实体障碍**：放下去之后自己也走不进去（只有刚放下的那颗例外，可以踩着走出去）。
  **放弹前必须确认有退路**——这是本游戏最容易犯的错。
- 火焰扫到的其他炸弹会**连锁引爆**。
- 硬墙阻挡火焰；软墙被摧毁后可能掉落道具：**炸弹 +1 / 火力 +1 / 速度 +1**。火焰会烧毁地上的道具。
- 道具随局重置，每局双方都从 1 炸弹、1 火力、初始速度开始。

## 涨水：反拖延机制

> 开局 **40 秒**后，战场从四边向内收缩，每 **2.5 秒**淹没一圈。站在水里的角色**立即死亡**。

这是本游戏最核心的设计，也是它与「躲着不动比谁活得久」这类退化玩法的分界线：

| 位置 | 距边 | 被淹时间 |
| --- | ---: | ---: |
| 出生点 | 1 格 | 约 42.5 秒（第 2 圈） |
| 中心区 | 8 格 | 约 60 秒（第 9 圈） |

**单局硬上限约 65 秒。** 躲着不动不可能拖出胜利——水会先淹死你。你必须主动结束对局：要么炸死对手，要么把对手逼进正在收缩的死角。

赛制为**五局三胜**，双方同时死亡记平局（占局数但不计分）。

## 外部程序 API

服务端以固定 20 Hz 推进。

创建对局：

```http
POST /api/matches
Content-Type: application/json

{"players":[{"name":"Agent A","kind":"api"},{"name":"Agent B","kind":"api"}],"seed":1,"mode":"lockstep"}
```

响应 `{match, seats:[{player,token}], state}`。`player` 从 0 开始；房主不能是电脑。把各自 token 单独交给对应选手。

```http
GET /api/catalog            # 尺寸、涨水节奏、炸弹参数、道具权重
GET /api/health
GET /api/matches/MATCH_ID   # 可选 Bearer；不带凭据即只读观战
```

提交决策窗口（每 20 帧一次，双方同时提交，收齐后统一推进）：

```http
POST /api/matches/MATCH_ID/decisions
Authorization: Bearer YOUR_TOKEN

{"inputs":[{"dir":"R","btn":null},{"dir":"R","btn":"BOMB"}, … 共 20 帧 … ],"note":"可选简注"}
```

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `dir` | `N` / `U` / `D` / `L` / `R` | 不动 / 上 / 下 / 左 / 右，**持续按住即持续移动** |
| `btn` | `null` 或 `"BOMB"` | 放弹，**上升沿触发**，连续按住只算一次 |

不足 20 帧的尾部由裁判补中立；超过 20 帧或名称非法整条拒绝（不消耗本窗口的提交机会）；同一窗口重复提交返回 `409`。双方都提交后推进整整 20 帧。等待期间游戏时间不推进，所以本模式不奖励网络速度。

真人练习另有逐帧通道（网页用它驱动键盘）：

```http
POST /api/matches/MATCH_ID/step
{"input":{"dir":"R","btn":"BOMB"}}
```

观察字段包含完整公开地图（无战争迷雾）：`map.tiles`（行主序，`0` 空地 / `1` 硬墙 / `2` 软墙）、`map.audit`（对称性自检）、`flood`（当前圈数与下一圈倒计时）、`fighters`（位置用 `px`/`py` 插值坐标）、`bombs`（含 `fuse`）、`blasts`、`drops`、`roundLog`、`rules`、`events`。

不提供对局持久化：重启服务即清空。回放与系列赛归档由竞技框架单独保存。

## 地图公平性自检

每局开局都会跑一次 `auditMap()`，结果随状态一起返回：

```json
{"asymmetric":0, "soft":84, "hard":56, "spawnBlocked":0, "fair":true}
```

`asymmetric` 必须为 0——软墙严格 180° 镜像，两个出生点周围无软墙。这是「双方起点完全相同」这句话的可验证依据，不是靠人肉感觉维持的。

## 模型对战与回放

双击根目录 `WatchBomberBattle.bat`，或打开 <http://127.0.0.1:8798/?replay=latest>。回放支持选系列、选局、暂停、0.5/1/2/4 倍速、拖动时间轴。

`bomber/arena/train.py` 负责模型竞赛：

```powershell
python bomber/arena/train.py --players opus sol --rounds 3 --prepare-seconds 1800 --port 8797
```

每轮冻结策略后交换座位打两局；每 20 帧同步决策。准备预算默认 30 分钟。客户端 effort 设为 medium；跨厂商同名 effort 不代表计算量相同。

参赛程序在 WSL Bubblewrap 隔离工作区运行，双方看不到对方文件；比赛执行阶段工作区只读、无网络，也不挂载模型凭据。公开规则源码去掉了练习电脑。程序单次响应硬上限 5 秒；崩溃、超时或非法响应记技术负，和游戏内胜负分开报告。

继续双方各自上一版：

```powershell
python bomber/arena/train.py --players opus sol --continue-both --from-run bomber/arena/control/<旧系列目录名> --rounds 3
```

`node bomber/arena/audit.js <比赛目录>` 从初始状态重新执行全部双方输入，逐帧核对每一个快照，并核验引擎、规则目录及冻结策略的哈希。

## 验证

根目录运行 `npm test`。泡泡堂的测试覆盖：地图 180° 对称性与出生区空旷、炸弹引信与十字火焰、硬墙阻挡与软墙摧毁、连锁引爆、道具掉落与拾取与被烧毁、一击即死、同时死亡判平局、五局三胜赛制、涨水节奏与「躲着不动会被淹死」、输入校验、同种子同输入必得同结果、终局不可变，以及 HTTP 席位隔离、同步决策等待语义、凭据不泄漏与静态文件安全。
