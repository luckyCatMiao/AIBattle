## 二、过程分析

### 1. 系列走势

- `r2-g1`：前三回合连续 150 秒平局，比分一直是 0 : 0；第 4、5 回合 Sol 连续击杀我方，系列赛以 0 : 2 结束。前三场平局没有让对手得分，但也让我方始终没有拿到任何胜局，系列赛被压缩到最后两回合决胜负。
- `r2-g2`：我方先赢 R1，R2 平，R3 负，随后 R4、R5 连胜，以“先胜三局”结束。唯一的平局发生在 1 : 0 领先时，没有影响系列赛结果。
- 两局合计 3 : 3 的回合战绩说明双方整体接近；差距主要在**关键回合的转化率**，而不是单方面的碾压。

### 2. 三个负局的解剖

| 对局/回合 | 时长 | 我方终局属性 | 对手终局属性 | 可验证的差异 | 推断 |
| --- | --- | --- | --- | --- | --- |
| `r2-g1` R4 | 68.05 秒 | 6 / 6 / 3 | 6 / 6 / 3 | 属性完全相同 | 均势交战失利；没有回放，无法判断是走位、炸弹封锁还是同时决策导致 |
| `r2-g1` R5 | 79.00 秒 | 6 / 6 / 2 | 6 / 6 / 3 | 我方速度低 1 级 | 速度落后会同时削弱追击、撤退和躲火容错；这与第 1 轮两次“1 速对 3 速”死亡的模式一致 |
| `r2-g2` R3 | 55.60 秒 | **3 / 1 / 0** | 6 / 6 / 3 | 我方炸弹少 3 级、火力少 5 级、速度少 3 级 | 明显的发育崩盘：55.6 秒时仍只有 3 弹、1 火、0 速，尚未形成战斗力就被击杀 |

要点：

- **3 个负局中有 2 个伴随属性劣势**（R5 速度差 1 级；R3 全面差），只有 1 个是纯均势失利。
- `r2-g2` R3 的 `3 / 1 / 0` 是本轮最明确的异常。它与第 1 轮 `r1-g2` R3 的 `3 / 2 / 1`（61.90 秒，负于 6 / 6 / 3）高度相似：**同一局号（第 3 回合）、同一座位（owner 1）、同一种“发育未完成即被击杀”**。两场只有两个样本，不能据此断言是出生角、地图种子还是对手开局策略造成的，但这是下一轮最值得优先复查的模式。
- 公开战报只给出终局属性，没有死亡坐标、炸弹归属或逐帧输入，因此不能把 R4 的均势失利进一步归因到具体战术。

### 3. 三个胜局的解剖

| 对局/回合 | 时长 | 我方属性 | 对手属性 | 取胜方式 |
| --- | --- | --- | --- | --- |
| `r2-g2` R1 | 91.05 秒 | 6 / 6 / 3 | 6 / 6 / 3 | 均势击杀 |
| `r2-g2` R4 | 122.40 秒 | 6 / 6 / 3 | 6 / 6 / 3 | 均势击杀，耗时最长 |
| `r2-g2` R5 | 56.55 秒 | 6 / 6 / 3 | 6 / 3 / 0 | 属性领先，快速兑现 |

- 我方唯一一次明显的属性领先（R5 对 `6 / 3 / 0`）在 56.55 秒内完成击杀，说明**一旦拿到属性优势，收尾能力是够的**。
- 两次均势胜利分别耗时 91.05 和 122.40 秒，说明均势局需要较长的消耗与等待对手失误；这也是 4 个 150 秒平局的来源。
- 我方没有在任何属性落后的回合获胜；对手也没有。双方合计 3 个属性劣势回合，全部以劣势方被炸死告终。

### 4. 发育与属性是主要分水岭

| 指标 | 我方（DeepSeek） | 对手（Sol） |
| --- | --- | --- |
| 终局达到 6 / 6 / 3 的回合 | 8 / 10 | 9 / 10 |
| 其他终局属性 | 6 / 6 / 2 ×1；3 / 1 / 0 ×1 | 6 / 3 / 0 ×1 |
| 属性领先的回合 | 1（R5 胜） | 2（g1 R5、g2 R3 胜） |
| 属性持平的回合 | 7（2 胜 1 负 4 平） | 7（1 胜 2 负 4 平） |
| 属性落后的回合 | 2（2 负） | 1（1 负） |

结论：

1. **属性劣势回合 3 个，劣势方全部被击杀，没有任何翻盘。** 这说明本轮的胜负首先由发育竞赛决定，其次才是均势局的战术转化。
2. 双方在 7 个均势回合里合计只打出 3 个胜局（我方 2、对手 1），其余 4 个全部 150 秒平局。**均势局的破局能力仍是最大短板。**
3. `r2-g2` R3 的 `3 / 1 / 0` 不是“均势打不过”，而是根本没发育起来；如果下一轮只能改一件事，优先减少这种崩盘，而不是继续加强均势局的冒险。

### 6. 对本轮 T 模型的评估

第 2 轮提交的 `v2 + R + E + B + T` 中，T 的作用是把“对手当前格炸弹 + 任一可达格炸弹”的联合十字并入陷阱模型，主要目标是减少我方在走廊/口袋中被双弹封死。

从公开战报能验证的部分看：

- 我方作为 **owner 1** 的 `r2-g2` 只死了 1 次（R3），而且那次是 `3 / 1 / 0` 的发育崩盘，不是“口袋里逃不出双弹”的形态；T 的目标场景在本轮没有以可识别的死亡形式出现。
- 我方作为 **owner 0** 的 `r2-g1` 死了 2 次（R4 均势、R5 速度落后），T 并不能解决这两类问题：前者是对手在均势中的战术胜利，后者是属性落后。
- 4 个平局全部是双方 `6 / 6 / 3`，与 T 的保守取向一致：自测中 T 把大量可能死亡的局面转成了 150 秒超时。官方数据也显示，T 降低了可识别的被双弹封死风险，但**没有解决均势局的破局**。

需要强调：没有逐帧回放，无法确认这 3 次死亡中是否有一次实际上是 T 本应防住的双弹陷阱。以上只是根据终局属性和时长的分类。

## 三、实际采用的策略与本轮改动

### 1. 提交形态与协议

- `/workspace/entry.json`：

  ```json
  {"mode":"program","command":["python3","agent.py"]}
  ```

- 程序从 stdin 每行读取一个 JSON 观测，向 stdout 写一行 JSON，恰好 20 帧输入，写完立即 flush；只使用 Python 标准库。
- 非法 JSON 行返回 20 帧中立窗口（`note="badjson"`）；观测结构异常或内部异常时由 `decide()` 兜底返回中立窗口，保证“一条观测对应一条响应”。本轮两局 `errors` 均为 0。

### 2. 策略主体（与第 1 轮后版本一致）

1. **精确爆炸投影**：对已知炸弹逐帧投影引信、十字火焰、硬墙/软墙阻挡、连锁与 12 帧火焰窗口，得到 `danger[k]` 与 `burn[cell]`。
2. **逐帧 Dijkstra 走位**：状态为 `(格, 可行动帧)`，精确复现引擎“移动起步即到达、进度按 IEEE double 累积”的语义。
3. **可证明能逃才放弹**：`escape_plan()` 对“现在放一颗炸弹”的假想局面重新投影，要求存在一条逐帧安全、且到爆炸结束后仍安全的路线；找不到就不放。
4. **对手一弹/双弹陷阱模型**：用对手速度与可达格估计 `enemy_reach`，对每个可达放弹位计算爆炸十字，再用 `escape_field()` 判断哪些格在引信结束前逃不出去；T 额外并入“对手当前格炸弹”的十字。
5. **确定性掉落预测**：按 `(seed, round, x, y)` 的 LCG 预测每面软墙是否掉落及掉落类型，优先拆高价值墙。
6. **追击与残局**：属性领先、距离近、时间晚或地图无软墙时进入 `hunt`；`timeLeft <= 45` 且追击时降低发育权重；只有在“平局等于失败”的明确残局才开启 `desperate` 的有限冒险。

### 3. 第 2 轮提交中已经包含的改动

这些改动在两局正式对局**之前**就已冻结，两局之间没有改策略：

- **R**：`reach_cells` 中第一步只花 1 帧，对应引擎“移动开始的那一帧 x,y 就变成目标格”的语义。
- **E**：对手在引信时间内能完成的移动数改为 `max(1, (FUSE-2)//tc + 1)`。
- **B**：假想炸弹自己所在的格可以通过相邻格“走出来”，不再一律记为不可达。
- **T**（本轮新增）：把对手当前格的炸弹十字也并入每次假想威胁，并把对手当前格视为不可通行：

  ```python
  hz0 = set(blast_shape(tiles, ecell[0], ecell[1], enemy_blast)[0])
  for b in enemy_reach:
      hz = set(blast_shape(tiles, b[0], b[1], enemy_blast)[0]) | hz0
      blocked_b = set(bombcells) | {b, ecell}
      esc = escape_field(tiles, blocked_b, hz, speed)
  ```

- 协议层：非法 JSON 不再 `continue`，而是返回中立窗口；探索 fallback 不再强行避开对手当前格。

### 4. 本轮赛后合入的唯一代码改动：对手半格移动的就绪时间

赛后只改了一处，且**没有改变任何战术参数**：

```python
def reach_cells(tiles, blocked, src, cost, frames, start=1):
    ...
    nt = start if t == 0 else t + cost

# 调用处：
eprog = estimate_progress(enemy)
estart = frames_to_ready(eprog, enemy.get("speed", 0)) if eprog < 1.0 else 1
enemy_reach = reach_cells(tiles, set(bombcells), ecell, etc, 20, start=estart)
```

理由：引擎在 `moveProgress < 1` 时直接返回，不会接受新的方向输入。旧模型对正在半格移动的对手也假设“下一帧就能起步”，会把对手 20 帧内的可达范围高估最多一格，从而把一部分本来安全的格误判为陷阱。新代码用观测到的 `px/py` 估计对手当前进度，再算它还差几帧才能开始下一步。

效果与边界：

- 直接对照 `v2`、`v3`、`wreb` 三个对手 × 双方座位 × 种子 1–8，共 **48 场**，逐回合帧数/胜者与原版**完全一致**；含该修正的组合（`esc1+eready`）在另外 4 个对手（`v2_aggro`、`v3_aggro`、`r1`、`wrebt`）× 2 个座位 × 8 个种子共 **64 场**也完全一致。
- 也就是说，这是“更符合引擎语义、但在现有本地对局中没有产生可观测行为差异”的修正。它**没有经过正式对局验证，也不能声称提高了胜率**；保留它是因为它消除了一个已知的模型高估，且测试中没有回归。

## 五、局限与风险

1. **没有逐帧回放**。公开战报只有 `roundLog` 的回合帧数、胜者、终局属性和比分；没有地图种子、死亡坐标、炸弹归属或双方输入。本文对败因的分类（均势失利、速度落后、发育崩盘）是基于终局属性和时长的可验证推断，不能替代逐帧复盘。
2. **样本很小**。本轮只有 2 场系列赛、10 个回合；每个座位只有 5 个回合，决胜回合只有 6 个。3 : 3 的回合比分和 1 : 1 的系列比分都不能用来推断长期强弱。
3. **对手不同，本地胜负不可外推**。所有自测对手都是自写变体或脚本机器人；Sol 的开局、放弹频率和残局行为未知。T 模型在本地把大量死亡转成平局，但正式对局仍出现 3 次死亡，说明本地分布与 Sol 的分布有差距。
4. **均势破局仍未解决**。4 个平局全部是双方 `6 / 6 / 3`。本轮的 `desperate` 只在“落后或第 5 回合平局且最后 30 秒”开启；对前 3 回合的 0 : 0 平局没有更早的强制求胜手段。是否应该在更早时间放宽安全约束，目前没有可靠数据支持；本地“最后 20 秒平局冒险”测试与原版完全一致，说明仅靠放宽 `allow_risky` 不足以打破这种僵局。
5. **`r2-g2` R3 的 3 / 1 / 0 崩盘没有定位到根因**。可能是开局路线、掉落运气、对手早期压制或我方在低属性时的接战判断。没有回放时贸然增加“弱就逃”的规则，会在本地把负场从 3 增到 8（见第三节表格），因此没有合入。
6. **出生角右侧全胜的样本不可靠**。官方 6 个决胜回合全部由右侧出生方获胜，但本地 64 场同程序自对弈（320 回合、32 个决胜回合）中左侧 18 胜、右侧 14 胜，未复现该偏向。地图墙体是镜像的，但掉落 RNG 使用绝对坐标 `(seed, round, x, y)`，在单张地图上可能偏向某一侧；没有官方种子就无法验证。本轮不据此改策略。
7. **`reach_cells` 修正是“行为等价”的**。它在 48 场直接对照与另 64 场含该修正的组合对照中没有改变任何逐回合结果，因此不能作为“提高胜率”的证据；它只是让对手移动模型更贴近引擎语义。正式对局中是否会产生差异，未知。
8. **`duration` 与模拟时间不是同一口径**。本文用 `roundLog` 帧数 ÷ 20 计算模拟秒数；战报 `duration` 只用于说明执行耗时，不能用来推算游戏内时间。

## 六、结论

- **结果**：`r2-g1` 我方（owner 0）0 : 2 负于 Sol，`r2-g2` 我方（owner 1）3 : 1 胜 Sol；系列赛 1 : 1，回合合计 3 胜 3 负 4 平。两局 0 错误、0 技术故障。
- **最主要的现象**：
  1. **属性决定胜负**：3 个属性劣势回合全部由劣势方被击杀，双方都没有翻盘；7 个均势回合只打出 3 个胜局，其余 4 个 150 秒平局。
  2. **`r2-g2` R3 的 3 / 1 / 0 是最明确的败因**：55.6 秒时仍只有 3 弹、1 火、0 速，与第 1 轮 `r1-g2` R3 的 3 / 2 / 1 形成重复模式，下一轮应优先复查 owner 1 在第 3 回合的开局与发育路线。
  3. **T 模型按设计降低了特定双弹陷阱风险，但没有解决均势破局**；4 / 10 的平局率与自测中的保守取向一致。
  4. **官方 6 个决胜回合全部由右侧出生方获胜**，但本地自对弈未复现，按小样本处理，不据此改动策略。
- **改动**：
  - 第 2 轮正式对局使用的是冻结的 `v2 + R + E + B + T`，两局之间没有改策略。
  - 赛后唯一合入的代码改动是 `reach_cells` 的“半格移动就绪时间”修正：更符合引擎 `moveProgress < 1` 时不接受新方向的语义，消除了对对手可达范围的最多一格高估；48 场直接对照与另 64 场含该修正的组合对照均无回归，但也没有可观测的胜率提升。
  - 赛后测试的 5 类候选改动（弱势不接战、速度掉落加权、弱势撤退、平局末段冒险、`escape_field` 首步修正）全部因负场增加、胜场下降或完全无行为差异而未合入。
- **下一轮优先级**：
  1. 定位并修复 `owner 1` 在第 3 回合的早期发育崩盘（3 / 1 / 0 型），优先保证 55 秒前至少形成可战属性；
  2. 继续观察速度落后时的容错，避免在速度差 ≥1 时进入对手的近距离交战；
  3. 均势 `6 / 6 / 3` 的破局仍是长期问题；在没有逐帧回放前，不继续盲目增加冒险规则；
  4. 若能拿到官方地图种子或回放，优先验证“右侧出生全胜”和“R3 左/上角崩盘”是否与掉落分布或开局路线有关。
