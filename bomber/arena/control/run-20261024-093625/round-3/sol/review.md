## 最终实际采用的策略

沿用 80 帧递归爆炸预测、时间展开生存规划、浮点移动时序恢复、确定性掉落估价、对手未来避难格压缩评分及逐帧输出安全层。本轮实际改动：

1. **提高速度资源优先级。** 速度三级边际价值由 22/20/14 调整为 36/30/20，满速后为零；脚下拾取仍按引擎先拾取、后放弹顺序处理。目标是减少容量已高而速度落后的发育路径，不代表保证每局能获得速度。
2. **扩大盲窗口普通新弹覆盖。** 除对手当前格的假想弹外，加入其一步可达格、移动完成后放置的普通引信假想弹。对这些互斥情形取火焰危险并集，并把对应格标记为可能被炸弹封路；既有潜在连锁扩展预测保留。
3. **加强主动进攻。** 当前格/邻域及路线封锁的进攻分乘 2，纯炸墙分乘 0.85；沿用装备达标、时间不足时减少刷墙的机制。
4. **有限连续放弹。** 已启动一次计划放弹后，若容量允许、距对手不超过八格、距本窗口既有新弹至少两格，可在本窗口第 17 帧前追加，单窗口最多三颗。每颗追加弹都重新运行完整预测与生存规划；安全层随后重查动作，不为增加放弹量取消退路门槛。实际测试证明可以输出多弹窗口，但不是协同必杀搜索。

程序仅使用 Python 标准库；持续逐行读取 stdin，输出一行 JSON、恰好 20 帧并 flush。比赛时不联网、不写工作区。异常兜底会记录 stderr 并输出合法中立窗口，不保证此时存活。

## 实际采用的策略

1. **逐帧爆炸预测**：将现有炸弹、软墙移除、火焰持续与递归连锁按时间模拟到未来 80 帧。递归射线按公开引擎的右、左、下、上顺序处理；连锁中的软墙移除可能让父炸弹后续射线继续深入，不能仅取静态十字并集。
2. **时间展开生存规划**：每格用位掩码表示危险帧与炸弹占位。反向动态规划求各个时刻是否还有可存活路径，再从当前位置前向搜索到炸墙点、道具或进攻点。新炸弹必须在包含其爆炸、余焰的预测中有退路才允许提交。
3. **真实移动时序**：初始速度的浮点累加使走一格实际需要 7 帧，其他速度分别为 5、4、3 帧。保存自己上个窗口的插值预测，处理“视觉上已到中心、实际尚差一帧”的状态。道具只在停稳后的处理帧拾取，速度升级后重新计算后续转向。
4. **资源与进攻**：按自身装备估价道具，优先补速度、炸弹数与火力；利用公开的确定性掉落规则评估软墙价值。炸墙同时考虑朝对手开路，装备足够或临近时限时降低纯刷资源的权重。用穿软墙有额外代价的距离场引导接近，优先在能覆盖对手当前格或邻域的位置放弹。
5. **盲窗口风险处理**：估计对手在本窗口可到达的放弹位置，对会接上现有火线的位置再执行完整递归爆炸模拟，保守避开可能提前扩大的火区。若保守预测无生路，会退回仅根据已知炸弹的预测，避免完全停住。
6. **最终动作安全层**：输出前再次逐帧检查走位、拾取加速与放弹；计划方向不再安全时改用可存活方向，放弹失去退路时取消。按钮只短按一帧，窗口末尾释放，避免上升沿丢失。

### 对当前策略的诊断与拟议改动

以下为结合代码提出的下一版改进计划，**本次未修改 `agent.py`，未把建议冒充已经实现或验证的修复**。

1. **从“命中当前格”改为“压缩未来生存空间”。** 当前 `static_values` 主要给覆盖对手当前格、邻格的放弹位置加分；`decide` 主要选择一个放弹计划。这能解释为何满配后仍可能相互躲避，但不是对两场超时的逐帧归因。拟加入对手可达格、逃生出口数与放弹前后安全区域缩减量评分，先评估单弹有效性，再考虑有限的双弹组合。对应证据：`r1-g2` 小局 1、4，各 **3000 帧 / 150 秒**。
2. **加强盲窗口的对手新增炸弹建模。** 当前 `enemy_risk` 重点覆盖对手在本窗口可达位置放弹、接上已有火线的情况，并非完整枚举普通引信新弹或多颗未来炸弹配合。拟对关键走廊、必经退路添加有限候选，检验其正常到期与连锁两种时序，同时保留计算预算。重点回归：`r1-g1` 小局 2（**938 帧 / 46.90 秒**）、小局 3（**1240 帧 / 62 秒**），以及 `r1-g2` 小局 5（**1284 帧 / 64.20 秒**）的“满配仍死亡”类型；没有回放时不能声称已复现这些死亡。
3. **退路不仅要存在，还要有冗余。** 当前候选放弹和最终安全层已有生存路径验证，应保留，不重复宣称新增了此机制。拟在可存活前提下优先选择具有多出口、较少依赖单格瓶颈的撤离状态；对只有唯一出口且对手可抢占的位置降权。与上一项配套，避免为解决平局而增加自陷风险。
4. **发育阶段按资源缺口与地图局势切换。** 当前代码已经在速度、容量、火力达到一定水平时降低刷墙权重，并在剩余时间少于 55 秒时继续降低，不能写成此前完全没有阶段切换。拟增加满配后纯刷墙收益的抑制，并用对手威胁和路径代价调整拾取优先级。对应 `r1-g1` 小局 4（**1246 帧 / 62.30 秒**）的末态落后与 `r1-g2` 两次满配超时，目标是同时避免“没发育就交战”和“满配仍无效刷墙”。
5. **把系列赛比分纳入风险控制。** 当前决策主要依据本局观察，没有显式按系列赛领先程度调风险。拟从公开 `roundLog` 计算胜负与剩余局数，在领先、平局不计分的规则下避免没有收益的高风险追击；落后且需要胜局时再增加有效进攻权重，而非无条件保守。`r1-g2` 的 **2 胜 1 负 2 平**说明必须按胜局数理解结果；末局死亡本身不等于系列赛失利。
