### 1.3 “射门数据”到底有什么

公开战报**没有**以下字段：射门数、射正数、射门位置、xG、乌龙球。因此：

- 能确认的只有**进球**（比分）和**踢球次数** `kicks`。
- 在不考虑乌龙球的前提下，进球数可以作为“射正数”的下界：`r1-g1` 我方至少 1 次射正、`sol` 至少 4 次；`r1-g2` 我方至少 11 次、`sol` 至少 0 次。真实的射门数/射正数只会更高，无法从战报还原。
- `kicks` 包含开球、解围、传球和射门，所以 `进球/kick` 会**低估**真实射门转化率。例如 `r1-g2` 的 11/12 只能说明“12 次踢球里至少 11 次直接变成进球（若无乌龙）”，不能说明“12 次射门进了 11 个”。
- 本文不根据比分反推“射门次数”，也不编造未提供的射门明细。

## 2. 两局比赛解读

### 2.1 `r1-g1`：2v2、先手、1:4

**数据层面**

- 控球 105 : 943，约 **10% : 90%**；`sol` 把球控制住了约 47 秒。
- 双方 kicks 10 : 11，几乎一样。也就是说，我们并不是“完全碰不到球所以没有踢球”，而是**每次拿到球后很快失去**，或者开球/解围后立刻被对手回收。
- `sol` 的 possession/kick ≈ `943 / 11 = 85.7` 帧（约 4.3 s/次踢球）；我方只有 `105 / 10 = 10.5` 帧（约 0.53 s/次踢球）。这组比例更像“对手长时间护球/盘带后偶尔踢一脚”，而不是“对手频繁传球调度”。
- 进球/kick：我方 1/10 = 10.0%，`sol` 4/11 = 36.4%。在触球次数接近的情况下，对手把少量机会转化成了 4 球。

**代码层面的结构性弱点（推断）**

第 1 轮使用的 2v2 阵型是“1 名门将 + 1 名追球者”。当对手控球时，追球者的旧目标是：

```text
O = 持球者位置
G = 自家球门中心
tgt = O + 0.92 * unit(G - O)
```

即“站到持球者身体靠自家球门一侧 0.92 格”。这个目标在对手正面朝球门时没问题：球在持球者前方 0.62 格，追球者离球不远，进入 0.82 控球圈即可抢断。但如果对手把球藏在**远离我们的一侧**（护球），球到旧目标的距离最远可达 `0.92 + 0.62 = 1.54` 格；而抢断要求追球者比持球者更靠近球 0.12 格，即追球者到球的距离必须 `< 0.62 - 0.12 = 0.50` 格。旧目标在最坏几何下**永远够不到 0.50**，追球者只能一直贴着持球者的身体跑，却碰不到球。

同时，2v2 里的门将默认留在门线附近，不会成为第二抢球点。于是对手可以用一个持球者长时间护球，我们的单追球者被“身体隔开”，比赛就被消耗掉了。这与 90% 控球、kicks 却只有 11 次的数据是吻合的。

**必须保留的不确定性**

- 没有回放，无法确认 4 个失球分别来自开球、反击、远射还是门将失误；上述只是“数据 + 代码行为”下最一致的解释。
- 战报没有乌龙球信息；`sol` 的 4 个进球也可能包含我方乌龙，不能逐球归因。
- team0 在完全对称的开球距离下有数组顺序优势（`nearestEligible` 严格 `<`，team0 在前），但我们仍然只拿到 10% 控球，说明问题主要发生在**开放进攻/防守**，而不只是开球。

### 2.2 `r1-g2`：1v1、后手、11:0

**数据层面**

- 11 个进球、12 次 kicks，进球/kick = **91.7%**；`sol` 12 次 kicks、0 进球。
- 若无乌龙球，11 个进球至少对应我方 11 次直接得分的踢球，12 次 kicks 中最多 1 次是非进球踢球（很可能是开球/解围）。这说明一旦拿到球，1v1 的护球推进和终结非常高效。
- 控球 247 : 48（83.7% : 16.3%），但总控球只有 295 帧（14.75 s）。所以这局并不是“我们控了 100 秒”，而是**大部分时间球在飞/无人控制，我们在少量控球回合里几乎每回合都得分**。
- 作为 team1（后手）还能 11:0，说明本轮对手在 1v1 的开球/反抢环节没有占到结构性便宜，或者我们的 1v1 抢断/护球执行得很好。

**结论**

- 1v1 的现有行为是第 1 轮的**已验证强项**，没有证据支持在本轮后改动它。因此最终改动把 1v1 完全排除在外。
- 但也要注意：1v1 的 11:0 不能证明“我们的 1v1 策略在一般情况下优于 2v2 策略”；它只说明在这一个对手、这一个座位下，1v1 的执行非常有效。人数不同，样本只有一局，不能外推。

## 3. 第 1 轮实际使用的策略（改动前）

- `entry.json`：`{"mode":"program","command":["python3","agent.py"]}`。
- 纯 Python 3 标准库；stdin 逐行读观察，stdout 输出一行 `{"inputs":[...]}` 并 flush；每帧严格 `teamSize` 个单位、共 20 帧；异常时退化为 20 帧中立输入。
- 内部用一个与官方规则一致的简化前向模型推演 20 帧；对手位置按上一窗口速度外推，带瞬移保护。
- 角色：门将（n≥2，粘性选择，半冻结参考球）、追球者、支援/防守者；控球时用屏蔽式朝向把球放在远离对手的一侧，朝对方球门推进，有清晰线路时射门；开球/冻结期有专门处理。
- 赛前准备版在同一套 84 局本地电池上的结果是 **78W 0D 6L，577:65**，与赛前 `review.md` 记录一致。

## 4. 赛后改动（为后续轮次准备）

### 4.1 唯一保留的改动：2v2 追球目标改为“球的门侧”

**文件与位置**：`/workspace/agent.py`，`chase_decide`（约第 515 行），2v2 分支约第 518–526 行；调用处约第 497 行把 `n` 传入。

**改动前**（对手控球，所有人数）：

```text
tgt = 持球者位置 + 0.92 * unit(自家球门中心 - 持球者位置)
```

**改动后**（仅 `n == 2`）：

```python
bp = (ball['x'], ball['y'])
ux, uy = norm_vec(my_gx - bp[0], 13.0 - bp[1])
tgt = (bp[0] + ux * 0.40, bp[1] + uy * 0.40)
```

即：目标点取**球**靠自家球门一侧 0.40 格，而不是持球者身体靠门侧 0.92 格。

**为什么是 0.40**

- 持球者控球时，球在持球者朝向前方 `0.62` 格。
- 抢断条件（引擎）：抢断者到球的距离 `d` 满足 `d + 0.12 < 0.62`，即 `d < 0.50`。
- 目标取 0.40，留出 0.10 格余量；即使一帧移动有离散误差，也仍有机会进入 0.50 的抢断范围。
- 旧目标在对手护球（球在远侧）时可能离球 1.54 格，永远进不了 0.50；新目标则始终贴着球，追球者被迫“攻击球”而不是“贴着人跑”。

**为什么只改 n=2**

- `n=1`：`r1-g2` 的 11:0 已经证明现有 1v1 防守/开球行为有效，没有赛后数据支持改动；保留原逻辑，避免用一局特例去改一个已经赢 11:0 的分支。
- `n≥3`：旧目标的作用是让追球者卡在“持球者—球门”连线上，保持防守层次，避免被一脚传球打穿。本地电池显示 n≥3 的 W/D/L 与进失球在改动前后完全一致；把改动限制在 n=2 可以避免破坏高人数阵型。
- 2v2 的特殊性在于：只有一名非门将追球者，没有第二个人补位；因此“必须直接攻击球”比“保持身体站位”更重要。

### 4.2 试过但**没有保留**的改动：2v2 门将第二抢球点

针对 `r1-g1` 的 90% 控球，曾实现并测试过“门将前压、从球的另一侧夹击”的方案：

- 记录对手连续控球窗口数 `MEM.opp_hold`；
- 当 `n==2`、对手控球、连续控球 ≥2 个窗口、球离自家球门 >18 格、且我方未领先时，门将离开门线，目标取球靠**进攻侧** 0.40 格，与追球者形成两侧夹击；
- 球靠近自家球门或我方领先时，门将不出去。

**测试结果（84 局同一电池）**：

| 方案 | 总战绩 | 进:失 |
|---|---:|---:|
| 只改追球目标（最终保留） | 79W 0D 5L | 579:61 |
| 追球目标 + 门将夹击 | 79W 0D 5L | 577:61 |

W/D/L 和失球完全相同，带门将夹击反而少进 2 球。自定义“预设落后 2 球”的 n=2 场景里，带不带夹击的实际净胜球也没有改善（对 v0 都是 +1，对 noshield 都是 +6）。因此**删除了这套逻辑**，只保留更简单、已被 84 局电池验证的追球目标改动。

这个负结果本身值得记录：在本地对手上，“门将前压夹击”没有带来可测收益，却增加了门线暴露风险；除非后续有官方回放能证明 `r1-g1` 的失球确实来自“单追球者被护球耗死”，否则不应为了故事性保留它。

### 4.3 未改动的部分

- `n=1` 的追球、门将/清道夫、开球行为：完全不动。
- `n≥3` 的追球目标、门将上限、传球、射门、站位：完全不动。
- `entry.json`、协议输出、异常兜底、20 帧 × `teamSize` 的组装：不动。
- 未修改 `RULES.md`、`GAME.md`、`simulation.js`、`catalog.js`、`example.json`。

## 5. 自测方法与结果

### 5.1 方法

- 使用官方 `simulation.js` + `catalog.js`，通过 `tools/match.js` / `tools/bench.js` 按官方协议驱动两个子进程 agent：每次 `sim.view` → agent 输出 → `sim.submitWindow` 校验 → `sim.advanceWindow`。
- 7 个自写对手：`baseline`、`kickbot`、`dribbler`、`park`、`swarm`、`noshield`、`v0`；每个对手在 `n=1..6` 各打两局（交换座位），共 **84 局**。
- 对手均为本地自写脚本，没有读取任何对方代码；`sol` 的代码/回放不可得。
- 引擎是确定性的：固定人数 + 固定座位只有一局，两个座位就是两局；因此 84 局不是 84 个独立样本，不能给置信区间。

### 5.3 n=2 分对手明细（每格 2 局，交换座位）

| 对手 | 改动前 | 改动后 | 说明 |
|---|---:|---:|---|
| `baseline` | 2W，15:0 | 2W，13:1 | 仍全胜，少进 2、多失 1 |
| `kickbot` | 2W，18:1 | 2W，18:1 | 不变 |
| `dribbler` | 2W，16:0 | 2W，17:0 | 多进 1 |
| `park` | 2W，11:0 | 2W，11:0 | 不变 |
| `swarm` | 2W，20:0 | 2W，20:0 | 不变 |
| `noshield` | 1W 1L，6:7 | **2W，13:3** | 最接近“贴身/护球型”的本地对手，提升最大 |
| `v0` | 2W，13:7 | 2W，9:6 | 仍 2W，但净胜球下降 |

**解读**

- `noshield` 是本地最接近“持球者把球藏在身体一侧、我们只有一个人追”的场景；改动后从 1W1L、6:7 变为 2W、13:3，说明“攻击球的门侧”确实能破解单点护球。
- `v0` 有传球/换位，追球者过度贴球会被一脚传球打身后，所以净胜球从 13:7 降到 9:6；这是本次改动的已知代价。因为 W/L 仍是 2W，且失球没有增加（7→6），我们接受这个取舍，并把改动限制在 n=2，避免影响 n≥3 的传球防守。
- `baseline` 的 15:0 → 13:1 也是同一取舍的小样本表现：更主动攻击球会带来更多转换，但也给对手更多一次反击机会。

### 5.4 落后场景的补充测试（自定义，不是官方对局）

为了模拟 `r1-g1` 这种“先落后、对手长时间控球”的状态，写了一个本地“预设落后”跑法：正常开赛，但把 A 方初始比分设为落后 2 球（或 3 球），其余协议不变。下表是 n=2、落后 2 球、交换座位中的一局；括号内为扣除预设 2 球后的“实际进球”。

| 场景 | 改动前 | 改动后 |
|---|---|---|
| vs `v0` | 5:7（我方实际 5，对方实际 5） | 3:4（我方实际 3，对方实际 2） |
| vs `noshield` | 1:5（我方实际 1，对方实际 3） | **7:3（我方实际 7，对方实际 1）** |

6. **门将第二抢球点没有保留。** 它的收益在本地不可测，且会增加门线暴露；如果后续回放证明 `r1-g1` 的控球问题必须靠双人夹击解决，可以再拿官方数据重新评估。
7. **战报字段解释风险。** `stats` 按 `[team0, team1]` 解读；`duration` 单位未标注；`frames=2401` 与 `windows×20=2400` 差 1 帧。本文已按最合理的解释处理，并在正文标注。

### 8.2 核算公式

- 模拟秒数 = `frames / 20`；两局均为 `2401 / 20 = 120.05 s`。
- 控球占比 = 本方 possession / 双方 possession 之和。
  - `r1-g1`：`105 / (105+943) = 10.0%`；`943 / 1048 = 90.0%`。
  - `r1-g2`：`247 / (247+48) = 83.7%`；`48 / 295 = 16.3%`。
- 进球/kick = 进球 / kicks；它不是射门转化率（kicks 含开球、解围、传球）。
  - `r1-g1`：`1/10 = 10.0%`；`4/11 = 36.4%`。
  - `r1-g2`：`11/12 = 91.7%`；`0/12 = 0.0%`。
- possession/kick = possession 帧 / kicks，用来粗略看“每次踢球前持球多久”：
  - `r1-g1` 我方 `105/10 = 10.5` 帧（0.53 s）；`sol` `943/11 ≈ 85.7` 帧（4.29 s）。
  - `r1-g2` 我方 `247/12 ≈ 20.6` 帧（1.03 s）；`sol` `48/12 = 4` 帧（0.20 s）。
