## 1. 本轮实际采用的策略

### 1.1 总体思路（继承 + 本轮修正）

`agent.py` 是一个“物理克隆 + 逐帧规划”的程序：每个决策窗口（1 秒 / 20 帧）拿到观察后，用内置的公开物理模型把未来 20 帧推演一遍，为每名球员排出逐帧输入。核心原则：

1. **能射就射，射门只打门框内、且线路上没人**：`best_shot` 在 y=10.7–15.3 取 11 个目标点，用“球飞行时间 vs 对手可移动距离”算净空，选净空最大的点。
2. **不非法进对方禁区**：所有落点都过 `safe_target`，把点投影到禁区外（`BOX_MARGIN`）。
3. **防守用“卡线路”而不是“追人”**：无球时站在球与自家球门之间；1v1 时站 1.9 格。
4. **解围/传球都走 `kick_to_space` 的“赛跑模型”**：按“球几秒到落点、我们的人几秒能到、对手几秒能到”给落点打分，避免把球踢给对手。

### 1.2 本轮三处代码改动

| # | 位置 | 改动 | 动机（对应第 1 轮的哪条事实） |
|---:|---|---|---|

| 2 | `decide_frame` 1v1 松球分支（约 1044–1060 行） | 松球时先算**落点 `end` 和拦截点 `ipt`**：只有我们确实抢先（`myd <= fxd - 0.6`）才去抢；抢不到就退到**落点与自家球门之间 2.4 格**卡位，不再按“球当前在哪”决定姿态。 | 第 1 轮 1v1 的“卡线路”是按**球当前位置**算的：球朝对方球门滚时，“球与自家球门之间”就在球的**后面**，于是我们永远追在球后 4–9 格。 |

## 2. 自测方法

### 2.1 工具

- `tools/harness.js`：用**公开的** `simulation.js` 跑真实比赛，外部程序按 `stdin/stdout` 一行一个 JSON 交互，和官方协议一致。
- `tools/arena.js`（本轮新增）：批量跑“我方 vs 陪练”，**每个 size 各打两个座位**，汇总 W-D-L 与进失球。
- `tools/sol_like.js`（本轮新增）：按第 1 轮公开战报里观察到的 sol 行为写的陪练（落点争抢 + 边角长球 + 门将站线路）。**这是我自己的复刻，不是 sol 的代码**。

```bash
# 单局
node tools/harness.js --p0 "python agent.py" --p1 "bot:pro" --games 2 --teamSize 5
# 全套（1–6 人 × 双座位）
node tools/arena.js --agent "python agent.py" --opp "bot:sol" --sizes 1,2,3,4,5,6 --seeds 1 --verbose
```

### 2.2 确定性说明

`simulation.js` 无随机数；同一 `seed + teamSize + 双方输入` 逐帧完全一致。`seed` 只影响开球方（`seed % 2`），所以同一 size 的样本远少于局数：在 n≥2 的几个 size 上我抽查过，不同 seed 的比分、起脚数、控球帧数**完全相同**；1v1 因为开球方不同会出现不同局面（例如 `bot:sol` 陪练在 seed 101 是 2:12、seed 108 是 4:9）。`arena.js` 的 `--seeds 16` 因此只是把 1–2 个真实局面重复计数。本文所有对比按“**每个 size × 座位（+ 1v1 的开球方）= 1 个场景**”解读，不做显著性推断。

### 2.3 陪练

| 名称 | 说明 |
|---|---|
| `bot:balanced` | 仓库自带：无球人直冲球、持球人打远角。**直冲抢断型** |
| `bot:pro` | 仓库自带：持球人推进到射程内起脚，门将站球线，逼抢者站球前 0.55 格 |
| `bot:pro?pressN=2&shootRange=17&laneClear=0.6` | 高压变体：两人逼抢、射程更远、对线路净空要求更低 |
| `bot:sol` | 我按第 1 轮战报复刻的 sol 风格：全队抢落点、边角长球、门将站线路 |

## 3. 自测结果

### 3.1 主结果：新版本 vs 旧版本（每格 12 局：6 个 size × 2 个座位）

| 陪练 | 旧版本（第 1 轮提交，`tools/base_r2.py`） | 新版本（本轮 `agent.py`） |
|---|---|---|
| `bot:balanced` | 11-1-0，进 33 失 1 | **11-0-1，进 57 失 12** |
| `bot:pro` | 10-1-1，进 27 失 6 | **12-0-0，进 32 失 7** |
| `bot:pro` 高压变体 | 9-3-0，进 26 失 5 | **10-2-0，进 42 失 6** |
| `bot:sol`（自写） | 11-0-1，进 29 失 6 | **11-0-1，进 47 失 5** |
| **合计** | **41-5-2，进 115 失 18** | **44-2-2，进 178 失 30** |

- 新版本每个陪练的**进球都明显变多**，胜场更多；代价是**失球变多**（18 → 30），主要来自下面 §3.2 的 1v1 那一局。
- 新 vs 旧**直接对打**（同一套 12 局）：**5-5-2，进球 5:2**。没有出现“新版被旧版克制”的情况，但也没有压倒性优势——两版在 n≥2 的骨架是同一套。

### 3.2 1v1 专项（第 1 轮 0:5 的那条链路）

| 配置 | 对 `bot:sol`（自写） | 对 `bot:balanced` | 对 `bot:pro` |
|---|---|---|---|
| 旧解围规则（对手 5.5 格内就起脚解围，其余同新版） | 2:0 / 2:1 | 3:2 / 0:2 | 3:2 / 3:2 |
| 新版（持球不踢，只在有射门线路时起脚） | **10:0 / 10:0** | **1:11 / 9:1** | 7:2 / 5:4 |

> 上面两行只差“贴身是否解围”这一条规则（同一次实验、同一组 seed），所以可以直接对照；第 1 轮实际提交（`tools/base_r2.py`）在 1v1 对 `bot:sol` 是 5:3（两局合计），对应的是“旧解围规则 + 更早的松球逻辑”，见 §3.1。

- 对“抢落点 + 长球”型陪练，新版把 1v1 从 2 球小胜变成 10 球大胜：因为球权不再白送，对手没有二点球可抢。
- 对“直冲抢断”型陪练，新版出现一局 **1:11**：我们在中场被断球后，对手 18–20 格外的长球直接打进空门。这是本轮最明确的风险，见 §4。

### 3.3 1v1 参数扫描（决定性、非随机）

- **防守卡位距离**（对手持球时站在球与自家球门之间的距离）：在**最终配置**下对 `bot:pro` 各跑 16 个 seed（32 局，1v1 里 seed 只改开球方，实际是 2 个互不相同的局面）：
  `0.5 → 16-0-16（144:144）`、`0.8 → 16-0-16（80:144）`、`1.5 → 16-0-16（112:176）`、**`1.9 → 32-0-0（192:96）`**、`2.2 → 32-0-0（240:32）`、`2.5 → 0-0-32（0:304）`、`3.2 → 0-0-32（0:320）`。
  对 `bot:pro` 而言 2.2 比 1.9 还好，但换成 `bot:sol`（自写）做同样的对照，2.2 在 a 座 **3:9 负**、1.9 是 **10:0 胜**，所以最终**沿用 1.9**（更近会被带球人撞开/绕过，2.5 以上会退成 0 射门的单方面挨打）。
- **松球姿态**（最终配置，对 `bot:sol` 自写陪练，4 个 seed = 8 局）：永远追落点 `4-0-4（46:56）`；“落点在对方半场或我们更快就追” `4-0-4（46:56）`；**只在确实抢得先时追、否则卡位 `8-0-0（80:0）`**。结论：**“抢不到就卡位”是必须的**，无脑追落点会被打穿。
- **贴身解围阈值**（对手离我多远时解围）：0 / 1.0 / 1.5 / 2.0 / 2.5 / 5.5 格，四种陪练各两局。没有阈值能在四种陪练上都不吃亏（例如 2.5 格对 `bot:balanced` 是 2:2 / 0:2，对高压 pro 是 1:4 / 1:3；5.5 格对 sol 陪练只有 2:0 / 2:1，但正是第 1 轮被 0:5 的打法）。最终选 **0（持球不踢）**。

### 3.4 n≥4 出球点专项

| 配置 | `bot:pro` | 高压 pro | `bot:sol` | `bot:balanced` |
|---|---|---|---|---|
| 无出球点（旧） | 7-1-0 | 6-2-0 | 7-0-1 | 8-0-0（进 26） |
| 出球点 n≥4（采用） | **8-0-0** | **7-1-0** | 7-0-1 | 8-0-0（**进 44**） |
| 出球点 n≥3 | 8-0-0 | 8-0-0 | 7-1-0 | 7-0-1 |

n≥4 时启用最稳：n=3 只有两名场地球员，抽一个去当出球点会让禁区前沿只剩一人，实测对 `bot:balanced` 会多输一局（2:3 金球）。

### 3.5 工程性自测

- **协议**：用 `example.json` 的起始观察连续喂 5 次，每次输出 20 帧 × `teamSize` 个单位的合法 JSON，`dir`/`aim`/`kick` 全部合法（`aim` 归一化到 0–359）。
- **延迟**：单次响应 **约 10 ms**（含物理推演 20 帧），远低于 5 秒硬上限。
- **鲁棒性**：`status != playing` 时输出中立窗口；`compute_window` 单帧异常时该帧降级为中立，不会整场技术负。
- **受保护文件**：`RULES.md` / `GAME.md` / `simulation.js` / `catalog.js` / `example.json` / `entry.json` 的 SHA-256 与 `manifest.json` 全部一致。
- **自对弈**：1–6 人各 2 局无崩溃、无犯规；1v1 自对弈 0:0（双方都持球不踢），n≥2 为 0:0–2:1 的低分对局。

## 4. 局限与已知风险

1. **对手全是自写陪练，不是 sol。** `bot:sol` 是我按第 1 轮公开战报里“抢落点、边角长球”的行为复刻的，**没有读取对方任何代码**；它像不像 sol 无法验证，本文所有比值都不能外推成对 sol 的预期。
2. **样本极少且确定。** n≥2 时同一 size + 座位只有一局不同样本（`seed` 只改开球方）；1v1 因为开球方不同会多出 1 个局面。§3 的“12 局”实际是 6 个 size × 2 个座位重复计数。这些数字用于**否决明显更差的改动**，不足以做显著性判断。
3. **1v1 对“直冲抢断型”对手会崩。** `bot:balanced` 用 1.9 格的直冲把我们在中场的持球断掉，随后 18–20 格长球打空门，实测一局 1:11。根因是决策窗口 20 帧内对手的实际移动不可见（我们的推演假设对手不动），被断球后要等下一个窗口才反应。**如果 sol 的 1v1 也是这种直冲逼抢，这一局会很难看。** 我尝试过“贴身解围”“绕开防守人”“按逼近速度解围”三种修法，都会在另外两种陪练上换来更大的损失，最终没有采用。
4. **n=3 的犯规任意球二点球抢不到。** 对手带球进我方禁区造犯规后，球被放在禁区外最近的任意球点（x≈33.1），犯规者只被移到 1.3 格外；我们最近的场地球员通常在 8 格外，0.6 s 冻结结束后对手先到。自测里 `bot:sol` 唯一的 0:1 就是这条链路。n≥4 的出球点能顺带缓解，n=3 没有好的解法（加固定清道夫会在 n=6 掉分）。
5. **进攻仍然依赖“长球 + 二点球”。** 第 1 轮 5v5 的 0 射门是“被压扁 + 二点球抢不到”的复合结果，本轮只改了“留一个出球点”这一半；如果 sol 继续用全队前压，效果要等第 2 轮官方对局才能验证。
6. **没有第 2 轮官方数据。** 本文不含任何第 2 轮比分或复盘结论；赛后另写 `postmatch.md`，并把本文件保留为赛前说明。
