## 2. 对比赛机制的要点理解

- 服务器 20 Hz，双方每 1 秒（20 帧）同时提交逐帧输入，之后统一推进 20 个物理帧。对手在本窗口内的输入在提交时已经固定，因此**存在约 1 秒的决策延迟**；已经踢出的近距离射门在越过门线前往往来不及反应，守门员必须提前选位。
- 球速 11 格/秒、每帧摩擦 0.978，单次踢球大约只能飞 25 格；因此几乎所有踢球都是"长传/远射"，不存在轻推短传。撞墙保留 0.72 速度，反弹球仍然危险。
- 控球半径 0.82 格；抢断需要比持球者更近 0.12 格；持球时球贴在朝向前方 0.62 格处，持球移动速度只有 1.83 格/秒。
- **犯规检查在球权更新之前**：对手踏入我方禁区会被立刻判罚，因此我方禁区是安全的控球区；反过来，我方程序从不进入对方禁区。
- 守门员（index 0）**没有额外扑救半径**，和其他人一样是 0.82 格，只能靠站位和移动扑救。
- 进球判定是球心 x≤1（左门）或 x≥43（右门）且 y 在 10.5–15.5；球门线附近的站位误差 1 格就可能决定胜负。

## 3. 实际采用的策略

### 3.1 自带物理模型 + 20 帧前向预测

`agent.py` 内置了一份与 `simulation.js` 对齐的确定性物理实现（移动、撞墙滑动、球体子步推进、摩擦、控球/抢断、踢球冷却与控制锁）。每个观察到达后：

1. 用观察重建世界（坐标、朝向、球权、冷却时间按 1/20 秒换算）。
2. 从当前帧的决策出发，预先排好 20 帧的逐帧动作，逐帧向前模拟；我方输入按计划执行，**对手单位在窗口内按静止/中立处理**。
3. 预测到进球即停止；同时用 `ball_path` 模拟球在无干扰下的完整轨迹，用于射门/传球线路的净空判断。

对手建模偏保守（不假设对手会移动），避免"模拟里能抢到、现实里抢不到"的乐观错误。

### 3.2 角色与无球移动

- **守门员（index 0）**：始终留在本方禁区附近，站位在"球门中心—球"连线上、离门线约 0.55–1.3 格；当球是松球且朝我方球门运动（或已进本方禁区）时，用预测轨迹求拦截点并出击。守门员不参与前场进攻。
- **场上球员**：选择离球最近的至多 2 人上抢，且尽量从**球门一侧**接近持球者；其余人保护中路与射门线路。所有人按"离对方禁区保持 0.85 格安全边距 + 4 帧前瞻"的规则移动，绕行对方禁区时再外扩 1.2 格，保证绝不踏进对方禁区。
- 移动被墙阻挡时，程序会尝试单轴替代方向；所有目标点、拦截点都经过禁区安全过滤。

### 3.3 持球决策

- **射门**：在射程内且模拟线路净空足够时，枚举 36 个方向（10° 步长）模拟球的完整轨迹，按"前进量 + 靠近球门中心 + 线路净空 + 是否直接进球 − 落入对方禁区 − 落点附近有对手"打分，选最优角度射门。
- **传球**：存在净空更好的队友线路时传给队友，同样用轨迹模拟检查中途是否会被对手碰到。
- **带球**：向对方球门方向推进，但目标点始终停在对方禁区外（边线一侧留出 1.6 格以上）；附近有对手时，把朝向调整为背对对手的护球方向。

### 3.4 防守决策

- 对手持球：最近的 1–2 人去压迫；如果我方某人明显更接近球则直接上抢，否则站在球与己方球门之间的封堵点。
- 松球：球在移动时用预测轨迹求拦截点；球静止或很慢且双方距离接近时，**不贸然越过球**，而是保持球门一侧 1.9 格的封堵位，等对手先动。这条规则修复了早期 1v1 中"追球追过头、被对手从身后打空门"的实际问题。

### 3.5 1v1 专用逻辑

- 我方持球：射程内且线路净空就射；有对手在 5.5 格内时，用 36 方向模拟把球踢过对手并前追；否则带球到进攻边线附近并护球。
- 对手持球：球在我方半场深处就上抢，否则站在球与球门之间 1.9 格的封堵点。
- 松球：明显更近才上抢，否则守住球门一侧。

### 3.6 容错与协议安全

- 每帧输出前统一清洗：`aim` 为有限数值时取模到 0–359，否则置 `null`；`dir` 不在合法集合时改为 `N`；`kick` 强制转布尔。保证不会因为非法字段被判技术负。
- 任何异常都退回 20 帧 × 本队人数的中立输入；非法 JSON 行直接跳过；日志只写 stderr；进程正常退出。

### 4.5 性能与协议

- 单次决策耗时（在转储的真实观察上进程内测量）：n=1 平均 0.4 ms / p95 0.5 ms / 最大 0.6 ms；n=3 平均 1.0 / p95 1.1 / 最大 1.3 ms；n=5 平均 1.3 / p95 1.4 / 最大 1.7 ms。远低于 5 秒硬上限。
- 协议测试：
  - 正常观察 → 恰好 20 帧 × teamSize 个单位；
  - `status=finished` → 中立 20 帧；
  - 缺少 `units` 等字段的畸形观察 → 仍按 `teamSize` 输出中立 20 帧，不崩溃；
  - 非法 JSON 行 → 不输出该行，后续合法观察仍正常响应；
  - 全程 stderr 为空，进程退出码 0；
  - 所有 `aim` 均为 `null` 或 0–359 的有限数值。

## 5. 已知局限

1. **对手在窗口内被当作静止**。预测不会考虑对手下一拍的上抢、传球或射门，因此偏保守；近距离被射门时尤其明显。
2. **1 秒延迟导致的近距离失球无法根除**。4.3 节的金球失利就是对方在禁区外侧翼近距离起脚，球在约 1 秒内越过门线，守门员来不及横移。离线未能稳定修复，且针对该 bot 的射门习惯调参有过度拟合风险，故保留现状。
3. **1v1 与部分人数可能僵持**。自对弈 n=1/2/4/5 出现 0:0；如果真实对手也选择不主动压上，比赛可能以平局结束。
4. **测试对手过于单一**。只与两个简单内建 bot 和自对弈交过手，没有与真实对手对局；真实策略可能完全不同，现有参数存在过拟合风险。
5. **没有主动造犯规战术**。对手踏入我方禁区时我们能获得任意球，但程序不会刻意引诱对手犯规；这既是稳健选择，也放弃了一种得分手段。
6. **定位球/开球处理较朴素**。开球和任意球阶段主要按普通进攻逻辑处理，没有专门的战术设计。
7. **尚无正式对局**。本文件不包含任何真实比赛复盘；`postmatch.md` 将在赛后按实际结果补写。
