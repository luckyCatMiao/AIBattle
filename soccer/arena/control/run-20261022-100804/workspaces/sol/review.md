# 第三轮提交说明与离线自测

## 状态

已完成程序提交文件 `entry.json`。启动命令为 `python3 agent.py`；Python 入口使用 exec 启动同目录的自写 `agent.js`，由 Node.js 持续读取观察并逐行输出、即时写出 JSON。运行不访问网络、不写工作区，也不加载公开模拟器；公开模拟器仅用于准备期自测。

目前没有收到本轮正式比赛结果。下文所有比分和统计都来自实际运行的离线自测，不能作为正式比赛复盘。`public_results.json` 是空数组，没有据此推断对手策略。

## 实际采用的策略

1. **统一进攻坐标**：右侧球队镜像到向右进攻的坐标，最后将移动与角度转换回来。人数严格读取观察的 `teamSize`，支持 1–6 人。
2. **逐帧预测**：每次从观察重建状态，在内部推进 20 个物理帧，每帧重新安排己方动作，同时用启发式预测对方。实现持球减速、踢球冷却、控球锁、球摩擦、墙面反弹、普通半径控球、抢断和球员分离。它是近似预测器，不是修改或引用裁判。
3. **争球**：预测自由球约 4.5 秒轨迹，寻找球员可赶上的拦截点；按预计到达时间挑选主追球者，多人局允许第二人协防，其他人保持接应或防线。
4. **防守**：2 人起保留 index 0 为主要门将；根据球的位置站在球与球门的连线上，来球进入本方禁区时寻找截球点，近距离持球威胁时上前。单人局不能同时保留门将，只能争夺控球。
5. **进攻**：在有效门口 y=10.65–15.36 采样精确角度，按射线路径、对手距离、球摩擦导致的飞行时间及对手移动能力估计射门余量。持球受压时优先寻找空位、护球或明确安全的向前传球；本方门前受压时解围。单人局取消贴身强行射门，避免球刚踢出就被对手没收。
6. **禁区避让**：目标点投影到合法区域，逐帧检查下一步位置，并留出安全边距；使用适合八方向移动的距离代价，避免争球时横向修正太晚。仍不能保证碰撞推挤后绝对零犯规。

## 实际运行的测试

使用未修改的 `simulation.js` 创建完整比赛，调用 `submitWindow` 验证每个窗口，推进至常规时间或金球结束。自写测试对手均未读取任何对方文件：

- `rush`：全员追球，拿球持续向门中央踢。
- `corners`：全员追球，拿球持续瞄准门口另一侧。
- `balanced`：保留门将，其他人追球，靠近射程后射门。
- `defense`：一人追球，其余人收缩到门前。
- `self`：当前策略与自身对战。

最终回归命令：`node test.js rush corners balanced defense self`。

每类对手覆盖 1–6 人和双方座位，共 12 场；种子为 41 + 人数。完整结果保存于 `test_results.json`。

| 对手 | 场数 | 胜 / 平 / 负 | 我方进球 / 失球 | 我方犯规 |
| --- | ---: | --- | --- | ---: |
| rush | 12 | 12 / 0 / 0 | 69 / 12 | 5 |
| corners | 12 | 12 / 0 / 0 | 85 / 3 | 0 |
| balanced | 12 | 12 / 0 / 0 | 83 / 4 | 0 |
| defense | 12 | 10 / 2 / 0 | 39 / 1 | 0 |

自对战对同一固定种子的双方座位分别报告，因此其中实际上包含重复轨迹，不是 12 个独立样本；自对战胜负并不表示相对自身变强。密集防守的两场平局都是 6 人局 0:0，暴露出破密集防守能力不足。

额外命令：`node stress.js`。种子 101、202、98765，各覆盖 1–6 人和双方座位，共 36 场；奇数种子对 `corners`，偶数种子对 `rush`。实际结果：36 胜、0 平、0 负，进球 229、失球 18、犯规 5。原始记录保存于 `stress_results.json`。

最终合计运行 96 条完整比赛测试记录，含上述自对战重复记录。回归中内部决策最大耗时约 4.2 毫秒，额外种子测试最大约 3.0 毫秒；这只是在当前准备环境测得的数值，不代表比赛机器性能保证。

另外通过真实 `python3 agent.py` 持续进程输入 12 条观察，覆盖全部人数与双方座位，检查每条恰好 20 帧、每帧人数正确、方向合法、角度在 [0,360)、kick 为布尔值。全部通过，实际测得最大完整响应约 0.006 秒，远低于 5 秒限制。

## 调试中发现并修正的问题

- 初版单人局对立即射门型对手失利：贴身强行射门容易被挡回，且下一秒内对方行动预测失真。修正单人护球策略和单人对手模型。
- 原先按欧氏距离贪心移动，常常接近中圈后才修正纵向位置，造成争球失位。改为八方向距离代价。
- 双人局原先没有固定门将，出现远射漏防；改为双人起保留主要门将，最终双人回归对四种基线均获胜。

以上早期现象不计入最终表格；最终表格对应当前提交代码重新运行的结果。

## 局限

- 对方动作并不可知，预测器不是实际对手；尤其一秒窗口内突然传球、转向、射门可能让后半窗口动作失效。
- 观察不提供全部内部锁定状态，当前重建中对抢断锁、犯规锁作了近似；开球方推断也未完整追踪所有重开球事件。
- 内部预测发现进球后不完整重建下一次开球，余下动作可能偏离真实重置后的站位；下一次观察会重新纠正。
- 禁区目标约束不能抵消全部球员推挤，实际测试仍有少量犯规，不能声称零犯规。
- 没有穷举反弹射门、多步传切和所有敌方行动；面对大量门前守卫可能长时间无法进球。
- 基线对手是自行编写的有限启发式，不代表正式对手。固定种子测试及高度相关的重复对局不能推断正式胜率或模型综合能力。
