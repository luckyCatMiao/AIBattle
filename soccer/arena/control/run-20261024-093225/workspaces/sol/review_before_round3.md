### r2-g1：控球优势未转化为进球，金球阶段也有险情

- Sol 控球累计 290 帧，对手 115 帧，约为对手的 2.52 倍；但双方都只出脚 25 次，全场无进球。这个结果说明控球和推进并没有兑现为突破门将的终结，不能把持球领先当作进攻已经成功。
- 对手门将共 7 次触发扑救：第 **389 / 1313 / 1547 / 1810 / 1889 / 2135 / 2671 帧**，分别为 **19.45 / 65.65 / 77.35 / 90.50 / 94.45 / 106.75 / 133.55 秒**。上下半场和金球阶段都出现被门将没收的来球；说明已有制造门前压力的能力，但射门线路、出手时机及二次进攻仍未解决对方门将。
- Sol 门将在第 **2456 帧、122.80 秒**完成唯一一次记账扑救，发生在金球开始后的 2.80 秒。虽然对手控球更少，也曾在突然死亡阶段形成威胁；不能说这是一场毫无失球风险的平局。
- 正面结果是 140 秒零失球、零犯规、零协议错误；主要不足是进攻效率与僵局处理，而不是程序稳定性。仅凭这些统计无法断言所有未进球都由同一个射门评分缺陷造成。

### r2-g2：扑救后回收二次球，禁区外斜射得分

本场实际是 5v5，不能直接当作首场交换座位后的完全同条件对照。Sol 控球 302 帧，对手 155 帧，约为对手的 1.95 倍；出脚反而更少（26:39），最终取得唯一进球。

进球前的可核验事件链：

1. 第 **1654 帧、82.70 秒**，Sol `t0u2` 从球坐标约 **(35.125, 1.851)** 出脚。
2. 第 **1676 帧、83.80 秒**，对手门将 `t1u0` 记录扑救；这是其全场第三次扑救，前两次为第 **351 帧、17.55 秒**及第 **1030 帧、51.50 秒**。
3. 第 **1677 帧、83.85 秒**，对手门将在约 **(41.424, 9.967)** 出球，方向角约 2.723 弧度（向左下）。
4. 第 **1703 帧、85.15 秒**，Sol `t0u3` 从球坐标约 **(31.603, 13.682)** 出脚，方向角约 **−0.260 弧度（−14.9°）**，向右上方球门斜射。这一出脚最终被明确验证为进球射门，而非仅凭 `kick` 事件推定。
5. 第 **1730 帧、86.50 秒**，球已到约 **(42.803, 10.703)**，对手门将在约 **(42.520, 11.913)**，未能贴住来球线路。第 **1731 帧、86.55 秒**触发进球，记给 **Sol `t0u3`（index 3，即第 4 名球员）**，`ownGoal:false`，比分变为 **1:0**。射出到得分历时 **28 帧、1.40 秒**。
6. 余下 **33.45 秒**未再进球，Sol 将 1:0 保持到第 2400 帧、120 秒结束；没有进入金球。

这次得分的关键可观察现象是对方扑救出球后，Sol 在前场重新获得出脚机会，并从对方禁区外打出避开门将位置的斜线。Sol 全场 0 次 `save` 不等于对手没有射门或威胁，只能说明没有符合引擎条件的门将扑救事件。

### 我的实际改动、效果与后续建议

**本轮赛前已经实施的改动**（已对照 `agent_round2_base.js` 与 `agent.js`）：

- 在多人局原有候选之外，新增 `mirror/link` 与 `chase/link` 两套候选；仍通过原先多对手模型的最差情况与均值评价选取，不强行启用。单人局不增加这两套候选。
- `link` 的无球接应从固定纵向分布改为围绕持球位置前移、上下错开；目标横坐标约为球前方 7 或 9 格，并保留边界约束。
- `link` 不再只在紧迫受压或门将出球时寻找前传；传球评分加入双方到目标点的估计时间差，以及接球队友的射门评分。
- `link` 的射门评分阈值由普通策略的 **−0.12** 放宽到 **−0.45**；原有候选、20 帧预测及最终禁区约束保留。

**不能过度归因：**本轮正式结果是 **1 胜 1 平、总进球 1:0**，两场均零犯规、零程序错误。首场仍陷入零进球僵局，次场的二次进攻与接应改动的目标一致，但回放不记录最终采用的候选标签，也没有同种子关闭 `link` 的正式对照；不能宣称该进球必然由 `link` 产生，或声称新增策略已经证明全面有效。

**后续改进方向（尚未实施、尚未测试）**：优先将射门、传球、解围按可复现标准分项统计，并为候选选择增加仅写 stderr 的离线调试记录；针对对手门将连续没收来球，增加门将横移与二次球回收的专项测试；再评估更长射门飞行时间的前推及金球阶段的风险权衡。不要仅凭两场结果盲目提高出脚频率，也不要把未实现的领先控时模块写成已采用策略。

## 实际采用策略

### 原有基础

1. 将左右座位统一为向右进攻的坐标系；实际人数严格使用观察 `teamSize`，支持 1–6 人。单人局 index 0 同样追球进攻，多人局 index 0 主要守门。
2. 依据公开 `simulation.js` 恢复观察状态，包括统计、冻结、冷却；依据公开事件近似恢复开球方、抢断锁、犯规锁。
3. 每个窗口在本地逐帧模拟 20 帧，产生多套完整输入序列。候选包括旧策略、普通策略、积极射门及偏边进攻；模拟不同的预测对手（旧策略、积极出脚、追球）。
4. 每个候选按三个对手模型前推 50 帧，综合最差结果和均值评价。进球、失球权重最高，辅以球场推进、持球、截球时间、犯规与门将位置。
5. 射门扫描多个精确门内目标，估计摩擦后的到达时间及对手可达区域；持球受压时选择向前传球或解围，否则接近禁区前沿、绕向边路。用精确角度而非八向射门。
6. 无球者追预估落点，多人局保持门将、追球者、接应者和后侧保护。门将依据球的预测线路移动，拿球后通常快速出球。
7. 最后对整段输入做保守禁区约束，兼顾持球与无球速度差，避免预测失误后闯入对方禁区。

### 本轮新增：可选的接应/出球候选 `link`

- 原策略完整保存在 `agent_round2_base.js`。
- 仅在多人局加入两套新候选（分别以普通和追球对手生成），并不强制所有回合使用。
- 接应目标随持球者的位置前移，并在其上下错开，替代该候选中的固定纵向分布。
- 该候选允许在未紧迫受压时寻找向前传球；传球评分加入双方到接球点的距离时间差，并小幅考虑接球队友的射门线路评分。它只是接球可达性的启发式，不是完整传球落点求解器。
- 新候选射门阈值略放宽；其他候选和最后的安全约束仍保留。候选通过相同的最差情况/平均评价竞争，降低无条件改阵型的风险。
- 单人局不加入新候选，沿用原先搜索。

## 实际离线对抗

自编 `round2_compare.js`；完整 120 秒比赛，平局按引擎进入金球，覆盖人数 1–6、左右两个座位。每组种子、每类对手各 12 场。

四类独立基线：
- `old`：本工作区自有旧策略 `agent_r1.js`，同样每秒输出 20 帧。
- `corners`：自编追球与向门内偏角出脚基线。
- `swarm`：自编多名球员围抢基线。
- `oracle`：旧策略每个物理帧获得真实新状态作出反应，特意给测试对手比正式协议更强的信息条件；不是正式赛制。

普通基线有相同的一秒开环限制，并只使用自己的预测状态。没有使用或猜测对方文件。

## 协议、安全、耗时验证

- `node round1_validate.js`：240 个随机状态，覆盖 1–6 人及双座位；另检查真实 example 与历史统计恢复。全部通过，最大决策 151.82 ms。
- `python current_r1_protocol.py`：实际 `python -> Node` 常驻进程连续 6 次请求，20 帧输出合法；正常退出、stderr 为空。首次约 96 ms，后续约 25–30 ms。
- `python round2_protocol_sizes.py`：一个常驻进程连续接收 1–6 人 × 双座位的 12 个观察，全部按实际人数输出；正常退出、stderr 为空。首次约 73 ms，其余约 8–31 ms。
- 尺寸协议测试第一次因测试脚本默认 GBK 读取 UTF-8 观察而失败（UnicodeDecodeError）；已显式指定 UTF-8 后重跑通过。这是测试文件编码问题，比赛程序没有相应异常。
- `node round1_edges.js`：48 个边界场景（高/低线路来球、禁区前持球、冻结）全部跑完，本方 0 犯规；不将跑完场景等同于每条来球都被扑住。
- `node round2_transitions.js`：24 个半场、金球、进球重置及对方犯规场景，每例推进三个窗口；全部完成，本方 0 犯规。
- 本轮新版所有完整比赛对抗中最大实测决策 193.31 ms，保留版最大 161.19 ms；均低于 5 秒。耗时受机器负载影响，不构成绝对上界。

## 局限与最终选择

1. 未知对手的实际策略不在模型集合中，一秒开环内抢断、碰撞和出球后的误差仍会积累。
2. 门将并没有特殊控制半径。现有门将拦截是近似路径方案，不保证应对所有角度和连续传射。
3. 射门/传球的对手可达性是启发式，可能过于保守或乐观；接应得分增加不等于成功传球次数已被独立验证。
4. 对强旧策略和每帧反应对手仍有较多平局，直接交锋多人局全为 0:0；短搜索与固定终点评价可能偏好僵持。
5. 无专门的领先控时或落后搏命模块。禁区约束虽然本轮测试零犯规，也不是任意拥挤碰撞下的形式安全证明。
6. 测试对手均为自编策略而非真实对手；两组种子和左右座位存在相关性，不能推断模型总体能力。

赛前最终保留 `link` 作为可选候选：同条件合计增加 4 胜、29 个进球、少失 1 球，未出现额外犯规或超时；但不宣称它全面优于旧版。正式第 2 轮结果现已补记于文首，不与上述自测混算。
