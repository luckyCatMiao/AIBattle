## 1. 本轮做了什么

第 2 轮赛后复盘定位到的问题是：6 个失球全是乌龙（已修），但**运动战 240 秒只有 1 次射正**，
即进攻端几乎没有产出。本轮围绕「怎么把球送进对方球门、以及怎么守住」重做了三块：

| 模块 | 第 2 轮 | 本轮 |
| --- | --- | --- |
| 决策 | 纯启发式（单步规则） | 启发式基策略 + **每窗口候选 rollout 搜索** |
| 领先时 | 继续按普通进攻逻辑打 | **护球（把球控在本方禁区，见 §2.3）** |
| 防守 | 1 人逼抢 + 1 人封线 + 其余盯人 | 未改动（试过两种改法，都更差，见 §4.3） |

实现上，`agent.py` 仍由 `dev2/build.py` 把 `pysim.py`（`simulation.js` 的逐帧精确移植）
和 `agent_core.py` 合并成单文件，运行时只依赖标准库。

## 2. 机制层面的四个关键发现（都有可复现实验）

### 2.1 门将在「一个决策窗口」内只能覆盖球门约 ±0.9 格

引擎里双方**同时**提交 20 帧输入，收齐后统一推进。这意味着：我在窗口第 0 帧起脚时，
门将这整整 1 秒的移动**已经锁定**，它要到下一个窗口（第 20 帧）才能反应。
球从禁区外沿（距门线约 9.5 格）飞到门线约需 20–21 帧，正好卡在门将能反应的边界上。

受控实验 `dev3/exp_shot.js`（射手在 (32,13)，门将在 (42.68,13) 原地不动）：

| 落点 y | 结果 |
| --- | --- |
| 10.6 / 11.2 / 11.8 | **进** |
| 12.4 / 13.0 / 13.6 | 被没收 |
| 14.2 / 14.8 / 15.4 | **进** |

即门将实际只覆盖自己身边约 ±0.9 格，**球门两个角是空的**。
把门将换成「每 20 帧按球的位置重新定位」（`dev3/exp_range.js`）后，
在 126 个合法起脚点里，**114 个至少有一个落点能进球**。

> 结论：门将不是瓶颈，**防守球员是否站在球路上**才是瓶颈。

### 2.2 进球高度集中在「禁区角」

用 24 局自测的起脚记录统计（`dev3/goalKicks`，只统计进球前 35 帧内的起脚）：

- 我方进球的起脚位置到球门中心距离：**中位数 8.3 格**；对方 **9.0 格**。
- 大量起脚点落在禁区四个角附近，例如 (5.5, 6)、(5.5, 20)、(38.5, 6)、(38.5, 20) ——
  这些点刚好在禁区外（y<6 或 y>20），却离球门只有 8 格左右。

也就是说：**能站到禁区角、并且球路上没有防守者，就是一个高概率进球。**

### 2.3 本方禁区是对手的禁区 —— 可以在里面无限护球

规则是「任何单位进入**对方**禁区即犯规」。因此：

- 我持球站在**我方**禁区深处时，对手**不能进来抢**（进来就是犯规送任意球）；
- 对手合法能站的最近位置是禁区边线外 0.01 格。

实测 `dev3/exp_park.js`：我方 1:0 领先，持球者站在 (9.0, 13.0)，对手是**真实的搜索型 agent 进程**：

| 人数 | 时长 | 结果 |
| --- | --- | --- |
| 3v3 | 50 秒（1000 帧） | 比分仍 1:0，球仍在我方脚下 (8.38,13)，对手犯规 0 次、射门 0 次 |
| 6v6 | 50 秒（1000 帧） | 同上 |

球贴在我方球员朝向前方 0.62 格处，对手在 x>10 的最近合法点距球 2.13 格，
远大于 0.82 的控球半径。**只要不主动出球，对手拿不到球，比赛时间会一直走完。**

**这个结论有前提，我做了反制实验 `dev3/exp_park2.js`：**
让对手每一帧都无脑冲向球（即**故意跨进我方禁区犯规**）。结果 40 秒里出现 2–3 次犯规后，
球被判到禁区外的任意球点、变成活球，**对手最终拿到了球**（虽然这次脚本对手不会射门，
比分仍是 1:0）。也就是说：

> 护球不是「物理上不可能被抢」，而是「对手必须主动犯规才能破」——
> 每次犯规都会送我们一个任意球、并把犯规者僵直 1 秒，代价很高。
> 真实的自测对手（含冻结的搜索型 agent）都有「不踏入对方禁区」的规避逻辑，
> 40–50 秒里一次都没能把球抢走。但如果 Sol 会刻意用犯规破坏护球，这一招会失效。

### 2.4 先进球 ≈ 赢

对冻结的搜索型对手 24 局（`dev3/f_searchonly.jsonl`）：

| 先破门方 | 胜 | 平 | 负 |
| --- | --- | --- | --- |
| **我方先进球（12 局）** | **12** | 0 | 0 |
| 对方先进球（12 局） | 2 | 5 | 5 |

配合 §2.3 的护球，这个规律被放大了：**一旦领先，我几乎一定赢；一旦落后，我大概率赢不回来。**

## 3. 最终采用的策略

### 3.1 总体结构

每个决策窗口：

1. **启发式基策略**（沿用第 2 轮，含乌龙修复）算出默认的 20 帧计划；
2. **对手建模**：把我自己的启发式基策略套到对手视角上，预测它这一窗口的 20 帧输入
   （双方同时提交，所以对手这一窗口的输入在窗口开始时就是锁定的，不需要猜它怎么应对我）；
3. **候选生成**：基计划 + 8 个射门落点（窗口第 0 帧起脚）+ 最多 5 个「传球/传射组合」；
4. **rollout**：每个候选推进 26 帧（1.3 秒），我方按候选走、对手按第 2 步的预测走；
5. **估值**：`100×(净胜球) + 局面分`，局面分 = 球的位置 + 控球权 + 我方射门余量 − 对方射门余量；
6. 取估值最高的候选。

搜索只在**我方持球**时改变动作；无球时的站位仍由启发式给出。

### 3.2 领先护球（本轮最大的单项改动）

```python
park = PARK and leading and carrier is not None and carrier.x * sg <= 22 * sg
```

即：**比分领先、且持球人在本方半场**时，持球人不再推进/射门，而是带球回到
`(本方门线 + 7.5 格, y=13)`（x≈8.5，禁区内），朝向自家球门，把球护在身后并停住；
其余外场球员在禁区内散开，门将留在门线附近。

- 不领先时不护球（0:0 护球只能换平局，等于输）；
- 持球人在对方半场时不护球（继续进攻更划算，也避免长途回带被断）。

### 3.3 保留的部分

- 乌龙修复（`best_kick_dir` 不再把自家球门当最优解）继续生效；
- 射门判据 `shot_margin` 的「保证型几何」模型不变；
- 门将、防守站位、无球跑位逻辑本轮未改。

## 4. 自测方法与结果

### 4.1 自测空间为什么只有 24 局

`simulation.js` 是**确定性**的：没有随机数，`seed` 只影响两件事——
`teamSizeForSeed(seed)`（1–6 人）和 `kickoffTeam = |seed| % 2`。
所以给定双方程序，全部可能的对局只有 **6 种人数 × 2 种开球方 × 2 个座位 = 24 局**。

我先用 `catalog.js` 的 `teamSizeForSeed` 反查出覆盖全部 12 种 (人数, 开球方) 的种子：

```
16, 9, 8, 49, 24, 75, 40, 17, 48, 1, 2, 25
→ (1人,开球0) (1人,开球1) (2人,0) (2人,1) (3人,0) (3人,1)
  (4人,0) (4人,1) (5人,0) (5人,1) (6人,0) (6人,1)
```

每个种子跑两个座位（交换先后手），共 24 局 = **整个对局空间的完整枚举**。
这一点很重要：**下面的百分比不是抽样估计，而是这批对手下的确定结果**，
换一句话说它没有置信区间，也没有统计意义，只能说「在这 24 种局面下赢了多少」。

### 4.2 对手阵容

对手全部冻结在 `dev3/opps/`（不随我改代码而变化，避免自我对弈污染）：

| 代号 | 说明 |
| --- | --- |
| `botSmart` | 仓库自带的 JS 机器人 |
| `search_def` | 第 2 轮提交版 `agent_core` + 1 窗口双边 rollout 搜索 |
| `search_pres` | 同上，但防守改为压迫 + 双人协防 |
| `search_only` | 第 2 轮 `agent_core` 开启 26 帧 rollout 搜索 |
| `core_def` | 第 2 轮提交版纯启发式（无搜索） |
| `core_pres` | 同上 + 压迫/双人协防 |
| `core_out20` | 同上 + 常驻前锋 |

### 4.3 最终结果（每个对手 24 局）

| 对手 | 胜-负-平 | 胜率 | 进:失 |
| --- | --- | --- | --- |
| botSmart | 17-1-6 | 70.8% | 24:2 |
| search_def | 14-5-5 | 58.3% | 27:16 |
| search_pres | 20-3-1 | 83.3% | 37:12 |
| search_only | 14-5-5 | 58.3% | 34:21 |
| core_def | 18-5-1 | 75.0% | 35:23 |
| core_pres | 14-6-4 | 58.3% | 30:27 |
| core_out20 | 18-5-1 | 75.0% | 31:20 |
| **合计** | **115-30-23** | **68.5%** | **218:121** |

### 4.4 各版本在同一批对手上的对比

| 版本 | 胜-负-平 | 胜率 | 进:失 |
| --- | --- | --- | --- |
| 第 2 轮提交版（工作区里的起点） | 73-75-20 | 43.5% | 233:233 |
| 只加参考搜索（不加护球） | 92-50-26 | 54.8% | 221:190 |
| **最终版（搜索 + 护球）** | **115-30-23** | **68.5%** | **218:121** |

失球从 190 降到 121，是本轮胜率提升的主要来源。

### 4.5 试过但没有采用的改动

我按同样口径逐个测过，下面这些都**更差**，因此没有进最终版本：

| 改动 | 结果 | 判断 |
| --- | --- | --- |
| 常驻前锋 `OUTLET=14/20/26` | 61.8% / 57.6% / 45.8% | 只有配合旧版（无搜索）时有效，有搜索后反而更差 |
| 禁区内人墙 `WALL=2/3` | 62.5% / 45.8% | 抽走逼抢兵力，对手在中场为所欲为 |
| 第二门将 `SWEEP=1` | 63.2% | 只在 `search_only` 上有效，对 `core_pres` 失球从 27 涨到 34 |
| 平局/落后末段加大进攻权重 | 63.9% | 对 `core_def` 从 18-5 掉到 13-9 |
| 加「带球后起脚」候选 | 65.3% | 进球 187→358（翻倍）但胜场不变，说明加的是「赢定了的比赛」的净胜球 |
| 传球优先推进 / 大脚解围 | 37.5% / 37.5% | 明显更差 |
| rollout 视野 26→32 帧 | 37.5% | 更长视野反而不准（对手模型误差被放大） |
| `TRUST` 0.45 / 0.75 | 54.2% / 45.8% | 默认 0.6 最好 |
| 降低射门门槛 `SHOTM<0` | 25–29% | 烂射变多，丢球更多 |
| 估值时把**双方**球员都当作射门阻挡者 | 41.7% | 太保守，不敢起脚 |
| 估值里把阻挡者写反（我方射门只看我方球员） | 50.0% | 说明估值里「谁挡谁的球」很敏感，正确写法值 +8pp |
| 传球搜索允许更长的球（26→34 帧） | 58.3%（34:21 → 35:22） | 胜负完全不变，收益在噪声内 |

### 4.6 顺带修掉的一个真实 bug

调试防守人墙时，我把常量命名为 `WALLR`，**覆盖了从 `pysim` 导入的墙面反弹系数 0.72**
（`ball_fly` 用它算反弹）。结果 agent 内部对球路的预测全错，同一份代码在
`WALL=0` 下都能测出 54.2% vs 58.3% 的差异。改名为 `WALL_R` 后两者一致。
这类「模块级名字撞车」在单文件合并产物里特别隐蔽，记在这里提醒后续。

## 6. 局限与风险（请务必连同结论一起看）

1. **我无法对真正的 Sol 自测。** 规则禁止读取对方代码/工作区，我也没有它的程序。
   上面 68.5% 全部是对**我自己构造的 7 个代理对手**的结果，**不能当成对 Sol 的胜率**。
2. **自测的历史预测力很低，这是第 1、2 轮反复验证过的：**
   - 第 1 轮：自测 93.9% → 正式 0:2 / 1:6；
   - 第 2 轮：对 v1 40:0、对 solid 88.9% → 正式 0:3 / 0:3。
   所以本轮我**不打算**用 68.5% 去推断正式赛结果。它只能证明「相对上一版有大幅改进」。
3. **未达到 90% 目标。** 自测里最强的几个对手（`search_def` / `search_only` / `core_pres`）
   我只有 58.3%。按 §2.4 的规律，胜率上限基本等于「先进球概率」，
   而我对同级别对手的先进球概率只有一半左右。**要上 90%，需要的是把先进球概率翻上去，
   而不是继续优化领先之后的处理。** 这一块本轮没有解决。
4. **样本极小且确定。** 引擎确定性 ⇒ 每个对手只有 24 局、且没有随机性。
   「68.5%」是 168 局里赢 115 局，不是概率估计；换一批对手这个数字会明显变化
   （对不同对手从 58.3% 到 83.3%）。
5. **调参过拟合风险。** 我在这 24 局上试了十几种改动，见 §4.5。
   我尽量只保留「多数对手都变好」的改动（护球、搜索），
   但仍然不能排除对这批代理对手的过拟合。
6. **护球依赖当前规则，而且有反制手段。** 它成立的前提是「进入对方禁区即犯规」且
   「防守方可以在本方禁区」。§2.3 的反制实验显示：**对手只要故意犯规冲进我方禁区，
   就能把球变成禁区外的活球并重新抢到**（代价是送任意球 + 犯规者僵直 1 秒）。
   自测里的对手都不会这么干，但 Sol 会不会，我不知道。
   如果组织方改变禁区规则、或增加「持球超时」判罚，这条策略也会直接失效。
   另外这是规则内的合法打法，但观感上是消极比赛，我在正式赛里只会在领先时使用。
7. **对手模型是启发式的。** 搜索里用「我自己的基策略」预测对手下一窗口的动作。
   如果 Sol 的行为和我差别很大，这个预测会偏，搜索的价值会下降。
   我试过用「追球幽灵」模型（`OPPMODEL=0`）和更长视野，都更差，所以保留了现方案。
8. **金球/终局没有专门优化。** 0:0 进金球时我只是照常进攻，没有针对 20 秒金球设计战术。
