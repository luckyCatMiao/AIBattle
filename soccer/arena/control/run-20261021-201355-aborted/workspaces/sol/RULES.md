# 3V3 足球 · 模型竞技规则

你是独立参赛者，指挥 3 名球员；对手也指挥 3 名。目标是在 120 秒内比对手进更多球。可以自行选择直接思考、自写程序或混合策略。组织者不提供战术或默认控制器，也不会修改你的策略代码。禁止读取或获取对方代码。

## 场地与比赛

- 球场 **44×26 格**，四周有墙；左右各一个 **6 格宽**的球门。球出不了场，只会撞墙反弹。
- 每局 **120 秒**，60 秒时下半场开球；常规时间战平进入 **20 秒金球**，金球进球立即结束，仍平则平局。
- 进球后中圈重新开球，并有 0.6 秒冻结。
- 每轮 2 局，双方交换座位；共 3 轮 6 局。

## 观察

无战争迷雾，双方看到同一块完整球场。每个观察包含：

- `units`：你的 3 名球员（`team/index/x/y/facing/hasBall/kickCd/controlLock/goals/kicks/touches`）；
- `ball`：`x/y/vx/vy/owner/lastTouch/lastTeam`；
- `score`、`half`、`timeLeft`、`golden`、`freeze`、`stats`、`events`；
- `map`：`width/height/tiles/goals/spawns`；
- `rules`：全部物理参数。

## 决策窗口

每 **20 帧（1 秒）** 双方同时提交一次逐帧输入，收齐后统一推进 20 个物理帧。

```json
{"inputs":[[{"dir":"R","aim":0,"kick":false}, … 共 3 个单位 …], … 共 20 帧 …]}
```

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `dir` | `N` / `U` / `D` / `L` / `R` / `UL` / `UR` / `DL` / `DR` | 八方向移动 |
| `aim` | 八方向名，或 0–359 的**角度（度）** | 朝向；0=右，90=下，180=左，270=上。省略或 `N` 时朝向跟随移动 |
| `kick` | `true` / `false` | 沿当前朝向踢球 |

不足 20 帧的尾部由裁判补中立；方向名/字段非法、超过 20 帧整场判技术负。

## 足球物理

- 球员半径 0.34 格，移动速度 3.15 格/秒；球员之间会互相挤开，不能穿墙。
- 球半径 0.22 格；踢出速度约 **14 格/秒**，每物理帧乘 0.97 的摩擦；撞墙反弹 0.72。
- 球员进入球 **0.82 格**内即可控球；控球时球贴在朝向前方 0.62 格。
- 对手比你更近地逼近球（近 0.12 格以上）会抢断；刚被抢断的一方 0.18 秒内不能反抢。
- 踢球冷却 **0.35 秒**；踢出后 **0.3 秒**内不能重新控球。
- 球心越过球门线（x≤1 或 x≥W−1）且在球门高度内即进球；乌龙球记给对方。

## 程序协议

程序持续运行，通过 stdin 每行接收一个 JSON 观察，每次必须向 stdout 输出**一行** JSON 并立即 flush。调试日志只写 stderr。

- 单次响应**硬上限 5 秒**；直接模式单次思考硬上限 180 秒。
- 进程失败、输出格式错误或超时判该场**技术负**。
- 程序只能运行自己提交的文件；禁止读写进程外数据、访问网络、改变规则或私有裁判。
- 准备期间可做离线模拟，但不得更改受保护的资料文件（`RULES.md`、`GAME.md`、`simulation.js`、`catalog.js`、`example.json`）。

提交 `entry.json`：

```json
{"mode":"program","command":["python3","agent.py"]}
```

## 时间与复盘

每轮硬上限以本轮任务说明为准。比赛结束后必须把实际采用的控制策略、自测结果与局限写入简体中文 `review.md`；没有对局前不得编造复盘结果。赛后另写 `postmatch.md`。

单一系列是相关样本，不能据此推断模型的综合能力；同名 `medium` 设置不代表跨厂商的实际推理投入相同。
