# 第 1 轮提交说明与准备期自测

## 状态

已生成 `entry.json`，入口为 `python3 agent.py`。Python 入口使用 `exec` 启动同目录的 `agent.js`，由 Node.js 持续读取 stdin 的 JSON 行，逐行输出并立即写出结果。运行时不写文件、不访问网络。仅使用本方文件以及公开的 `simulation.js`、`catalog.js`，未修改受保护资料。

**本节保留准备期离线测试记录，不是正式比赛复盘。** 准备时 `public_results.json` 为空；现已收到第 1 轮公开战报，正式结果与分析见文末。

## 实际策略

- 将任意座位镜像成向右进攻，人数完全服从当前 `teamSize`，每次输出 20 帧、每帧恰好该人数的合法输入。
- 从观察重建公开模拟状态，对未来 20 帧逐帧计算己方动作，并用同一策略预测对方动作，通过公开物理推进。这样能在一个窗口内安排拿球、转向、踢球和回撤；不假设能收到窗口内的新观察。
- 空闲球预测包含摩擦和边墙反弹，按移动距离与到达时间选择接球点。主要追球队员外，其余队员保持接应、压迫与后方保护位置。
- 多人局让 index 0 优先守门，根据来球轨迹预测拦截纵坐标；本方禁区内近距离来球可上前收球，控球后优先向前解围。单人局不把唯一球员永久留在门前。
- 控球时枚举精确角度，目标覆盖球门内部 y=10.65..15.35。估计球沿途的摩擦、到达时间、敌方可达距离以及近处队友阻挡，选择较安全的射门。
- 没有合适射门时向禁区外推进，必要时走侧翼；受压时评估向前传球或踢向空当。带球朝向尽量背离最近对手，降低球暴露给抢断的风险。
- 禁区避让留出额外安全余量，减少球员分离碰撞把本方推进禁区的风险。实际限制比规则更保守，禁区正面在 x=33 附近停止，侧面也留出约 1 格余量。

## 已实际执行的测试

运行 `node test.js --full`，结果见 `test_results.jsonl`。

- 覆盖 1–6 人，每个人数交换座位。
- 两种自行编写的基线：多人追球压迫，以及守门员配合瞄准远角的进攻。
- 双方均每秒提交一次 20 帧输入；基线也从自己的预测状态生成窗口，没有读取实际未来动作。
- **最终版本：20 胜、4 平、0 负，本方累计 0 次犯规。**
- 每次策略响应最大记录约 **6 毫秒**，远低于 5 秒硬上限。
- 这些基线较简单，24 场也不是独立随机抽样，不能视为正式胜率估计。

早期较窄安全余量版本虽取得 24 胜，但追球压迫测试共出现 4 次本方犯规。最终增加余量后重新跑完整测试，犯规降为零，代价是出现更多平局；提交的是后者。

## 已知局限

1. 对方窗口动作不可见，当前只使用同策略自对弈预测，没有建立多种对手模型或在线动作辨识。
2. 射门安全评估是启发式可达距离估计，不是穷举对手所有拦截动作；传球落点与反弹轨迹也存在近似。
3. 观察不公开部分内部锁定状态，重建时抢断锁和犯规锁只能近似；冻结期由公开字段恢复。
4. 多人局缺少复杂交叉跑位与主动换位，密集防守时容易僵持；保守禁区余量也减少了侧翼进攻空间。
5. 单人局没有独立守门员，需要在前压与保门间取舍，强化压力测试已有失利，不能声称稳胜。
6. 没有根据领先比分专门拖延或落后时增加风险；随机场景测试主要验证协议与计算时间，不等于覆盖所有战术边界。

## 第 1 轮正式比赛复盘（sol）

### 数据来源与口径

本节依据用户提供的两场公开战报，以本方 `sol`、对手 `deepseek-flash` 叙述。未读取逐帧回放，不能还原进球时刻、射门位置或具体失误链。

- 名称虽为「3V3 足球」，实际人数由 `teamSize` 决定：本轮分别为每队 2 人、每队 1 人，不是每队 3 人。
- 公开规则为 20 Hz，因此模拟秒数按 `frames / 20` 换算。战报 `duration` 分别为 2.11、1.59；它们不是场内模拟时长，战报未说明其计时口径，以下仅原样保留，不用来计算比赛节奏。
- `stats`、`saves`、`fouls` 按 `seats` 顺序映射。第二场座位对调，不能沿用第一场的数组下标。
- **射门数据限制：战报仅给出 `kicks`（所有踢球次数，包含可能的传球、解围和射门），没有独立射门数、射正数或射门转化率。** 下文列出踢球数作为相关数据，不能将其直接当作射门数；“进球/踢球”也不是射门转化率。
- `possession` 是模拟器在每帧结束时记录的持球队伍帧数，不包含无人控球及冻结等帧，不能直接解释成完整比赛的传统控球率。

#### r1-g1：低持球、少量机会下的金球险胜

本方在第二座位，以 1:0 获胜。常规时间未分胜负，最终靠金球结束。本方踢球 16 次、对手 17 次，次数接近；本方持球仅 134 帧，明显低于对手的 609 帧。在双方有归属的 743 个持球帧中，本方占约 18.0%，但这不是全场控球率。双方各记 2 次扑救、均无犯规。

这场结果与准备期的防守保护、禁区保守余量及择机向前踢球策略相容：本方没有因犯规或技术错误送出比赛，在低持球条件下仍取得唯一进球。不过，仅凭汇总数据不能证明进球源于某次反击、远角射门或传球配合，也不能把持球少直接归因于某项策略。两次扑救说明本方确有扑救记录，不代表对手恰好只有两次射正。

**需要改进：** 两人局仍应优先检查夺回球权后的接应、出球与第二落点覆盖，避免把金球险胜当成稳定压制。缺少逐帧证据，暂不能认定是守门员站位过深、前场被孤立，还是主动快速出球导致低持球。

#### r1-g2：单人局进攻产出更高，但仍有失球

本方换到第一座位，以 4:1 在常规时间获胜。踢球次数为 17:9，持球帧为 143:57；在双方有归属的 200 个持球帧中，本方占 71.5%。本方在这些汇总指标及比分上均占优，与第一场低持球险胜形成对比。

单人局不把唯一球员永久留在门前，是现有策略的明确设计。本场结果说明该策略至少在这一场能兼顾争球与进攻，但不能据此证明其普遍有效。双方扑救均为 0，而本方失 1 球，说明不能用“没有扑救记录”推断没有威胁或防守完美；没有回放，也不能断言失球是前压过度、丢球后回撤慢或对手直接射门造成的。

**需要改进：** 优先检查单人前压时的失球风险，以及踢球冷却、失去球权后 1 秒动作窗口内的回撤选择。目标是在不牺牲进攻机会的前提下减少暴露空门，而不是凭一次 4:1 就进一步激进前压。
