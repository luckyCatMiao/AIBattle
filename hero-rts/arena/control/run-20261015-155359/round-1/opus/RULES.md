你是独立参赛者，目标是赢得比赛。可以自行选择直接思考、自写程序或混合策略。组织者不提供战术或默认控制器，也不会修改你的策略代码。禁止读取或获取对方代码。双方使用相同游戏规则；本轮任务会说明起点、推理设置及准备预算，挑战赛可能沿用一方的既有策略。

## 游戏与资料

阅读 GAME.md 的玩法和命令、catalog.js 的全部数值、simulation.js 的公开规则，以及 example.json 状态示例。公开 simulation.js 已去掉内置电脑控制器，仅供理解、离线测试，不是对战中的权威引擎。可用 node 执行测试。你的 prepare 环境仅包含自己的 /workspace；真正比赛时 /workspace 只读且无网络，只有 /tmp 可写。

地图 3200×2000；每方 1 名自选首发英雄、5 农民、4 盾卫及初始建筑；650 金250木。10位英雄，每方最多5位不同英雄；16类战斗兵种。英雄技能、走位、经营、建造、科技、野怪和占点都是可用策略。双方获得相同公开全图信息。20分钟内摧毁对方全部大厅获胜，超时按战役积分结算（公式见 simulation.js）。对战不会运行内置 bot。

每场交换东西出生位置，两场之间策略冻结、控制进程重启。地图相同；首发英雄可以由你自由选择，随策略随换边保持不变。所有 ID 必须从当前状态读取，不能硬编码己方编号或出生点。

## 提交 entry.json

自写程序可用 Python 3 或 Node.js 标准库，不允许下载引擎或安装依赖：

```json
{"mode":"program","command":["python3","agent.py"],"hero":"vanguard"}
```

也可提交 `{"mode":"direct","hero":"vanguard"}`，由每个决策窗口重新调用你的模型并读取你写入的 action.json。直接模式允许保留自己的 notes 文件；思考耗时不计入游戏时间。hero 必须是 catalog.js 中的合法英雄 ID。

程序持续运行，通过 stdin 每行接收一个 JSON 对象，每次必须向 stdout 输出**一行** JSON 并立即 flush。调试日志仅写 stderr。状态含 `yourPlayer`、`catalog`、`lastErrors`、`decisionSeconds:0.25`、`maxCommands:20` 及 simulation.snapshot 的全部公开字段。输出格式：

```json
{"commands":[{"type":"train","unit":"worker"}],"note":"可选的简短中文解释"}
```

每0.25模拟秒最多20条指令。双方都看到同一帧，组织者等双方响应后才执行命令并推进5个20Hz物理帧。游戏不奖励模型网络速度。所有阵营共用规则；错误指令不会生效，错误列表在下一观察的 lastErrors 中。重复移动/攻击指令可能打断攻击前摇或施法，请按公开机制判断何时重新下令。空 commands 数组合法，单位持续执行已有命令。

程序单次响应硬上限5秒；直接模型单次思考硬上限180秒。进程失败、输出格式错误或超时判该局技术负，并在结果中单独说明，不冒充游戏战术胜利。程序只能运行自己提交的文件；禁止读写进程外数据、访问网络、改变规则或私有裁判。准备期间可做离线模拟，但不得更改受保护的资料文件。

提交之前实际验证输出格式、命令合法性、资源/人口条件和响应时间。准备预算以本轮任务为准，当前默认上限30分钟，充分自测后可提前提交。沿用的冻结策略不会额外修改。将策略、自测结果与局限写入简体中文 review.md，最后保留 entry.json 与可运行文件。没有对局前不得编造复盘结果。
