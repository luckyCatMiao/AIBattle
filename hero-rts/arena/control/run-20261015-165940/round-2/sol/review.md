# 第2轮复盘与提交

入口为 `entry.json`，运行 `node agent.js`，首发 `druid`（森之先知）。仅使用 Node.js 标准库。持续逐行读取 stdin、逐行输出 JSON，使用 `process.stdout.write` 立即提交响应，无需网络或写文件。单位、建筑、所属玩家及出生方向均从观察识别。上一轮提交原样保存为 `agent-round1.js`。

## 最新公开比赛

本轮先阅读规则、玩法、目录、公开引擎、状态示例及既有复盘，再分析最新的 `public-r1-g1.json.gz` 和 `public-r1-g2.json.gz`。它们是本系列第1轮，不能与内部局号相同的 `public-history-*.json.gz` 混合统计。

最新两局 Sol 换边后均摧毁对方大厅获胜，分别344.95秒、279.50秒；结果记录双方命令错误均为0，均无技术负。公开表现不代表第2轮对手将保持同一策略。

对手已主动争夺外侧圣坛：两局90秒我方都只剩一座圣坛，敌方占三座。第一局240秒我方1481金、206木，第二局240秒2172金、447木，两局此时都只有两门迫击炮。第一局霜语先知245.30秒在地图下缘阵亡。这些是公开记录中的实际问题，不能因最终获胜而忽略。抽帧、采木工人数及英雄阵亡事件保存在 `round2-public-analysis.json`，提取脚本为 `replay-analysis.py`。

## 最终保留的改动

1. 取消追加英雄必须先有三名弓手的门槛，将英雄招募、复活放到经济支出前面；前四位英雄期间为招募预留金币。首个窗口即可排队霜语先知。
2. 两名盾卫继续去南北外点，第三名盾卫负责自家圣坛，占领后归队。英雄与剩余主力无需等待全军先占自家点，可更早清理本方附近野怪，利用多英雄共享经验的规则。
3. 已招募至少四位英雄后，允许更早建铁匠铺、升级城堡时代。进入二级后，工坊和迫击炮生产优先于弓手补充，并为前三门迫击炮保留人口。
4. 160秒后若金币积压，提高木材目标及木工上限；前期仍保留上一版的木材预算，避免过早抽走金矿工人。
5. 牧师和祭司在处理友军控制之后，可主动驱散密集召唤物，按区域内实际可造成的召唤伤害估值，达到300才施放。保持已有的治疗、范围预警避让和普通部队指挥轮转。
6. 点目标技能坐标也夹入合法边界，避免单位被推到边缘时召唤等技能越界。

未保留新撤退向量、主动分散、全面驱散护盾、改招曙光骑士或更换首发法师等实验。最终仍使用森之先知、霜语先知、烬焰法师、星辉祭司、逐风游侠的英雄组合。

## 冻结版本的完整对抗自测

全部使用公开 `simulation.js`，双方同步观察，每次决策后推进5个物理帧，持续至实际胜负。测试对手均为我自己保存或编写的控制器，没有读取真实对手私有文件。以下是本地实验，不是本轮正式成绩，也不能解释成未知对手胜率。

| 自编对手 | 我方西侧 | 我方东侧 |
| --- | --- | --- |
| 上一轮冻结控制器，森之先知首发 | 胜，386.45秒 | 胜，392.35秒 |
| 上一轮控制器，改为烬焰法师首发 | 胜，208.25秒 | 胜，174.20秒 |
| 自己上一轮保存的无主动友军驱散变体，法师首发 | 胜，183.65秒 | 胜，160.80秒 |
| 自编盾卫压力变体，法师首发，追加曙光骑士等英雄 | 胜，438.15秒 | 胜，187.65秒 |
| 上一轮法师控制器，45秒后每秒主动进攻 | 胜，246.90秒 | 胜，180.85秒 |

最后一行压力脚本会避开正在施法、攻击前摇及本窗口刚下达施法的单位，避免进攻指令取消自身新技能。盾卫变体为 `opponent-frontline.js`，是基于自己代码构造的压力对手，并非正式对手的复刻。

上述十场我方和对手命令错误均为0，单次决策最多18条，模块调用最大耗时约6.40毫秒。原始文件为 `r2-final-*.json`。

另用 `integration-battle.js` 真正启动 `entry.json` 指定子进程，对盾卫压力对手完成两场整局：西侧438.15秒、1753次响应、最大18.55毫秒、最多18条命令；东侧187.65秒、751次响应、最大21.74毫秒、最多16条命令。两场均获胜，双方错误均为0。这是同一战术对局的协议重复验证，不另算两场独立战术胜利。真实检查了每行 JSON、连续输入输出、20条上限和5秒截止时间。另将待开始、进行中、结束三个状态连续输入进程，均得到一行合法响应，初始实际命令均可被引擎接受；记录为 `r2-smoke.json`。

## 失败实验与已知弱点

开发期间保留了失败记录。例如单独提早升时代的版本在西侧输给上一轮控制器；新撤退方案在西侧190.70秒输给法师变体；避敌侦察版本在东侧412.05秒输给法师变体。只提前英雄、不改变清野分工时，对盾卫压力对手仍两侧落败。最终方案加入召唤物驱散前，也曾在西侧419.50秒输给上一轮控制器；加入该改动后的重测获胜。这些中间结果没有并入最终十场表格。

最终版并非没有重大损失：西侧盾卫压力局虽胜，仍阵亡83名弓手、20名牧师；西侧对上一轮版本也损失68名弓手。密集范围伤害、复活后重新集结、地图边缘撤退及长期兵力交换仍不理想。早招英雄会推迟经济和普通兵，未穷尽极早突袭、空军、复杂资源枯竭与1200秒积分结算场景。对手第2轮的实际改动未知，正式结果尚未发生。
