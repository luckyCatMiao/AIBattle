# 第 2 轮准备记录与自测复盘

## 数据边界

本文件记录本轮实际提交策略和已运行的离线测试，**不是第 2 轮正式比赛赛后复盘**。目前没有本轮正式对局结果，`public_results.json` 是空数组，不编造正式比分。工作区已有上轮控制器及复盘，分别保留为 `round1_agent.py`、`round1_review.md`；其中历史正式战报描述未在本轮重新核验，不作为本轮测试成绩。

## 实际采用的策略

提交入口为 `entry.json`，持续运行 `python3 agent.py`。每行观察输出一行 JSON 并 flush，购买与比赛阶段分别返回 buys 和严格 20×5 的 inputs。无需网络和运行时文件写入。

- **经济**：手枪局优先购买护甲；其后在预留护甲预算后优先升级步枪、其次 SMG，保留已有更贵武器。护甲低于 60 时补甲，剩余资金允许则防守方购买拆弹器。不购买狙击枪或机枪。
- **导航**：八方向 A*，禁止斜穿墙角；使用圆形半径碰撞检测、路径拉直及每物理帧位置预测。单位间无碰撞、不挡队友子弹，因此保留紧凑集结方案。
- **进攻**：按回合与席位交替选择 A/B；先横向集结，再到选定侧的中央墙下方，再进包点。携包者进入任一包点后立即静止下包。掉包时向炸弹汇合、自动拾取。
- **交战**：保存来自各单位合法视野的最近敌情，估计速度，预测短时间位置，选择可见直线上的近目标预瞄；主要交火距离内停止推进以便协同输出。队友观察仅用于决策和预瞄，不读取隐藏敌人状态。
- **本轮改动一：进攻射击方向记忆**。保留最近 1.1 秒己方公开射击事件的终点，而非原先 0.35 秒，避免在一秒决策间隔之间失去刚刚射击的目标方向。无当前敌情但近期射击时继续守该方向。
- **本轮改动二：包后警戒**。保留紧凑守包位置，但在无敌情及射击记忆时轮流检查上侧、侧面与下侧回防角度；不再只朝下侧固定预瞄。存在敌情时仍优先跟踪敌人。
- **本轮改动三：防守扫描**。保留中路集结及接敌后轮转，空闲时逐帧扫描 D/DL/DR/L/R，单位间错相；敌情或最近射击方向优先于扫描。下包后全员回防，进入炸弹 0.85 格范围内静止拆包。

已检查公开源码：`canFire` 实际只检查枪械射程、墙体和朝向，未调用 8 格视野检查。这与规则文字“只能向自己视野内敌人射击”存在差异。本控制器没有提交射击键或读取超视距敌人，而是依赖官方自动开火；预瞄和扫描可能触发源码允许的长距离自动射击。若正式裁判修正该差异，短时回合与本地成绩不一定复现。

`r2_selftest.js` 每次覆盖 `r2_results.json`，两批最终记录已另存上述文件。最终对抗测试中主控制器单次响应最大实测 **37 ms**，低于 5 秒硬限制；这不是所有环境下的最坏时间保证。

协议和功能检查实际通过：

1. 初始购买护甲且资金合法。
2. 包点内携包者连续 20 帧静止。
3. 拆包范围内连续 20 帧静止。
4. 包后既定位置保持静止。
5. 50 次密集敌情窗口均为合法 20×5 输入，方向名称合法；最大计算耗时约 5.19 ms。
6. 所有开放格均可生成通向 A/B 的路径。此项检查连通性及路径终点，不等于穷尽逐帧导航正确性。
7. 额外启动真实 stdin/stdout 持续进程，依次发送 buy/live/live，全部及时返回正确响应字段，约 20.67/0.88/0.77 ms。

## 被撤回的试验与局限

准备过程中实际尝试了进攻全方向扫描、加速直接进点、侧路前压防守、延迟出门防守、全员同点防守，以及防守延长射击记忆。这些组合在若干双席位测试中出现 0:4、2:4 等退步，已撤回，未混入上表最终版本统计。没有声称所有测试版本都不败。

最终策略仍有明确不足：

- 对上轮控制器四场仅一胜三平；中路型对手两场均平，尚未解决强对手进攻突破问题。
- 对 B 路和部分分点防守的成绩随席位变化，暴露初始站位、路径、朝向及引擎逐单位更新顺序的敏感性。
- 包后仍然紧凑站位，没有验证分散交叉火力优于集结；某些最终比赛的进攻下包仍被拆，不能说包后问题已解决。
- 敌情最多保存九秒、交战瞄准主要用三秒内信息；死亡事件缺少结构化敌人 ID，可能残留旧目标和方向。
- 一秒内无法响应新观察；速度外推短时近似，敌人转弯或离开射线会使瞄准滞后。扫描也会减少某一方向连续覆盖时间。
- 固定 A/B 选择和阶段时间容易被针对，没有完整敌人信念分布、对手学习或长期经济搜索。
- 32 场仅是两个种子组与有限自写对照，部分对照共用主控制器的导航和战斗逻辑，存在相关性；不能据此估算正式胜率。

正式赛后应根据真实公开战报另写 `postmatch.md`，此时尚无结果，未生成虚构赛后报告。
