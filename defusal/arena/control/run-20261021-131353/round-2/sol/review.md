# 第 2 轮提交说明与离线自测

## 提交与状态

- 入口：`entry.json`，执行 `python3 agent.py`。
- Python 标准库实现，逐行接收 JSON，输出一行 JSON 并立即 flush；不访问网络，不依赖比赛期间写文件。
- 本文记录准备阶段的真实离线测试。尚未取得本轮正式比赛结果，不能视为正式比赛复盘；赛后另写 `postmatch.md`。
- `public_results.json` 为空，未据此推断任何对手打法。未读取对手文件，未修改受保护的规则和引擎文件。

## 实际采用的策略

### 购买

优先补护甲（当前护甲低于 65 时），再按剩余资金升级步枪、冲锋枪或微型冲锋枪；防守方有余款购买拆弹器。保留已有较好武器，不重复购买同档枪。首轮通常购买护甲、使用手枪。这个选择不是经过穷举得到的最优解，测试发现它在某些地图会输给先买枪的相似控制器。

### 寻路与逐帧输入

完整静态地图上用八邻接 Dijkstra 距离场，禁止斜穿墙角，缓存目标距离场。执行时预演人物半径 0.3 的逐轴碰撞，生成 20 帧各 5 人的合法输入。导航使用局部前瞻，避免直线撞墙。所有正式控制均只依据己方过滤观察。

### 战斗

保存己方实际观测到的敌人短期位置记忆，引导队友转向和支援；记忆不是敌人实时真值。自动射击由引擎执行。接敌时枚举八方向和静止，预演一秒移动，评分考虑侧移、目标距离、任务进展、掩体、上一窗口移动方向及队友间距。对观测到的敌方子弹，由跨窗口位置差估速；首次出现时尝试从最近已知射手位置估计方向。评分惩罚预测弹道碰撞。没有手动开火或子弹提前量控制。

### 进攻

根据距离场选择较近包点，五人朝同一目标推进，终点略作分散。携带者进入任一合法包点后静止下包。掉包时选路径距离最近的存活单位拾取。安放后在炸弹附近分散防守，优先面对实际发现的敌人。

### 防守

最终采用 A 点 3 人、B 点 2 人开局布阵。发现敌情后向近期接触位置协同转移；炸弹安放后全部回防，进入炸弹约 0.85 格内保持静止拆包。曾测试集中控中路版本，但多地图结果明显更差，已弃用。

## 对抗自测方法

`selftest.js` 调用原始 `simulation.js`，两个持久 Python 子进程仅接收各自的 `sim.view`，所有窗口经 `submitWindow` 校验，并推进完整比赛，包含购买、经济、半场换边、炸弹和胜负判定。

对手均为本人编写的测试控制器，不是正式对手或外部现成引擎：

- `camp`：分散守点，接敌倾向停步射击；进攻仍会寻路、下包、回防。
- `rush`：防守主动压向进攻出生区域，接敌使用简化移动。
- `assault`：采用与主程序相似的侧移战斗控制，但购买优先升级武器，防守采用旧版分散布阵。这是相关性较强的镜像式压力测试。

两种座位均测试，从而覆盖先攻与先守。

## 已知局限

1. 自编对手数量少，且共享寻路和部分战斗代码；54 场不是独立真实对手样本，不能外推正式胜率。
2. `assault` 在额外地图上造成 5 场失利，说明购买优先级、狭窄地形侧移和局部路线仍有明显弱点；没有隐瞒这些失利。
3. 一秒内无法接收新观察，敌人转向、停止或换目标时，整秒固定战斗方向可能失效；不做完整对手搜索。
4. 子弹观察不含速度，首次估计可能出错。躲避模型也未完整模拟子弹碰墙和未来连续射击。
5. 敌人位置记忆可能过时，支援有时会追向旧接触点。敌人消失不能等同于死亡。
6. 进攻集中单点可能受伏击；包点选择不做复杂中途转点；防守协同响应可能暂时放空另一点。
7. 下包及近距离拆包优先静止，可能在火力下阵亡。多人同时拆包没有精细指定携带拆弹器者优先。
8. 寻路是网格距离场加局部碰撞预演，不保证所有随机地图、所有浮点位置都不会短暂卡住。

以上仅是离线准备记录，正式比赛结果待裁判提供。
