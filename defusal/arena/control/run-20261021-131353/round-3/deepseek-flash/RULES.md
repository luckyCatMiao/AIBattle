# 爆破模式 · 模型竞技规则

你是独立参赛者，指挥一支 5 人小队；对手也指挥 5 人。目标是在炸弹模式中赢得比赛。
可以自行选择直接思考、自写程序或混合策略。组织者不提供战术或默认控制器，也不会修改你的策略代码。禁止读取或获取对方代码。

## 游戏与资料

阅读 GAME.md 的玩法与 API、catalog.js 的全部数值、simulation.js 的公开规则（已去掉练习电脑），以及 example.json 的起始观察与示例输入窗口。可用 node 执行测试。准备环境仅包含你自己的 `/workspace`；比赛时 `/workspace` 只读且无网络，只有 `/tmp` 可写。

地图 **56×34**，每场比赛用种子随机生成一张左右镜像的大图；出生点、包点连通性与左右对称由每局开局自检保证。

**每个单位有独立视野**：前方约 100° 视锥、8 格；近身 2 格 360° 感知；墙体遮挡。观察里的 `visibleEnemies` 是每个单位各自看到的内容，不存在全队共享真视。

**所有武器都发射可见的实体子弹**：速度 6.5–13 格/秒，明显慢于即时命中；角色可以侧移/走位躲开。子弹会被墙体挡住；观察里的 `bullets` 包含己方子弹与己方视野内看到的敌方子弹。

## 提交 entry.json

```json
{"mode":"program","command":["python3","agent.py"]}
```

也可提交 `{"mode":"direct"}`，由每个阶段重新调用你的模型并读取你写入的 `/workspace/action.json`。

## 购买阶段

每回合开始 `phase:"buy"`，游戏时间暂停，双方提交购买后回合开始。每个单位有独立金钱。

```json
{"buys":[{"unit":0,"weapon":"rifle","armor":true,"kit":false}, … 最多 5 个单位 …]}
```

- 初始 $800/单位；击杀 +$300；回合胜 +$3250、负 +$1900；下包/拆包 +$300。
- 存活单位保留武器/护甲；阵亡后下一回合回到手枪。
- 第 4 回合半场交换阵营，并重置经济与武器。
- 购买菜单：pdw $700 / smg $1250 / rifle $2700 / shotgun $1000 / sniper $4750 / lmg $4000；
  护甲 $650（吸收 50% 伤害）；防守方拆弹器 $400（拆包 5s → 2.5s）。
- 买不起或非法条目会被忽略；提交空数组表示存钱。

## 比赛阶段

`phase:"live"` 时，每 **20 帧（1 秒）** 双方同时提交一次逐帧输入，收齐后统一推进 20 个物理帧。
你提交 20 帧，每帧 5 个单位：

```json
{"inputs":[[{"dir":"R","aim":"U"}, … 共 5 个单位 …], … 共 20 帧 …]}
```

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `dir` | `N` / `U` / `D` / `L` / `R` / `UL` / `UR` / `DL` / `DR` | 八方向移动 |
| `aim` | 同上（可省略） | 只改变朝向/视野方向；省略或 `N` 时朝向跟随移动 |

- 开火自动：单位会向视野内、朝向内、射程内的最近敌人射击；子弹是实体、飞行需要时间，可能被移动躲开。
- 换弹自动；生命 100，护甲吸收 50% 伤害。
- 下包/拆包自动：进攻方携带者站在包点内不动 3 秒下包；
  防守方站在炸弹 1 格内不动，拆包 5 秒（拆弹器 2.5 秒）。移动会重置进度。
- 炸弹安放后倒计时 40 秒；爆炸进攻方胜，拆除防守方胜。
- 未下包时回合 100 秒；时间到防守方胜。
- 不足 20 帧的尾部由裁判补中立；超过 20 帧、帧形状/方向名不合法，整场判技术负。

## 胜负判定

- 炸弹爆炸 → 进攻方胜；炸弹拆除 → 防守方胜。
- 防守方全灭 → 进攻方胜；进攻方全灭且炸弹未安放 → 防守方胜。
- 炸弹已安放时，即使进攻方全灭，回合继续，防守方仍需拆包。
- 双方全灭：炸弹已安放 → 进攻方胜；未安放 → 防守方胜。
- 时间到且未安放 → 防守方胜。
- 每场 6 回合（3 攻 + 3 守），先赢 4 回合；3:3 平局。

## 程序协议

程序持续运行，通过 stdin 每行接收一个 JSON 观察，每次必须向 stdout 输出**一行** JSON 并立即 flush。调试日志只写 stderr。观察含 `phase`、己方 5 个单位、每个单位的 `visibleEnemies`、地图（完整静态）与炸弹状态（按队伍过滤）。

程序单次响应**硬上限 5 秒**；直接模式单次思考硬上限 180 秒。进程失败、输出格式错误或超时判该场**技术负**。

程序只能运行自己提交的文件；禁止读写进程外数据、访问网络、改变规则或私有裁判。准备期间可做离线模拟，但不得更改受保护的资料文件（`RULES.md`、`GAME.md`、`simulation.js`、`catalog.js`、`example.json`）。

## 时间与复盘

每轮硬上限以本轮任务说明为准。比赛结束后必须把实际采用的控制策略、自测结果与局限写入简体中文 `review.md`；没有对局前不得编造复盘结果。赛后另写 `postmatch.md`。

单一系列是相关样本，不能据此推断模型的综合能力；同名 `medium` 设置不代表跨厂商的实际推理投入相同。
