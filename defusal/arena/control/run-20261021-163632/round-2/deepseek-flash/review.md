## 2. 实际采用的策略

### 2.1 对引擎机制的利用

1. **`canFire` 不要求视野。** 自动开火只检查“武器射程 + 视线 + 朝向落在 ±50° 内”。
   因此单位可以在 8 格视野之外，提前把朝向对准包点、炸弹或已知敌踪；
   敌人一进入视线/射程就会立即开火。这是本 agent 远距离先手的基础。
2. **每单位独立视野。** 100° 视锥、8 格距离、2 格 360° 近身感知，墙体遮挡。
   指挥层只融合“队员真实看到的敌人”，不共享全图真视野；
   因此朝向分配和交叉火力比“全队冲一个方向”更重要。
3. **子弹可见、可躲。** 弹速 6.5~13 格/秒，横向侧移可以显著降低被命中率；
   交火时默认垂直于威胁方向来回侧移，而不是站桩对枪。
4. **经济是滚雪球。** 手枪局 $800 只买护甲（$650，吸收 50% 伤害，等效生命翻倍）；
   赢一回合约 $3400 -> 步枪+护甲（$3350）；
   输一回合约 $2050 -> 冲锋枪+护甲（$1900），不买“裸步枪”；
   防守方在武器+护甲后仍够 $400 时买拆弹器（5s -> 2.5s）。
5. **炸弹规则。** 下包需在包点内静止 3 秒；拆包需在炸弹 1 格内静止 5 秒（有包 2.5 秒），
   移动会重置进度；下包后 40 秒爆炸。下包后的站位必须同时覆盖“拆包者”和“回防来敌”。

### 2.2 进攻

- **3+2 双入口进点**（`AGENT_ATK_SPLIT=1`，默认开启）：
  主队 3 人走最近主入口，副队 2 人走方位差最大的另一入口；
  携带者先在后 7 格等待，护卫进点后再上前下包，避免携带者第一个被集火掉包。
- **选点规则**：上一回合真正赢下才复点，否则换点（`AGENT_ATK_REPEAT_WIN=1`）；
  本局第一个进攻回合用 seed/队伍/回合的弱随机哈希，避免固定先打某点。
- **下包后（`POSTPLANT=close`）**：
  以炸弹为中心、朝“炸弹—来敌参考点”的相反一侧取 2~6.6 格的架点，
  每个点都要求对炸弹有视线；朝向取“炸弹方向”和“来敌方向”的角平分线，
  100° 视锥同时覆盖拆包者和正面来敌；只有 1 人兼看远侧绕后。
  刻意不做 360° 大环形：环形会把 5 个人摊薄，容易被逐个击破（见第 3 节）。
- **手枪局**：全员护甲，不买枪；不采用“放一回合存钱”的 eco，因为本引擎的
  败方奖励固定 $1900，存一回合后仍然要面对已经拿到步枪的对手。

### 2.3 防守

- **5 人重堆一点**（`STACK_N=5`）：首个防守回合先验 A；
  之后按本局此前“我方防守回合”的对手攻点历史做复读/交替预测。
- **重堆点内部**：优先选有掩体、能看主入口/侧翼入口的点位；
  靠近侧翼入口的人负责看背面，其余人看正面。
- **下包后回防**：先集结到炸弹 8.8 格外，再 2 人拆包、其余人外围架枪；
  拆包者只在没有“有视线的威胁”时站定，移动会重置拆包进度，所以不会边打边拆。
- **购买**：防守方在武器+护甲后仍够 $400 时买拆弹器；
  经济劣势时优先冲锋枪+护甲，不买裸步枪。

## 3. 本轮做过的实验（含负结果）

所有实验都在真实 `simulation.js` 上运行，按正式协议每回合购买一次、每 20 帧提交一次。
批量对局全部 `badA = badB = 0`、无超时、无非法窗口。
下表只列“本轮新做或本轮复核”的实验；负结果也保留，避免下一轮重复踩坑。

| 实验 | 方法 | 结果 | 结论 |
|---|---|---|---|
| 按对手“上回合结果”预测攻点 | 新增 `AGENT_DEF_PRED=outcome`：上回合没下包/被拆 -> 换点；下包且攻方赢 -> 复点 | 同一 64 种子集，预测命中率 **40.9% -> 80.4%**（非首个防守回合 **33.2% -> 96.7%**）；但受控对比中第 5+6 回合防守胜率 **24/82 = 29.3%（旧） vs 21/81 = 25.9%（新）**，没有提升 | **不启用**，默认仍用旧规则 |
| 下包后 360° 环形守包 | `AGENT_POSTPLANT=ring`，按角度扇区选点，所有人朝炸弹 | 24 种子非对称自测：我方进攻 **25/72 = 34.7%**，默认 close 为 **41/72 = 56.9%** | **否决**，环形被逐个击破 |
| 弹药节制 | `AGENT_AMMO=1`：手枪/冲锋枪/霰弹枪只对 11 格内目标转向 | 24 种子：我方进攻 **36/72 = 50.0%**（默认 41/72 = 56.9%）；防守 14/54 vs 10/44 | **不启用**，默认关闭 |
| 防守 5-0 / 4-1 / 3-2 | `AGENT_STACK_N=5/4/3` | 首个防守回合防守胜：**12/24（5-0） vs 8/24（4-1） vs 7/24（3-2）** | **保留 5-0**；分兵会让回防集团变薄 |
| 下包后小范围横移+保炸弹视线 | 守包单位 leash 2.0/1.5，横移后检查对炸弹 LOS | 64 种子自测进攻胜率 **60.4%（改动） vs 66.7%（默认）** | **回退**，改为与上一轮版本完全一致 |

### 3.1 为什么“预测对了攻点”却没有提高防守胜率？

这是本轮最值得记录的负结果。按对手换点规律预测后，非首个防守回合的攻点命中率
从 33.2% 提高到 96.7%，但防守胜率没有提高（29.3% -> 25.9%，样本 80 回合左右，
差异在噪声量级）。说明在这套引擎/经济下，防守回合的胜负更多由**进点后的 5v5 对枪、
下包后的回防、以及输掉手枪局后的经济差**决定，而不是“5 个人站对了哪个包点”。
因此本轮没有把“提高预测准确率”当成提高胜率的手段。

### 3.2 实验的方法学局限

模拟器的随机数流在同一场比赛内是连续消费的：前几回合的行为一变，后面回合的
弹道散布随机流也会跟着变。所以小样本 A/B 的“后半场”数字会混入随机流差异，
只能作为方向性证据；上表的 64 种子对比已尽量扩大样本，但仍不应解读为统计显著。

## 5. 局限

1. **没有正式对局。** 本文所有数字都来自本地引擎和冻结机器人；
   没有 sol 的回放、没有本轮正式种子，也没有任何“赛后”结论。
2. **本地对手偏弱且同质。** r1/r2 都是“抱团 + 重堆”的旧机器人，
   95% 左右的进攻胜率不代表对 sol 或其他参赛者的胜率。
3. **自对弈不能直接外推。** 自对弈里双方共享同一套选点/换点策略，
   会出现“后半场进攻方 66.7%”这种结构性偏置；对手换点习惯不同，结论可能反转。
4. **随机流耦合。** 同一场比赛内随机数连续消费，前后回合不是独立样本；
   小样本实验的置信区间比二项分布更宽。
5. **实验开关仍在代码里，但默认全部关闭。** 正式运行不设置环境变量；
   `DEF_PRED` 默认 `legacy`、`POSTPLANT` 默认 `close`、`AGENT_AMMO` 默认 `0`、
   `STACK_N` 默认 `5`，与上一轮验证过的版本一致。
6. **没有读取对方文件、没有修改受保护文件、没有联网。** 本文的所有结论都只基于
   公开规则、公开战报和本地 `simulation.js`。

## 6. 结论与下一轮方向

- 本轮最终**保留上一轮已验证的基线**，没有把“预测更准”但“胜率没提高”的实验带上场。
- 最值得继续投入的方向不是“猜对包点”，而是：
  1. **输掉手枪局后的经济应对**（当前固定买冲锋枪+护甲，是否应该选择性存钱）；
  2. **进点后的 5v5 对枪结构**（谁先手、谁补枪、如何避免被逐个击破）；
  3. **下包后的回防/守包**（当前 close 交叉火力在本地已明显优于环形，但仍可优化掩体与交叉角）。
- 在这些方向拿到稳定的、跨对手可复现的正收益之前，不轻易改动默认策略。
