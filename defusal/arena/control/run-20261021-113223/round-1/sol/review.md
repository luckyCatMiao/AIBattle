# 第 1 轮提交说明与离线自测

## 状态

已生成 `entry.json`，运行命令为 `python3 agent.py`。本文件记录的是准备阶段的真实离线测试，不是正式比赛复盘。`public_results.json` 为空，尚无本轮正式比赛结果，未创建虚构的赛后战报。

## 实际采用的策略

- **持续进程协议**：标准库 Python，逐行读取观察，输出一行 JSON 并立即 flush。购买阶段输出 buys，比赛阶段输出严格的 20×5 输入。比赛时不写工作区、不联网、不依赖临时文件。
- **经济**：初始 $800 优先购买护甲并保留手枪。源码中手枪每 3 帧一发、伤害 24，而 PDW 每 2 帧一发、伤害 18；护甲提供的生存收益值得优先考虑。后续资金充足时购买步枪加护甲；中等资金购买 SMG 加护甲；剩余资金允许时升级 PDW。保留高档武器；护甲低于 75 时考虑补充，防守方余款购买拆弹器。
- **地图移动**：静态八邻接 Dijkstra 距离场，禁止对角穿墙；按公开源码的半径 0.30、每帧速度 0.15、先横后纵碰撞顺序预测 20 帧移动。局部选择更接近目标的路径节点，避免原先出现的原地局部最优。
- **进攻**：五人集中走一侧通道，先沿下方横廊绕开纵向掩体，再通过左/右通道推进。按回合使用 A/B/A 路线。携带者到包点即静止下包；掉包后最近存活单位回收。下包后收拢到炸弹附近，优先保住交叉火力，而非单独追击。
- **防守**：开局两侧各两人、中路一人，面向进攻方向；观测到实际突破后，较远单位支援。炸弹安放后全员回防，到炸弹附近静止拆除，继续独立控制瞄准。
- **交火与情报**：单位看到的敌人用于短期位置记忆及小幅速度外推；队员可以根据队友报告转向，但不会获得规则外真视，实际射击仍完全由裁判的墙体/朝向判定控制。根据源码，自动开火调用的是 `canFire`，并不调用 8 格 `canSee`；因此预瞄可以在长于观察视距的武器射程内触发合法射击。遇到近期目标通常停止移动，瞄准最近可通视目标；换弹且敌人很近时尝试后撤。依据公开死亡事件清理已死亡目标，避免持续瞄准尸体。

## 已知局限

1. 只有一秒一次观察，20 帧内无法响应突然出现的敌人；预测目标死亡或转向会造成瞄准浪费。
2. 进攻路线固定、阵形紧凑，缺乏真正的佯攻与动态换点。强防守对手可能稳定守住进攻回合。
3. 防守轮转是启发式；隐蔽推进、诱导轮转和多线夹击未充分覆盖。
4. 没有执行完整战斗蒙特卡洛搜索，武器选择不含专门狙击枪战术，弹量与换弹管理相对简单。
5. 掉包后只指定最近单位回收，没有危险度路径规划；携带者进入包点会优先静止，可能暴露于交火。
6. 购买逻辑、出生位置和通道站位针对给定地图；虽然寻路读取观察地图，战术没有泛化到其他地图。
7. 正式对手代码及正式战绩不可见，未读取对方文件，也没有把自测结果宣称为正式比赛结果。
