# 前线争夺 / Frontier

一个无需安装依赖的网页即时战略游戏。双击项目根目录 `StartRTS.bat`，或者运行 `npm run rts` 后打开 <http://127.0.0.1:8788/>。五子棋仍在 8787 端口。

## 玩一局

默认你对一名内置电脑，也可在右上角选择 2–8 方混战。点击「开始战役」后时间才会推进。

窗口较小时，点击地图右上角「专注视图」，可以同时查看完整战场、资源和生产面板；「退出专注」返回普通布局。

- 左键点击自己的单位，或拖动框选；Shift 可多选。
- 右键地面：推进并自动攻击沿路敌军；右键敌军：集中攻击。
- 采矿机自动工作，也可以选中它们后右键矿脉，重新分配采集目标。
- 点选指挥部后右键地面，可改变新兵集结点。
- `1` 全选作战部队，`2` 全选采矿机，`A` 后左键指定进攻位置，`S` 驻守。
- `E` 生产采矿机，`Q` 步兵，`W` 坦克，`R` 突击车。
- 单人战役可按空格暂停。多人/API 对战不允许暂停。

从 3 台采矿机、4 名步兵和 260 矿晶起步。指挥部提供 1.5 矿晶/秒的基础收入；采矿机要把矿物运回基地才能结算。矿脉会耗尽。

步兵克制突击车，突击车克制坦克，坦克克制步兵并有小范围溅射伤害。克制伤害为 1.5 倍。武器可升两级，每级增加 20% 伤害。基地自身也会防守，修复一次恢复 400 生命，冷却 30 秒。

作战单位在中继站附近驻留 8 秒即可占领，双方同时在场则争夺暂停；每座中继站产出 3 矿晶/秒。每方最多 40 个单位、6 个排队生产项目。

摧毁其余指挥部获胜。10 分钟仍未结束，则按战役积分结算：造成伤害×0.2 + 击毁数×35 + 采矿量×0.1 + 据点控制秒数×2 + 剩余基地生命×0.1；摧毁基地算 5 次击毁。已淘汰选手不参与限时胜者排名。

## AI / 多人 API

服务端以固定 20 Hz 计算战场，网页和外部选手使用同一套指令。全图信息公开，没有战争迷雾。内置电脑是规则程序，不调用大模型；`api` 席位完全由外部客户端控制。

新建两名外部选手的战役：

```http
POST /api/matches
Content-Type: application/json

{"players":[{"name":"Model A","kind":"api"},{"name":"Model B","kind":"api"}],"seed":1}
```

响应为 `{match, seats:[{player,token}], state}`。`player` 是从 0 开始的编号。支持 2–8 位、任意混合的 `human` / `api` / `bot`；机器人无需凭据。房主即选手 0，准备完成后发送 `start`。至少保留一个非机器人房主席位，便于开始战役。

```http
GET /api/matches/MATCH_ID
Authorization: Bearer YOUR_TOKEN
```

观察包含 `yourPlayer`、时间、基地、单位、矿脉、据点、各方资源、生产队列、兵种参数及结束结果。只读观战可不带凭据；任何公开状态都不包含席位凭据。

```http
POST /api/matches/MATCH_ID/commands
Authorization: Bearer YOUR_TOKEN
Content-Type: application/json

{"type":"train","unit":"rifle"}
```

指令示例：

```json
{"type":"start"}
{"type":"train","unit":"worker"}
{"type":"train","unit":"tank"}
{"type":"train","unit":"raider"}
{"type":"attackMove","units":["u4","u5"],"x":640,"y":420}
{"type":"move","units":["u4"],"x":300,"y":200}
{"type":"attack","units":["u4","u5"],"target":"b1"}
{"type":"gather","units":["u1"],"target":"m0"}
{"type":"stop","units":["u4"]}
{"type":"rally","x":350,"y":400}
{"type":"upgrade"}
{"type":"repair"}
{"type":"pause"}
```

地图大小 1280×840，坐标原点在左上。`move` 不自动追击，`attackMove` 会沿路交战；`stop` 原地防守。采矿机没有武器。每条编队指令至多包含 40 个自有单位，所有单位与坐标在生效前统一校验。持续频率限制为每秒 10 条指令，短时突发最多 15 条；无需每帧发指令，单位会持续执行已有命令。

真人席位可用下面的本地邀请链接打开（不要把对手的 token 交给选手）：

```text
http://127.0.0.1:8788/#match=MATCH_ID&token=HUMAN_SEAT_TOKEN
```

网页将凭据存入当前浏览器的本地存储，并立即清理地址栏的片段。服务只监听本机地址；远程联网大厅不在当前版本中。

当前战役保存在内存中，重启服务会清空。两分钟没有任何观察或指令请求的战役会停止推进，重新连接后继续。最多保留 24 个房间，满额时回收已经结束的房间。AI 对战时建议每 0.5–2 秒读取一次状态，并在 `status === "finished"` 后保存结果。当前接口不提供回放或持久化比赛记录。

## 模型对战与回放

Sol / Luna 回放：<http://127.0.0.1:8789/>。Astra 挑战 Sol：<http://127.0.0.1:8790/>。双击根目录 `WatchRTSBattle.bat` 可恢复最近一次已经完成的系列赛回放，不会重新调用模型，也不会影响 8788 端口的真人战役。

Astra / Sol 的 5 轮续赛：<http://127.0.0.1:8791/>。两方均保留上一系列最终代码，每轮开始前复盘改进，共 10 局。

Opus 5.5 挑战最新版 Sol：<http://127.0.0.1:8792/>。3 轮、6 局，Sol 首轮沿用五轮续赛的最终版本，Opus 从零开始；后两轮共同复盘。Sol 由 Codex CLI 调用，Opus 使用 Claude Code 2.1.296，明确指定 `claude-opus-5-5` 和 `--effort medium`。两个厂商的 medium 不代表相同计算量。Claude Code 使用本机既有代理配置，CLI 返回的模型标识会核对并记录。

Opus 在与其他选手相同的 WSL/bubblewrap 文件系统隔离中准备策略，只有自己的文件及模型配置可见。执行比赛程序时去掉模型凭据和网络，挂载冻结代码为只读。Claude Code 的 Linux 安装方式与调用参数参考 [官方安装文档](https://code.claude.com/docs/en/setup) 和 [CLI 参数](https://code.claude.com/docs/en/cli-reference)。

系列赛使用同一个 `simulation.js` 裁判。两名选手在隔离目录中自行选择策略，均为 medium、每轮准备最多 10 分钟。3 轮，每轮交换东西出生位置打 2 局；轮间获得相同的公开战报后改进。程序每游戏秒得到一次同时刻观察、最多提交 10 条指令；裁判收齐双方指令后推进 20 个物理帧，最高 8 倍速播放。该模式比较策略效果，不把模型网络延迟计入战斗时间。

`rts/arena/control/active-run.json` 指向最近系列赛的归档目录，包含逐秒快照、命令、各轮冻结代码、哈希清单、模型运行日志和赛后报告。观战 HTTP 服务只读，不提供策略文件或修改接口。选手运行环境仅挂载自己的目录；对战程序使用冻结的只读版本，禁用网络。

完整记录可用 `python rts/arena/report.py` 重新审计：从初始状态重放全部命令，核对每个快照、胜者与冻结文件的 SHA-256。比赛控制器 `rts/arena/train.py` 为每个系列建立独立的选手目录，不覆盖历史版本。`--players sol astra --incumbent sol --from-run 历史归档目录 --port 8790` 表示 Sol 沿用该归档第三轮策略、第一轮原样出场，Astra 从零编写；双方获得相同历史公开战报，第二、三轮再共同复盘。这种起点并非同等累计准备预算，报告会明确标注。

`python rts/arena/replay.py --run 历史归档目录 --open` 可以恢复指定系列的只读观战服务。端口从该系列配置读取；已运行时直接打开页面。

继续双方策略可运行 `python rts/arena/train.py --players sol astra --resume-both --from-run 历史归档目录 --rounds 5 --port 8791`。起点取归档配置所指定的最后一轮；双方获得此前各系列的相同公开战报，保留各自私有代码，第一轮起就分别复盘改进。轮数可配置，默认 3 轮；请使用空闲端口。
